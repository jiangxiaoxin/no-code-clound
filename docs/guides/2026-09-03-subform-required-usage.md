# 子表单必填与子字段必填说明

日期：2026-09-03  
范围：调色板 **子表单** `subform` 及其内部子字段的「必填」开关。  
对照设计：`docs/superpowers/specs/2026-08-30-subform-design.md` §6  
对照测试：`docs/testcases/2026-08-30-subform-test-cases.md` §6（V-01～V-07）

本文说明**两层必填分别管什么、空行怎么处理、保存时前后端怎么拦、提示文案长什么样**。不写逐步测试步骤。

---

## 1. 两层必填分别管什么

子表单有两处独立的「必填」，在设计器里分别配置：

| 开关位置 | 字段 JSON | 含义 |
|---|---|---|
| 选中子表单组件 → 属性「必填」 | 子表根上的 `required: true` | **整表**至少要有 **1 行有效数据**（剥空行后不能是 0 行） |
| 选中子表内某一列 → 属性「必填」 | 子字段上的 `required: true` | **每一行**（界面里还存在的行）该列都必须有值 |

二者可以只开一个，也可以都开：

- **只开子表必填**：允许某列全空，但至少要有一行填了任意一列（整行不能全空）。
- **只开子字段必填**：可以 0 行保存（子表不必填时），但只要表格里还有一行，该列不能为空。
- **都开**：至少一行，且每一行的必填列都要有值——等价于「至少一行且每列都填」（见 §6 V-06）。

子表 `subform` 本身**不是**主表那种 `isFillable` 字段：主表必填空时提示 `请填写「标题」`；子表用 **`[子表标题]不能为空`** / **`[子表标题.列标题]不能为空`** 这种方括号路径，前后端一致。

---

## 2. 什么叫「空」

保存、校验、入库前都会先判断单元格和整行是否为空。规则前后端对齐（前端 `subformField.js`，后端 `form-record.coerce.ts` / `form-record.service.ts`）。

### 2.1 单元格为空（`isSubformCellEmpty`）

| 子字段 type | 视为空 |
|---|---|
| 单行/多行文本、单选、下拉单选、日期/时间/日期时间、选择数据 `data` | `undefined`、`null`、`''` |
| 数字 `number` | `null`、`''`（**`0` 不算空**，算有值） |
| 复选框、下拉多选、图片、文件、人员多选、部门多选 | 不是数组，或数组长度为 0 |
| 图片 `image` | 无 URL |
| 文件 `file` | 无 `{ url, name }` 项（仅 URL 字符串会在入库前规范化） |
| 地址 `address` | 无 `ids` 或 `ids` 为空 |
| 人员单选 `member`、部门单选 `dept` | 不是正整数 id |

### 2.2 整行为空（`isSubformRowEmpty`）

一行里**所有**子字段按上表都算空 → 整行视为空行。

### 2.3 空行会不会入库

| 情况 | 行为 |
|---|---|
| 整行空，且**没有**任何子字段开必填 | **丢弃**，不入库 |
| 整行空，但**有**子字段开必填 | **不能保存**，报子字段必填（见 §4） |
| 整行空，子表必填、子字段不必填 | 丢弃后若 0 行 → 报子表必填（见 §3） |
| 行内至少一列有值 | 保留该行；必填列仍空的另报子字段必填 |

点「添加」、默认行数铺出来的行，只要还在表格里，都参与校验；**不会**因为有空行就自动从界面删掉。

## 3. 子表必填（`required` 在子表单根上）

### 3.1 规则

1. 对当前内存里的所有行做 **`stripEmptySubformRows`**（去掉整行空的行）。
2. 若子表 `required: true` 且剩余行数为 **0** → 拦截。

### 3.2 提示文案

```text
[子表标题]不能为空
```

示例：子表标题「订单明细」→ `[订单明细]不能为空`。标题缺省时用「未命名」。

### 3.3 典型场景

| 场景 | 界面状态 | 结果 |
|---|---|---|
| 默认行数 0，从未点「添加」 | `[]` | 拦截，文案如上 |
| 默认行数 2 或点过「添加」，但一行都没填 | 可见空行，剥后 0 行 | 同上（测例 V-02） |
| 子表不必填，全部空行 | 剥后 0 行 | **允许**，库里 `[]` 或不写 key（V-03） |
| 有空行也有实填行 | 空行丢弃，实填行保留 | 只要实填行 ≥ 1 且子字段必填满足，可保存（V-07） |

### 3.4 与「子字段必填」同时存在时的顺序

前端 `subformRowsRequiredError` **先**检查子表必填，**再**逐行检查子字段必填。

因此：子表必填 + 只有空行（哪怕某列也开了必填）→ 先报 **`[子表标题]不能为空`**，不会先报 `[子表标题.列名]不能为空`。  
有实填行但必填列为空时，才报子字段路径（§4）。

## 4. 子字段必填（`required` 在子表列上）

### 4.1 规则

对表格里**每一行**（含空行对象，不先剥掉）检查：凡 `required: true` 的子字段，单元格不能为空。

- 某行只填了别的列、必填列仍空 → 拦截。
- 点「添加」后一行全空，且「名称」列必填 → 拦截（V-05）；空行**不会**被悄悄丢掉。

### 4.2 提示文案

```text
[子表标题.子字段标题]不能为空
```

示例：`[订单明细.物料名称]不能为空`。

### 4.3 典型场景

| 场景 | 结果 |
|---|---|
| 「名称」必填；一行填了数量、没填名称 | 拦截（V-04） |
| 「名称」必填；新增空行保存 | 拦截（V-05） |
| 子表不必填；只有空行但「名称」必填 | 仍拦截子字段必填（子表 0 行允许，但行对象在就要验列） |
| 子表必填 + 每列都必填 | 至少一行且每列有值（V-06） |

## 5. 保存时前后端各做什么

### 5.1 前端（添加数据 / 详情编辑 / 工作台添加）

入口：`firstRequiredError` → 子表走 `subformRowsRequiredError`（`fillValues.js` / `subformField.js`）。

1. 校验失败：`ElMessage.warning(文案)`，并 `revealField` 滚到对应子表；**不发**创建/更新请求。
2. 校验通过：`buildRecordData` → 子表先 **`stripEmptySubformRows`** 再序列化各列；空表提交 `{ 子表key: [] }`（空数组会写入 payload，不是 `undefined`）。

涉及文件：

- `front/src/components/form-workspace/FormRecordManage.vue`（添加）
- `front/src/components/form-workspace/FormRecordDetailDrawer.vue`（编辑）
- `front/src/components/AppWorkspaceMain.vue`（工作台添加）

### 5.2 后端（创建 / 更新记录）

顺序：**`coerceRecordData`** → **`assertSubformConstraints`**。

**coerce 阶段（`coerceSubformValue`）**

- 整行空且没有**看得见的**必填子字段 → 丢弃。
- 整行空但存在看得见的必填子字段 → **`BadRequestException`**，文案 **`[子表.列]不能为空`**（与 §4 一致）。
- 非空行：按子字段类型 coerce；类型不对 → `字段值类型不正确`。
- 子表或子列关掉「是否可见」后，这一项的必填不再拦。

**assert 阶段（`assertSubformConstraints`）**

- 子表 `required` 且 coerce 后 `rows.length === 0` → **400**，文案 **`[子表标题]不能为空`**。关掉「是否可见」的子表跳过。
- 对 coerce 后**每一行**再查必填子字段（非空行里缺必填列）→ **400**，文案 **`[子表标题.列标题]不能为空`**。关掉「是否可见」的子列跳过。

正常走界面时前端已拦截，一般看不到 400；直接调 API 或绕过前端时，后端仍兜底。HTTP 状态码为 **400**（NestJS `BadRequestException`），`message` 即上表文案。

### 5.3 前后端文案差异（仅异常路径）

界面提交前会把空行剥掉再发 API，payload 通常是 `lines: []`。此时后端在 **assert** 阶段报 **`[子表标题]不能为空`**，与前端一致。

若有人直接 POST 带「整行空对象」且存在必填子字段，后端可能在 **coerce** 阶段就报 **`[子表标题.列]不能为空`**。正常产品路径以界面行为为准。

## 6. 与主表必填的对比

| | 主表可填字段 | 子表单 / 子字段 |
|---|---|---|
| 配置 | 字段属性「必填」 | 子表根或子列「必填」 |
| 空值定义 | `isEmptyValue`（各 type） | `isSubformCellEmpty`（§2.1） |
| 提示格式 | `请填写「标题」` | `[路径]不能为空` |
| 多行 | 不适用 | 按行 + 剥空行 |

标签页 `tabs` 内子表规则相同；未打开 pane 里的子表必填、子字段必填**仍然生效**，校验失败应跳到出错 pane（组合用例 T 系列）。

## 7. 设计器与填报界面提示

- 设计器：子表属性、子列属性里各有一个「必填」开关，互不影响。
- 填报：必填子列表头带红色 `*`（`FormSubform.vue`）。
- 子表无子字段时不显示「添加」，提示「请先在表单设计中添加子字段」；此时谈不上必填校验。

**默认行数**：新建时若 `defaultRowCount > 0` 会铺若干空行；用户删光后不会自动补回。编辑已有记录只显示库里的行，不按默认行数补空行。

---

## 8. 不在此规则内的情况

- **Excel 导入**：整列子表仍跳过；导入逻辑对主表必填空数组行会**静默跳过**该行，不走上述子表必填弹窗/400 文案（与界面保存不是同一条路径）。
- **列表单元格内联编辑**：不跑子表整表校验；子表只在添加数据、详情编辑里验。
- **数据联动 / 选择数据填充**：填充后仍受必填约束；空填充不算有值。

## 9. 实现索引（改代码时对照）

| 职责 | 前端 | 后端 |
|---|---|---|
| 单元格是否空 | `isSubformCellEmpty` | `isCoercedEmpty` / `isSubformChildEmpty` |
| 整行是否空 | `isSubformRowEmpty` | `isSubformRowEmpty` |
| 剥空行 | `stripEmptySubformRows` | `coerceSubformValue` 内丢弃 |
| 子表必填文案 | `subformRequiredError` | `assertSubformConstraints` |
| 子字段必填文案 | `subformChildRequiredError` | coerce 空行 + assert 非空行 |
| 提交前总入口 | `subformRowsRequiredError` ← `firstRequiredError` | create/update 内 coerce + assert |

单测：

- `front/src/components/form-fill/subformField.spec.js`
- `front/src/components/form-fill/fillValues.spec.js`（`validateRequired` 子表段）
- `server/src/application/form-record/form-record.coerce.spec.ts`（空行 + 必填子字段）
