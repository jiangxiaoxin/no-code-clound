# 人员单选 / 人员多选使用说明

日期：2026-09-01  
范围：调色板 **人员单选** `member`、**人员多选** `member-multiple`。  
对照设计：`docs/superpowers/specs/2026-08-31-member-select-design.md`  
对照测试：`docs/testcases/2026-08-31-member-select-test-cases.md`

本文说明**怎么配、填报时怎么选、容易搞错的地方**。不写测试步骤。

---

## 1. 这两个控件干什么

从**本系统组织**（管理后台的部门、角色、人员）里选人，表单上显示姓名，库里存用户 id。

| | 人员单选 `member` | 人员多选 `member-multiple` |
|---|---|---|
| 能选几个 | 一人 | 多人（去重，按选中顺序） |
| 入库 | 一个正整数 id | 正整数 id 数组 |
| 列表展示 | 当前显示名 | 多个姓名用顿号 `、` 拼接 |

和下面这些不是一回事：

- **登录人姓名** `currentUser`、**登录人部门** `currentUserDept`：只读当前登录人，不入库，不能当选人用。
- **部门选择** `dept`：选部门，不是选人；控件尚未做完。
- **下拉 / 选择数据**：选的是某张业务表的记录或选项值，不是组织用户。

没有管理后台权限的账号也能打开选人弹框（走 `/api/org/*`，不会走 `/admin/users`）。

---

## 2. 设计器里怎么配

拖到**主表**或**标签页**里。不能拖进**子表单**。

紧挨必填有两项：

### 2.1 可选范围（谁能被手选）

| 选项 | 候选人 |
|---|---|
| **全部** | 所有**启用**用户。没分部门的人只出现在「人员」搜索里，不会出现在某个部门节点下 |
| **自定义** | 见 §3。三个名单都空则运行时没有候选人 |
| **按部门字段** | 以当前表单某个部门选择字段的值为根，该部门及其下级里的启用用户。字段为空或不是合法部门 id 时没有候选人 |

「按部门字段」的下拉只列出本表（含标签页内部）的部门选择字段。部门选择控件未完成时，下拉通常是空的，占位为「请先添加部门选择字段」。选项会显示，但不要指望现在就能「改部门后自动清人」。

### 2.2 取值来源（人选从哪来）

| 选项 | 含义 |
|---|---|
| **自定义** | 填报时手选。没有「设计器里预选默认人」 |
| **数据联动** | 条件变化后从他表写入用户 id。见 §6 |

禁用字段不能打开弹框、不能点清除，但仍可被联动写入。

---

## 3. 自定义范围：三个名单是并集

点「设置可选范围」，弹框标题为 **设置可选范围（选择的合集作为备选）**。顶部按部门、角色、人员展示已勾选项，可点标签删除。下方三个 Tab 分别勾选；人员 Tab 要搜索（失焦或回车才查）并分页，不会一次拉全厂人员。切 Tab 不会丢掉已勾选。

配完后按钮文案变成「已设置可选范围」。右侧清除会二次确认。

候选人 = 启用用户中满足**任一**条的人：

1. 属于勾选的部门（**含这些部门的下级**），或
2. 拥有勾选角色之一，或
3. id 落在指定人员名单里。

只勾上级部门，等于把整棵子树都算进去。停用用户不会进范围。停用的部门、角色不会再往池子里加人。

三个名单都空：打开填报选人框会看到「没有可选择的人员」。

## 4. 新增 / 编辑时怎么选人

点控件**空白**打开弹框（点人名旁的清除不会打开）。标题「选择人员」，可拖拽。

顶部是本次弹框里的已选草稿：有标签可删，无人时显示「未选择人员」。点确定才写回控件；取消不改原来的人选。单选点一行只改草稿、**不关**弹框。

主体三列：

| 左 | 中 | 右 |
|---|---|---|
| 部门 / 角色 / 人员（「按部门字段」时没有角色） | 完整启用部门树 / 完整启用角色列表 / 搜索框 | 当前中间条件查出的人员，每页固定 10 条 |

**中间没有条件时右侧不查人：**

- 部门 Tab 未点节点：提示「请选择部门」
- 角色 Tab 未点角色：提示「请选择角色」
- 人员 Tab 未输入：提示「请输入姓名或用户名搜索」（占位「按姓名 / 用户名搜索」）

自定义范围时，中间仍是**整棵部门树、全部启用角色**，不会只显示你在设计器里勾过的那些。勾选只决定「谁能被选中」，不裁剪浏览树。

右侧实际列出的人 = **当前浏览条件 ∩ 可选范围**：

- 点某个部门：该节点及其下级里的人，并且必须落在 §3 的并集里。
- 点某个角色：有该角色的人，并且必须落在并集里。
- 人员 Tab：姓名或用户名模糊匹配，并且必须落在并集里（满足部门、角色、指定人**之一**即可）。

因此：**点了一个没在配置里勾过的部门或角色，右侧不一定为空。**  
例如只勾了角色「销售」、没勾研发部：点研发部时，研发部里带「销售」角色的人仍会出现。只有「这个节点下的人，部门、角色、指定人三条都对不上」时，才显示「暂无人员」。

控件上每个人名都展开，不省略成「等 N 人」。清除只去掉该人。已选中但后来被移出范围的人，标签仍在、可清除，弹框里不再勾选他们。停用用户不会出现在弹框里。

---

## 5. 保存之后

- 库里只存用户 id，不存姓名。改管理后台显示名后，刷新列表 / 详情即跟进。
- 用户还在库里就显示现名；已经从库里消失才显示「已删除」。不要把「已删除」理解成「id 显示失败」。
- 数据管理列不可单元格内联编辑。导入模版和导入过程都跳过这两列。人员多选不做列表筛选。
- 必填：一个有效 id 都没有则不能提交。

---

## 6. 数据联动

人员字段可以做取值来源=数据联动。联动条件里可以引用本表（含标签页内）的人员字段，按存的 id 比较。下拉「其他表数据」的选字段树里**不会出现**人员字段。

| 当前字段 | 匹配 0 条 | 匹配 1 条 | 匹配多条记录 |
|---|---|---|---|
| 人员单选 | 清空，不提示 | 写入该条里的 user id | **按记录条数**，不是按人数。两条记录即使是同一人，也会清空并提示 `[ 标题 ] 字段联动查询出多条数据` |
| 人员多选 | 清空为没有人选，不提示 | 写入去重后的 id | 最多查 100 条记录，收集 id、去重保序后全部写入；不截人数、不弹多条 |

联动写入**可以**带出当时不在可选范围里的人（和禁用字段仍可被联动写入一致）。**手选**仍然受可选范围限制。

未打开的标签页里，人员必填和联动仍然生效。

---

## 7. 注意事项

1. **并集 ≠ 浏览树被裁剪。** 设计器勾选的是候选人资格；填报左侧仍是完整组织。右侧是「点到的节点 ∩ 并集」。
2. **勾选部门含下级。** 只勾父级，点子部门一般仍能列出人。
3. **人员 Tab 不会默认列出范围内所有人。** 必须先输入关键字再查。
4. **三个名单都空** 和 **范围内确实没人** 文案不同：前者是「没有可选择的人员」（不出现三列浏览），后者是右侧「暂无人员」。
5. **不要和登录人控件混用。** 需要「表单里选一个同事」用人员选择；需要「自动带出当前登录人」用登录人姓名。
6. **不能放进子表单。** 可以放进标签页。
7. **「按部门字段」依赖未完成的部门选择。** 现在不要按「改部门后清人」去验收。
8. **普通账号选人应走 `/api/org/*`。** 若 403，说明请求打到了管理接口，算错误。
9. **联动看记录条数。** 人员单选匹配多条记录会清空；不要用人数去判断。
10. **没有人数上限、没有设计器预置默认人、没有按人员列做复杂筛选。**
