## 修复内容（3 条必须修，`workflow.engine.ts`）

- **必须修 1（撤回竞态）**：重试派发分支改为「先解析审批人、算清待办，再带 `status:'error'` 条件翻转」，翻转影响 0 行（发起人已撤回）直接返回；翻转成功、派完待办后复核一次数据库实际状态，单据已不是「审批中」就把刚派的待办撤回（原因「单据状态已变化，待办自动撤回」）并把 Mongo 对齐到实际状态。对应用例：必须修 1 两条 + 新增【必须修1-补】（翻转成功后撤回才落库，复核兜底）。
- **必须修 2（会签 mongo 重试绕闸门）**：mongo 重试补写成功后，若当前节点是会签且仍有待处理待办，单据回到「审批中」等剩余审批人，不再推进。对应用例：必须修 2 + 新增【必须修2-修复】（回到审批中）与【必须修2-锁定】（都批完才推进，回归锁）。
- **必须修 3（零待办卡死）**：重试前先重解析审批人；解析不到人保持异常并写清新原因；解析到了但这一轮派不出任何待办（已批的人不再派、其余已取消/停用）同样保持异常，提示「这一轮解析出的审批人都已通过……请先恢复被停用成员的账号再点【重试】」；只有确认派得出待办才翻转成「审批中」。对应用例：必须修 3（断言保持异常并带「都已通过」提示）。
- 顺带把 `dispatchApprove` / `dispatchTasks` 增加可选参数（预解析结果、已有待办），让重试路径复用同一次解析与查询，避免竞态窗口里重复解析。
