# 应用配置权与使用范围手工测试用例

日期：2026-09-06  
范围：应用后台【配置权限】【使用范围】【移交所有者】；首页谁能看见应用；只有使用权的人看不到【应用后台】和【表单设计】；所有者停用后，系统管理员在管理后台替他交出去。  
对照设计：`docs/superpowers/specs/2026-09-05-permission-design.md` 第 2 期。

本专项不测按表收权、不测删除人员接口、不测配置者删除应用。

---

## 测试用表结构

应用名：【人事】。所有者先用账号 **A** 建好。

| 表单 | 调色板控件 | 说明 |
|---|---|---|
| 请假单 | 流程表单（建表时选） | 已发布。请假类型用下拉单选框 `select`，选项来自字典「请假类型」（事假 / 病假） |
| 加班单 | 普通表单 | 用来测【转为流程表单】；先不要转 |

组织准备：

| 账号 | 部门 | 角色 | 用途 |
|---|---|---|---|
| A | 不限 | 不限 | 【人事】所有者 |
| B | 不限 | 不限 | 加进配置名单 |
| C、D | 不限 | 不限 | 移交用 |
| H | 研发部（启用） | 不限 | 部门范围普通使用 |
| R | 无部门 | 启用中的角色「人事专员」 | 没部门、靠角色进应用 |
| F | 不限 | 部门经理（审批用） | 首页看不到【人事】，只从【我的待办】批请假 |
| 系统管理员 | 不限 | `system_admin` | 停用所有者后移交 |
| 只有 `admin.access` 的人 | 不限 | 能进管理后台，但不是系统管理员 | 看不到移交 |

研发部下再挂一个子部门也可以，测「不含下级」时用子部门里的人，不要用 H。

---

## 0. 冒烟

| 编号 | 步骤 | 期望 |
|---|---|---|
| S-01 | A 打开【人事】→【应用后台】→【配置权限】 | 第一行是 A，标【所有者】，没有【移除】 |
| S-02 | 点【添加人员】，勾 B（启用），确定 | B 出现在名单里；B 刷新首页能看到【人事】 |
| S-03 | 用 B 打开【人事】 | 能进【表单设计】和【应用后台】【字典管理】；没有【移交所有者】；首页卡片没有【删除应用】 |
| S-04 | A 打开【使用范围】，点【添加部门】选【研发部】（确认说明写不含下级），确定 | 范围表出现研发部 |
| S-05 | 用 H 刷新首页 | 能看到【人事】；进应用能【添加数据】；侧栏没有【应用后台】；表单树没有 ⋯ 菜单，标题旁没有编辑图标 |

---

## 1. 配置权限

| 编号 | 步骤 | 期望 |
|---|---|---|
| P-01 | 名单里再勾一次 A | 提示「已是所有者，无需添加」，名单不出现第二行 A |
| P-02 | 添加一个已停用账号 | 提示不能添加停用账号，名单不变 |
| P-03 | 点 B 的【移除】 | 确认框写：他不能再配置本应用；如果使用范围也没有覆盖他，他同时失去使用权，首页不再出现这个应用 |
| P-04 | 确定移除。此时使用范围没有盖住 B | B 被送回首页；B 再刷新，首页没有【人事】；网址硬进 `/apps/{id}` 提示应用不存在 |
| P-05 | 先把 B 加回名单，再用 B 把自己移除 | B 离开应用后台回到首页（范围盖不住时） |
| P-06 | A 建两个应用【人事】【行政】都当所有者。打开【人事】→【应用后台】→【配置权限】，不离开这一页，直接从左侧切到【行政】的【配置权限】 | 名单换成【行政】自己的人；不会还显示【人事】的名单，也不会把人误加到【人事】上 |

---

## 2. 使用范围

| 编号 | 步骤 | 期望 |
|---|---|---|
| U-01 | 页面顶部有醒目提示 | 写明：按表收权做完之前，开放范围等于把本应用所有表的全部数据开放给范围内的人 |
| U-02 | 「始终可用」里能看到 A（所有者）和名单上的人 | 不能移除；旁边有【所有者】或【配置名单】 |
| U-03 | 对已经在始终可用里的人再【添加人员】 | 提示「已在始终可用中，不必再加」，范围表不出现这一行 |
| U-04 | 把 H 从研发部调到别的部门（或清掉部门），H 刷新首页 | 首页没有【人事】；网址硬进提示应用不存在 |
| U-05 | 用研发部子部门里的人登录 | 首页没有【人事】（不含下级） |
| U-06 | 用没部门的 R，【添加角色】勾「人事专员」 | R 首页能看到【人事】，只能填报，没有【应用后台】 |
| U-07 | 管理后台把研发部停用。A 再打开【使用范围】 | 研发部那一行还在，文案含「已停用，当前不生效」；H 若还在研发部，进不去【人事】 |
| U-08 | 添加停用账号到人员范围 | 提示不能添加停用账号 |
| U-09 | 停在【人事】的【使用范围】页，从左侧直接切到【行政】的【使用范围】 | 范围表换成【行政】的；此时【添加部门】加的部门进的是【行政】，回到【人事】看范围没有多出这个部门 |

---

## 3. 应用内移交

| 编号 | 步骤 | 期望 |
|---|---|---|
| T-01 | A 在应用后台右上或【配置权限】点【移交所有者】，选 C，确定 | A 立刻回到首页；再点【人事】只能当普通人：有【添加数据】【数据管理】，没有【应用后台】 |
| T-02 | 用 C 打开【配置权限】 | 第一行是 C（所有者）；名单里没有 A，也没有 C；【使用范围】出现「人员 = A」 |
| T-03 | 用 B 点【移交所有者】（B 只是配置者） | 看不到按钮；硬调移交接口当作应用不存在 |
| T-04 | C 把 A 加回配置名单，再把所有者交回 A，A 再交给 D | 交完后 A 仍只是普通人（范围再补「人员 = A」），名单里没有 A 也没有 D |

---

## 4. 停用所有者、管理后台移交

| 编号 | 步骤 | 期望 |
|---|---|---|
| M-01 | A 仍是所有者时，管理后台停用 A。用 B（配置者）进【人事】 | B 仍能配、能填，看不到【移交所有者】，删不了应用 |
| M-02 | 系统管理员 → 管理后台 → 人员 → 编辑已停用的 A | 能看到名下【人事】和【移交】 |
| M-03 | 只有 `admin.access`、没有系统管理员角色的人打开同一个编辑框 | 看不到名下应用 / 移交 |
| M-04 | 系统管理员把【人事】交给自己 | 成功；系统管理员现在是所有者，才能打开【人事】。交之前他打不开 |
| M-05 | 另准备一个停用所有者，交给别人（不是自己） | 系统管理员交完后仍然打不开【人事】 |
| M-06 | 编辑一个启用中的所有者 | 不出现名下应用移交区 |

---

## 5. 只有使用权、待办抽屉、失权发起人

| 编号 | 步骤 | 期望 |
|---|---|---|
| F-01 | F 不在配置名单、也不在使用范围。A 提交一张请假单，审批人是 F | F 首页【我的待办】能打开请假抽屉；请假类型显示「事假」这种中文，不是编码 |
| F-02 | F 直接打开 `/apps/{id}` 或调字典接口 | 提示应用不存在；F 不能进【数据管理】翻别人的单 |
| F-03 | 范围内的人提交请假后，B（配置者）看【加班单】树菜单 | 有【转为流程表单】；只有使用权的 H 菜单里没有这一项 |
| F-04 | 把发起人从使用范围拿掉。他打开首页【我发起的】 | 仍能【保存草稿】【再次提交】【撤回】【重试】；不能删草稿；已通过的单只能看 |
| F-05 | 预备：造一张异常请假单（例如部门经理角色下暂时没启用用户），发起人不是 H。H 打开【人事】→【请假单】→【数据管理】→ 点开这条异常单 | 能看详情和进度；底部**没有**【重试】 |
| F-06 | A 或 B 打开【数据管理】里同一条异常单 | 底部有【重试】 |
| F-07 | H 自己提交一张进异常的请假单，再进【数据管理】点开 | 底部有【重试】（他是发起人）。首页【我发起的】里同样有 |

---

## 不要测

- 按表「谁可以看哪些表 / 哪些行」
- 管理后台删除人员
- 配置者删除应用、配置者移交所有者
- 系统管理员没被交给所有权时打开应用看数据
