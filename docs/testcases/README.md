# 手工测试用例说明

日期：2026-08-31  
本目录只放**对照界面执行的测试用例**。功能设计、实施计划仍在 `docs/superpowers/specs/` 与 `docs/superpowers/plans/`。主表数据联动见 `docs/guides/2026-09-04-data-linkage-usage.md`；选择数据格子显示什么见 `docs/guides/2026-09-04-data-select-usage.md`；人员单选 / 人员多选见 `docs/guides/2026-09-01-member-select-usage.md`；子表单必填与子字段必填见 `docs/guides/2026-09-03-subform-required-usage.md`；表单谁能看见、数据看哪些行见 `docs/guides/2026-09-11-form-data-permission-usage.md`。

## 新增组件、或已有组件核心功能变了时怎么维护

实现**新**表单组件，或**已有**组件的核心功能发生改变后，**同一轮**改本目录，不要只更新规格。不是新组件也不能跳过。尤其是容器、联动、选择数据、流水号、成员/部门这类复杂控件。

核心功能包括：查询时机、选项来源、校验、能否进标签页/子表、入库展示、联动、权限等用户对照界面能测到的行为。只改样式、文案措辞、不影响测法的内部重构，不必为了对齐而扩写用例。

1. **专项**：新建或改该能力自己的 `YYYY-MM-DD-<能力>-test-cases.md`（设计、填报、校验、列表、导入等）。写到控件时同时写调色板中文名和 `type`。**文首必须有「测试用表结构」**：表名、字段、类型、配置条件、示例数据。核心行为变了就改旧编号或补新编号，不要留过期期望。
2. **联合**：改 `2026-08-31-complex-form-manual-tests.md`。至少写清和标签页 `tabs`、子表单 `subform`、数据联动 / 选择数据 `data`、流水号 `serialNumber` 叠在一起时怎么表现（能放进 tab / 子表吗、未打开的 pane 还校验吗、联动条件能不能引用、列表会不会多列、删父容器后子内容还在不在）。
3. **本文件**：补目录表、**调色板名称与 type 对照表**、执行顺序、开始前要造的表、破坏性步骤、「不要测」清单。简单字段（单行文本 `input` 等）只需组合冒烟带一条；复杂组件必须有专项 + 联合。

调色板里还是占位、控件没做完的，不要写成可测功能。

## 开始前

1. 登录本系统，打开一个**自己的应用**（不要拿别人正在改的表）。
2. 每张表拖完字段立刻点设计器 **保存**，再去工作台添加数据。未保存的表不会出现在联动「选表」列表里。
3. 流水号若带自动计数，确认 MySQL 已有表 `form_serial_seq`。没有则执行 `server/sql/2026-08-31-form-serial-seq.sql`，否则新增保存会失败。
4. 组合用例建议先造：配件台账（含子表「配件明细」）、采购单（见组合用例「准备」一节）。联动专项会再要员工档案、城市目录、奖金申报；人员专项会再要「人员源 / 人员填报」；关联专项会再要「工厂表 / 人员表」，可以另建，避免和采购单字段搅在一起。
5. 测人员选择前，管理后台至少两名启用用户、一名停用用户。用**没有**用户/部门管理权限的普通账号打开选人弹框，确认走 `/api/org/*` 且不是 403。
6. 测部门负责人前，先执行 `server/sql/2026-09-07-dept-leader.sql`。

## 注意事项

### 操作习惯

- **改条件字段后等约 1 秒**再看联动结果（填报有防抖）。首次进入添加数据会立刻判一次，不必干等。子表 / 主表下拉「其他表数据」也一样：只有选项过滤里引用的字段变了才重查。
- 联动专项**按编号顺序做**，后面的表和数据依赖前面；不要中途改字段标题。
- 设计器画布、数据管理**单元格内联编辑不跑联动**。要验证带出值，进「添加数据」或详情编辑。
- 数据管理**单元格内联编辑**已支持：文本、数字、选项（非联动来源）、日期时间、地址。不能 inline 改：选择数据、关联数据、人员、部门、图片、文件、流水号、子表；选项来源为数据联动的单选/下拉也不能 inline 改。
- 未打开的标签页里，必填和联动仍然生效；校验失败应跳到出错的 pane。
- `flattenFields` 只展开标签页 `tabs`，不展开子表单 `subform` 的列。列表不应出现子表里的「物料名称」当主表列；联动条件里的「当前表单字段」一般是主表（含 tab 内），不是子表列。

### 容易误判

- 流水号新增时只读、显示占位，**保存成功后**接口返回和列表里才有号。
- 没有自动计数段时，流水号**不保证唯一**，撞号不算失败。
- 编辑已有记录再保存，流水号必须不变。
- 子表有必填列时，点「添加」留下的空行不能保存，应拦 `[子表标题.子字段标题]不能为空`。没有必填列的空行保存时仍会丢掉；只剩空行且子表必填，应拦 `[子表标题]不能为空`。
- 数字 `0` 算有值，也参与重复值检测。
- 条件字段还空着时联动按 0 条处理，**不弹**「查询出多条」。
- 子表（或主表）下拉单选框 `select` / 下拉多选框 `select-multiple`（选项来源=其他表数据 `table_data`）：打开添加/编辑时查一次源表 `records/query` 是对的。之后只切换本列已有选项又出现该请求，算失败。选项过滤绑的是主表字段，设计器里选不到子表列。
- 人员单选 `member` 联动看的是**记录条数**，不是人数；两条记录各带同一人仍算多条，应清空并提示。人员多选 `member-multiple` 收集 id，不弹多条。
- 人员列显示姓名；用户已从库里消失才显示「已删除」。改显示名后要刷新列表才跟进。新增抽屉里已选人后再点开选人框，控件上的姓名应保持，不要闪「已删除」。已经选中后又停用的人仍显示现名，打开弹框已选区不应把他们拿掉。
- 选人弹框打开时右侧不会列出全厂人员。没点部门/角色、人员 Tab 没输入关键字，都不该出现 `/api/org/users?page=` 名单请求。右侧每页固定 10 条。再打开时也不该留下上一回的右侧名单。停用用户不能出现在右侧名单里。
- 部门多选勾父级时，父级和下级都会写入，不是只存父级。取值来源「当前用户所在部门」只在值为空时预填登录人第一个部门；用户清掉后同一轮不再自动填回。这和只读的登录人部门 `currentUserDept` 不是同一个控件。
- 子表单 `subform` 列表摘要只拼可填列。选择数据 `data` 的源记录 id **不该**出现在「订单明细」这类摘要里。子列没有「显示在表单中的字段」，详情/填报该格显示「已选择」，不是设备编号、也不是 24 位源 id。看到十六进制 id 算失败。
- 子表某列配了行内联动，或被选择数据填充：画布列头有图标。数据管理新增/编辑抽屉里，该列表头同样有图标，不是只有设计器才显示。
- 数据管理勾选后新增、编辑保存、删除，勾选都会清掉，「编辑」按钮重新变灰。再编辑要重新勾选；不要还用保存前那次勾选里的旧行。
- 设计器画布字段复制、属性面板子字段复制：入口已去掉。选中字段后浮动按钮只有删除；不要找「复制」，也不要测「复制后 key 换新、配置还在」。
- 点调色板往**主表**加字段：有选中的主表字段时插到它下方；点画布空白取消选中后才到主表最底部。选中子列仍进该子表，并插到该列后面，不是所有列最右侧。选中标签页或 pane 内字段仍进当前 pane。拖到空白画布仍以落点为准，追加到根列表末尾。属性里「添加子字段」仍追加到子表末列。
- 选择数据 `data` 弹框里，源表图片上传 `image` 列应出缩略图，不是「n 张图片」。点图预览不应勾选或取消该行。
- 选择数据 `data` 弹框里，源表人员单选 `member` / 部门选择 `dept` 列应显示姓名、部门名。人还在、部门还在组织树里时，**不要**显示「已删除」。没填的行这两列为空。
- 选择数据 `data` 选中后：主表若配了「显示在表单中的字段」，格子显示勾选顺序里**第一条有值**的列（例如先勾工厂编码就会看到 `F002`，不是工厂名称）；没配才显示「已选择」。子表选择数据没有该项，格子固定「已选择」。右侧有圆形清除图标（和输入框清空一样）。点它只清本列，**不会**清掉已填充到其他字段/子表列的内容。画布预览和只读详情没有这个图标。说明见 `docs/guides/2026-09-04-data-select-usage.md`。
- **普通表单**：【表单设计】字段属性里有**是否可见**、**是否可修改**，默认都开；关掉可见后填报不显示、列表不出列、必填跳过。子表单 `subform` 整表或某一列关掉可见时，这一项就算勾了必填也不拦提交。
- **流程表单**：【表单设计】**没有**是否可见 / 是否可修改；到【流程设计】点开始节点或审批节点，在右侧「字段权限」里配可编辑 / 只读 / 不可见（抄送节点还有简报）。填报与待办按当前节点权限生效，不看 schema 上的 visible / editable。节点把某字段（含必填子表单 `subform`）设成只读或不可见后，就算表单设计勾了必填，当前这一步也不要因为这项空着拦住提交；只拦当前能改的必填项。
- 关联数据列表列显示的是源表「显示字段」的当前文字，不是 id。源表改名后刷新才跟进。关联子表单不出现在数据管理列表里。设计器画布上，关联子表单应是和子表单类似的表格：表头是「显示的列」的字段标题，不是 UUID 那种字段 key。人员表删掉某列后，工厂表画布/详情里那一列应直接消失，不要用字段 key 顶替表头；控制台会打 `[人员表的<field key>字段无法匹配列名，因此被隐藏]`。关联子表单「显示的列」末尾可选创建人、创建时间、更新人、更新时间；勾上后详情里显示姓名和日期时间。关联子表单**没有字段宽度**，画布和填报/详情都固定占整行，不要在属性里找宽度。**添加数据 / 新增抽屉里不出现关联子表单**（无标题、无占位）；只有详情和编辑（已有这条数据 id）才显示反向表格。画布和详情里关联子表单标题左侧应有链式图标（与数据联动同类样式，悬停说明只读反向列表）。**「是否可查看详情」默认关闭**；没开时点表格行不会弹子表详情；开了才会打开只读抽屉。
- 只有使用权的人进【数据管理】打开**别人**的异常请假单，底部**没有**【重试】。发起人自己在【我发起的】或【数据管理】打开自己的异常单才有。【重试】不要当成「能进数据管理就能点」。
- 【重试】是**把卡住的那个节点重新派一遍**，不是往下走一步。补上审批人后重试，单据仍停在原来那个审批节点（例如还是「部门审批」），小图高亮的也还是它。看到它跳过这个节点直接进下一个，算失败。见流程专项 E-06～E-08。
- 审批人派出去之后才被停用：**打开单据才会发现**（【我发起的】卡片或【数据管理】详情）。打开后状态自己从「审批中」变成「异常」并出现【重试】，这是对的，不是被谁改过。停用审批人仍靠打开时检查。流程超时另有每分钟定时扫库，到期会自动驳回，见流程超时专项。
- 分支连线的过滤条件要**保存后刷新再点回这条线**验证，别只看点完当场还在。条件里选用了数据字典的字段时，值那一栏应能拉出字典选项。日期选择 `date` / 时间选择 `time` / 日期时间 `datetime` 默认操作是「选择范围」：范围内的单必须走这条条件线，范围外才走「其他情况」。两张都落到其他情况算失败，见流程专项 D-02e、组合 C-21d。
- 应用后台【配置权限】【使用范围】停在页面上直接从左侧换一个应用：名单和范围表要跟着换成新应用的。还显示上一个应用的内容，或把人加错到上一个应用，算失败。见权限专项 P-06、U-09。

### 不要测（调色板有、控件未完成）

关联数据 `relate`、关联子表单 `relate-subform` **要测**（专项 `2026-09-04-relate-test-cases.md`）。拖进子表单 `subform` 应被拒绝。关联子表单详情里**不要**测新增 / 编辑 / 删除子表数据（本期没有这些按钮）。

设计器字段复制（画布浮动按钮、属性面板子字段列表）：入口已去掉，见到「复制」按钮算失败。子表填报行操作也只有添加/删除，没有插入/复制。

人员单选 `member` / 人员多选 `member-multiple`、部门单选 `dept` / 部门多选 `dept-multiple`**要测**（各自专项 + 组合 §6）。人员「按部门字段」只认部门单选 `dept`，可配主表或同一子表行里的部门列。

明确不做、见到就算失败的现象见各用例文末「X-」表（移动端子表、子表 Excel、两个标签页、两个流水号等）。

流程表单**不要测**：减签、退回任意指定节点、批量转交、流程转回普通、首页【我发起的】删除、流程表导入 Excel、审批里改子表行、把抄送放进【我的待办】或【我处理的】、抄送人改表单或填意见、从结束连出抄送、抄送未读点、站外通知、流程设计画布的复制粘贴（Ctrl+C / Ctrl+V 已不支持，见流程补充 B-27）、分支条件里日期/时间的「动态筛选」（当前月、过去 N 天——引擎本期不算，会落到其他情况）。失权发起人改测权限专项 F-04。数据管理里谁能点【重试】改测权限专项 F-05～F-07。

权限第 2 期**不要测**：管理后台删除人员、配置者删除应用。按表收权改测 `2026-09-11-form-data-permission-test-cases.md`。

权限第 3 期**不要测**：自定义行条件、字段级对某些人隐藏、子表权限组、所有者和配置名单也受行范围限制。

部门负责人**不要测**：正副职、按上级逐级上报。
