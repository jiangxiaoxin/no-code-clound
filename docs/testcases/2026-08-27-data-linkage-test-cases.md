# 数据联动手工测试用例

建议先读本目录 [README.md](./README.md)，做完组合冒烟再跑本专项。按编号顺序做。前面的表和数据会被后面的用例复用，不要中途改字段标题。

对应实现：`optionSource: 'linkage'` + `linkage`，设计弹框 `DataLinkageDialog.vue`，填报 `FormFillGrid.vue`。

## 和界面有关的实现细节

- 字段属性里，文本 / 数字 / 日期 / 时间 / 图片 / 文件 / 地址是「取值来源」，下拉单选 / 下拉多选是「选项来源」，都是 **下拉框**，不是单选。选择数据仍是「数据源」。
- 单行 / 多行 / 数字 / 日期 / 时间 / 日期时间：「取值来源」选项为 **自定义**、**数据联动**。
- 下拉单选 / 下拉多选：「选项来源」选项为 **系统字典表**、**其他表数据**、**数据联动**。
- 单选框、复选框没有取值/选项来源这一项，仍是「选项字典」。
- 选「数据联动」后，下方表单项标题是「数据联动」。未配完显示 **设置数据联动**（无清除图标）；配完显示 **已设置数据联动**，右侧有关闭圆圈图标。
- 弹框标题 **数据联动设置**，可拖拽。联动表单是可搜索的 `el-select`（占位「请选择表单」），列表为本应用已保存表单，**含当前表**。未选表单时，条件和「触发以下联动」整块不出现。
- 条件嵌在弹框里，不再另开过滤弹框。文案：**联动表单字段满足以下** 〔所有 / 任一〕 **条件时**。添加按钮文案是 **添加过滤条件**。左侧占位「联动表字段」，右侧默认「当前表单字段」（图标悬停可切到自定义值）。条件左侧也会列出系统字段（创建人、更新人、创建时间、更新时间），本轮不要选它们。
- 「触发以下联动」：左侧「当前表单」只读框（带组件图标和当前字段标题）；中间 **联动显示**；右侧「联动表单」下拉（占位「请选择联动表字段」）；后面还有 **的值**。右侧选项是**联动表里类型兼容的字段**（单行文本 / 下拉单选都可对应单行、多行、单选、下拉；数字只能对应数字），不是当前表字段列表。
- 条件引用的当前字段为空时 **不发查询**，按 0 条处理，不弹多条提示。文本 / 数字 / 日期查询 `pageSize: 2`，用 `total` 判断是否多于 1 条；下拉仍 `pageSize: 100`。
- 首次进入填报表会立刻跑联动；之后改条件字段大约 **1 秒** 才再查（防抖）。编号填完后稍等再看姓名。
- 设计画布和数据管理单元格内联编辑 **不跑联动**。
- 新建表单成功后会自动进入该表单设计页，测完保存即可。

## 1. 设计器：取值来源 / 选项来源与弹框

### T1 单行文本出现「自定义 / 数据联动」

1. 打开「奖金申报」表单设计，选中 **姓名**。
2. 字段属性应有「取值来源」下拉，选项为 **自定义**、**数据联动**。
3. 选 **数据联动**，下方出现「数据联动」设置行，按钮文案 **设置数据联动**（还没有清除图标）。
4. 选中数字、日期字段，取值来源同样是 **自定义 / 数据联动**。
5. 选中下拉「城市」，应有「选项来源」，选项为 **系统字典表 / 其他表数据 / 数据联动**。
6. 单选框、复选框字段上 **没有**「数据联动」取值/选项来源，仍是「选项字典」。

**期望：** 通过。

### T2 缺项不能保存

1. 点「设置数据联动」，弹出 **数据联动设置**。此时只有「联动表单」下拉，没有条件行和触发联动。
2. 直接点确定 → 提示 **请选择联动表单**，弹框不关。
3. 联动表单选「员工档案」（可搜索表名）。条件和「触发以下联动」出现。条件行保持空白（会有一行空条件），点确定 → 提示 **请至少添加一条联动条件**。
4. 配条件：左侧选联动表「员工编号」，中间「等于」，右侧默认就是当前表单字段，直接选本表「员工编号」。不必再点图标切换，也不必再开一层过滤弹框。
5. 不选联动表字段（触发以下联动右侧下拉），点确定 → 提示 **请选择触发联动字段**。
6. 右侧下拉选「姓名」，点确定。

**期望：** 按钮变为 **已设置数据联动**，右侧有清除图标。触发行：左侧只读显示当前字段「姓名」（带单行文本图标），中间文案为「联动显示」，右侧为联动表字段，再后面是「的值」。

### T3 触发字段类型过滤

1. 再打开姓名的数据联动。
2. 触发联动下拉（联动表字段）应有：姓名、手机、部门、员工编号（都是单行文本）；**不应有** 奖金基数（数字）、入职日期（日期）。
3. 取消关闭。选中本表 **奖金基数**，取值来源选数据联动，联动表员工档案。
4. 触发联动下拉里应只有 **奖金基数**，没有姓名。

**期望：** 通过。奖金基数这步配完可用于 T6，条件同样是「员工编号 等于 当前表.员工编号」，触发字段「奖金基数」。

### T4 取消不保存、清除要确认

1. 选中 **手机**，取值来源选数据联动，点设置，选员工档案并配好条件，触发选「手机」，点 **取消**。
2. 按钮仍是 **设置数据联动**（未保存）。
3. 再配一次并确定，变为已设置。
4. 点清除图标 → 弹出标题 **删除**、文案 **确定删除数据联动？** → 取消，配置还在。
5. 再点清除 → 确定。按钮回到 **设置数据联动**，取值来源仍是 **数据联动**。
6. 把取值来源改回 **自定义**，联动设置行消失。

**期望：** 通过。T4 结束后把手机重新配成已设置（同 T2，触发字段选「手机」），后面填报要用。

### T5 把其余字段配齐并保存表单

按同一套条件配完（都先保存「奖金申报」字段设计）：

| 本表字段 | 取值来源 | 联动表 | 条件 | 触发联动 |
|---|---|---|---|---|
| 姓名 | 数据联动 | 员工档案 | 员工编号 等于 当前表.员工编号 | 姓名 |
| 手机 | 数据联动 | 员工档案 | 同上 | 手机 |
| 部门 | 数据联动 | 员工档案 | 同上 | 部门 |
| 奖金基数 | 数据联动 | 员工档案 | 同上 | 奖金基数 |
| 入职日期 | 数据联动 | 员工档案 | 同上 | 入职日期 |

**备注** 保持自定义，用来对照「不会被联动改掉」。

设计器画布上，配了联动的输入框只显示占位符，**不会**查出张三。未配完的下拉会显示「请配置选项来源」；配完后画布下拉选项仍为空（画布不查）。

点设计器 **保存**。

## 2. 填报：0 条 / 1 条 / 多条

### T6 编号未填：联动字段保持空

1. 工作台打开「奖金申报」→ **添加数据**。
2. 不填员工编号。首次进入会立刻判断一次（不必等 1 秒）。

**期望：** 姓名、手机、部门、奖金基数、入职日期都是空；没有「查询出多条」提示。备注可手填，不受影响。

### T7 唯一编号自动带出

1. 员工编号输入 `E001`，等 1 秒。

**期望：**

- 姓名 = 张三
- 手机 = 13800000001
- 部门 = 研发
- 奖金基数 = 8000
- 入职日期 = 2024-01-01
- 无报错提示

2. 改成 `E002`，等 1 秒。

**期望：** 变成李四及其手机、市场、9000、2024-03-15。

3. 点保存。到 **数据管理** 看这一行，各列是李四的值（存的是字段值，不是员工档案记录 id）。

### T8 匹配多条：不填并提示

1. 打开「员工档案」，临时关掉「员工编号」的不允许重复值（若之前开了），**保存表单**。再添加一条：员工编号 `E001`，姓名 `张三-重复`，手机 `13900000000`，部门 `总经办`，奖金基数 `1`，入职日期任意。
2. 回到「奖金申报」添加数据，员工编号输入 `E001`，等 1 秒。

**期望：**

- 姓名、手机、部门、奖金基数、入职日期被清空
- 每个被联动的字段各提示一次，格式为 `[ 字段标题 ] 字段联动查询出多条数据`；若标题旁有说明，则把说明接在标题后面，例如 `[ 奖金基数，数字越大给的越多 ] 字段联动查询出多条数据`（下拉联动字段不弹这条）
- 没有自动填成张三或张三-重复

3. 测完后，把员工档案里那条「张三-重复」删掉，避免影响后面用例。

### T9 查不到：清空、不提示

1. 添加数据，先填 `E001` 带出张三。
2. 把员工编号改成 `E999`（档案里没有），等 1 秒。

**期望：** 联动字段清空；**没有**多条提示。

## 3. 下拉联动

### T10 配置城市下拉

1. 设计「奖金申报」，再加一个单行文本 **省份**（自定义）。
2. 选中 **城市**（下拉单选）：
   - 选项来源改成 **数据联动**（不要用「其他表数据」）
   - 联动表：**城市目录**
   - 条件：省份 等于 当前表.省份
   - 触发联动：城市
3. 保存表单。配完后画布上城市不应再显示「请配置选项来源」。

### T11 下拉 0 / 1 / 多条

1. 添加数据。省份不填：城市下拉应为 **空选项**，值为空；不弹多条提示。
2. 省份填 `江苏`，等 1 秒：城市应 **自动选中** `南京`（去重后只有 1 个选项）。
3. 省份改成 `浙江`，等 1 秒：城市选项为 杭州、宁波，**不自动选**、**不弹多条提示**；原先南京应被清掉（不在结果里）。
4. 手动选杭州，保存。数据管理里城市显示杭州。
5. （实现对照）把省份清空：城市 **选项变空**，但已选的杭州 **可能仍留在值上**（条件未就绪时下拉只清空选项、不写回空值）。不要把这一步当成失败。再填 `江苏` 会重新按 1 条规则写成南京。

## 4. 禁用、不可修改、详情、单元格

### T12 禁用仍可被写入

1. 设计器：姓名打开 **是否禁用**。保存。
2. 添加数据，填 `E001`。

**期望：** 姓名灰不可点，但仍显示张三。保存后数据管理里姓名是张三。

3. 测完把禁用关掉，保存。

### T13 不可修改：新增能写，编辑不改

1. 设计器：姓名 **是否可修改** 关掉。保存。
2. 添加数据，填 `E002`，姓名应为李四。保存。
3. 数据管理点开这条 **详情**（先不要点编辑）。

**期望：** 姓名仍是李四。此时即使员工档案里把李四改成别的名字，这里也不变（只读详情 `disabled`，不发联动查询、不写值）。

4. 点 **编辑**，不要改员工编号，等几秒。

**期望：** 姓名仍是李四（首次进入编辑且条件没变，只刷新下拉选项，不覆盖文本值）。

5. 把员工编号改成 `E001`，等 1 秒。

**期望：** 姓名 **仍是李四**（不可修改 + 正在编辑已有记录，联动不能改姓名）。手机、部门等可修改字段应变成张三的。

6. 取消编辑。把姓名的「是否可修改」重新打开并保存，方便后面测覆盖逻辑。

### T14 编辑时改编号才重算

1. 用 T7 保存过的李四那条（或再新建一条 E002 并保存）。
2. 先在员工档案把李四的手机改成 `13700000000` 并保存记录。
3. 打开奖金申报这条详情 → 编辑，不改编号。

**期望：** 手机仍是原来带出的 `13800000002`，不会变成 137。

4. 把员工编号改成 E001 再改回 E002，等两次查询。

**期望：** 此时会按档案现况重查，手机变成 `13700000000`。

### T15 数据管理table，单元格不能内联改联动字段

1. 打开奖金申报数据管理表格。
2. 姓名、手机、部门、奖金基数、入职日期、城市这些配了数据联动的列（`optionSource === 'linkage'`），行内 **不应出现编辑按钮**。
3. 员工编号、备注、省份仍可单元格编辑。
4. 单元格里改员 工编号为 E001。

**期望：** 同一行姓名 **不会** 自动变张三。要改姓名只能进详情编辑（且姓名未锁「不可修改」时才会随编号变）。

## 5. 对照与收尾

### T16 不要和「选择数据 / 其他表数据」搞混

本轮 **不必** 再配这两种。只需确认：

- 奖金申报的姓名走的是取值来源「数据联动」，不是选择数据组件，标题前也没有「受选择数据填充」的连接图标。
- 城市走的是数据联动，不是「其他表数据」。
- 「其他表数据」下拉只改本列选中值时不应再打源表 `records/query`（主表见子表专项 G-07，子表见 F-33；组合用例 C-14）。

### T17 复制字段带上联动配置

1. 设计器选中姓名，点复制。
2. 副本取值来源应为数据联动，按钮为已设置数据联动。
3. 打开设置，联动表、条件、触发字段与原字段一致。
4. 测完删掉副本，保存。
