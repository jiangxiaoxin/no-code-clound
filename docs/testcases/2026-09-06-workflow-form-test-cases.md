# 流程表单手工测试用例

日期：2026-09-06  
范围：建表时选【流程表单】、【流程设计】画布、【添加数据】提交、首页和应用内【我的待办】/【我发起的】/【我处理的】、【数据管理】里的流程状态。  
对照设计：`docs/superpowers/specs/2026-09-05-workflow-form-design.md`  
对照使用说明：`docs/guides/2026-09-06-workflow-form-usage.md`

流程不是调色板控件。用例里的字段仍写调色板中文名和 `type`。

---

## 测试用表结构

应用名：【人事】。再准备一张普通表【加班单】（后面转流程用），一张普通表【考勤台账】（用来挑请假记录）。

### 请假单（流程表单）

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 请假人 | 人员单选 `member` | 可选范围不限 |
| 请假类型 | 下拉单选框 `select` | 选项：事假 / 病假（字典即可） |
| 开始日期 | 日期选择 `date` | |
| 结束日期 | 日期选择 `date` | |
| 事由 | 多行文本 `textarea` | 必填 |
| 附件 | 文件上传 `file` | 选填 |
| 明细 | 子表单 `subform` | 子列：说明（单行文本 `input`） |
| 更多 | 标签页 `tabs` | pane「补充」里放事由以外的一个单行文本 `input`「备注」 |

组织准备：

- 员工 A：发起人，挂部门「研发」
- 经理甲、经理乙：角色「部门经理」，同属「研发」
- 经理丙：角色「部门经理」，属「销售」（不同部门）
- 张三、李四：指定人员，不要求能进【人事】
- 另备一名账号停用的用户，测「审批人已停用」

流程画布（启用前画好）：

```text
开始 → 分支「请假类型」
  事假 → 部门审批（角色：部门经理，勾选「限定与发起人同部门」，或签）
  其他情况 → 人事备案（指定人员：张三、李四，会签）
部门审批 → 人事备案 → 结束
```

【考勤台账】放一个关联数据 `relate` 或选择数据 `data`，数据源选【请假单】。

## 0. 冒烟

| 编号 | 步骤 | 期望 |
|---|---|---|
| S-01 | 【人事】→ 新建表单，名称「请假单」，表单类型选【流程表单】→ 确定 | 树里出现【请假单】；打开设计顶栏有【表单设计】【流程设计】【表单发布】【数据管理】 |
| S-02 | 先不进【流程设计】，工作台打开【请假单】→【添加数据】 | 顶部写「这张表单还没有配置流程，暂时不能填报」 |
| S-03 | 填一事由，点【保存草稿】，再点【提交】 | 两次都提示还没配置流程；【数据管理】没有新行 |
| S-04 | 【数据管理】点【新增】 | 提示「这张表单还没有配置流程，暂时不能填报」，不出现可保存的新数据 |
| S-05 | 切到【流程设计】，按上面的图画完，点【保存并启用】，确认框点确定 | 成功；下拉里该行绿色「启用中」；顶栏有【保存】【保存并启用】，没有【发布】按钮，也没有「启用流程」开关 |
| S-06 | 回【添加数据】，请假类型选事假，填必填，点【提交】 | 提示「已提交，等待「部门审批」」；【数据管理】该行流程状态是「审批中」 |

## 1. 建表、页签、转换

## 2. 画布与启用

| 编号 | 步骤 | 期望 |
|---|---|---|
| D-01 | 【流程设计】左侧只有审批、分支、结束；画布上已有开始 | 开始不能从左侧再拖；删开始会立刻回来并提示不能删 |
| D-01b | 点开始、点结束，右侧改节点名称，点【保存】后刷新再点 | 右侧有「节点名称」输入框；画布上的字跟着改；刷新后名称还在 |
| D-02 | 分支线配「请假类型 = 事假」，另一条勾「其他情况」，可上移下移 | 保存后再打开顺序还在 |
| D-02b | 点中「请假类型 = 事假」那条线，右侧【添加过滤条件】选「请假类型」「等于」「事假」，点【保存】后刷新页面再点这条线 | 条件那一行还在，字段、比较方式、值都是刚才选的，不是空的；提交事假确实走部门审批 |
| D-02c | 同一条线上再点【添加过滤条件】加第二行，选一个用了数据字典的字段 | 值那一栏能拉出字典选项，不是空下拉；保存刷新后两行都在 |
| D-03 | 部门审批：指定角色选「部门经理」，「限定与发起人同部门」默认勾上；取消勾 | 提示该角色下所有部门的人都会收到待办 |
| D-04 | 人事备案：指定人员选张三、李四，会签；事由设为可编辑，子表单 `subform` 只能只读或不可见 | 属性里子表没有「可编辑」；关联子表单 `relate-subform`、分割线不出现在字段权限里 |
| D-04b | 部门审批节点：「通过时意见必填」默认不勾、「拒绝时意见必填」默认勾；取消「拒绝时意见必填」后保存刷新 | 勾选状态与刚才一致 |
| D-05 | 故意去掉分支的「其他情况」或删光审批节点，点【保存】后打开【管理已有版本】点【启用流程】 | 顶部逐条列出错误，弹框还在，这一版仍是设计中 |
| D-05b | 同样坏图点【保存并启用】，确认框点确定 | 顶部逐条列出错误，这一版仍是设计中 |
| D-06 | 配好后【保存】，管理里点【启用流程】 | 该版变成启用中；从未启用过时工作台仍不能填，要等启用成功。不要去找顶栏开关 |
| D-07 | 部门审批不指定人员、角色、表单人员字段，只勾「发起人所属部门的负责人」，点【保存】再【启用流程】 | 能启用，顶部没有「没有审批人」 |
| D-08 | 部门审批字段权限：事由、开始日期默认勾了简报，请假类型、附件默认没勾。把请假类型也勾上，保存并启用。提交一张填了这几项的事假 | 经理待办卡片摘要含事由、开始日期、请假类型，不含附件。把简报全不选再保存启用，新单卡片只剩记录编号一类的兜底 |
| D-09 | 请假单有部门单选 `dept`、人员单选 `member`（如直接领导），节点简报勾上这两项后保存启用并提交 | 待办卡片摘要是部门名、姓名，例如「研发部」「李四」，不要出现纯数字 id |
| D-10 | 部门审批字段权限保持默认（事由等显示为只读），不点成可编辑，保存启用后提交一张事假 | 经理打开【我的待办】抽屉，事由等格子不能改 |

## 3. 发起、或签、会签、驳回、撤回

| 编号 | 步骤 | 期望 |
|---|---|---|
| F-01 | 【添加数据】不填事由点【提交】 | 提示请填写事由，【数据管理】没有新行 |
| F-02 | 点【保存草稿】 | 【数据管理】状态「草稿」；首页【我的待办】没有；发起人【我发起的】有这张卡片；【考勤台账】选请假单看不到它 |
| F-03 | 提交事假 | 研发的经理甲、乙首页【我的待办】各多一张；销售经理丙没有；张三还没有；【我发起的】能【撤回】 |
| F-03b | 经理甲打开事假待办 | 默认【表单】页签，请假字段铺满；事由等没标可编辑的格子不能改；点【流程】才看到小流程图和审批进度 |
| F-04 | 再提交一张病假（人事备案会签） | 不经部门审批；张三、李四【我的待办】都有卡片 |
| F-05 | 经理甲打开事假待办，意见不填点【通过】 | 成功；甲的卡片进【我处理的】；乙的待办消失；张三、李四出现待办；打开新待办点【流程】，小图高亮人事备案 |
| F-06 | 张三在人事备案把事由改几个字（节点标了可编辑）点【通过】 | 流程仍停在人事备案，李四待办还在，状态不是已通过 |
| F-07 | 李四点【通过】 | 整单已通过；【考勤台账】现在能挑到这条 |
| F-08 | 另提事假，经理甲【驳回】且意见留空 | 拦「请填写驳回意见」（节点默认「拒绝时意见必填」） |
| F-08b | 部门审批已取消「拒绝时意见必填」并保存启用，经理甲驳回且意见留空 | 能驳回成功 |
| F-09 | 写上意见【驳回】 | 状态已驳回；发起人【我发起的】改成病假点【再次提交】；本轮没有经理待办，直接到张三、李四 |
| F-10 | 把人事备案改成或签并保存启用，再提交一张病假 | 张三、李四都有待办；张三【通过】后李四待办取消，整单已通过 |
| F-11 | 再提一张或签病假，两人几乎同时点【通过】 | 一人成功，另一人提示「这条待办已处理」 |
| F-12 | 会签单里张三【驳回】 | 李四待办取消，状态已驳回 |
| F-13 | 审批中的单，发起人点【撤回】 | 回到草稿；待办消失 |
| F-14 | 一人点【撤回】、另一人同时点【通过】 | 只有一边成功；失败方看到「审批人已开始处理，不能撤回」或「这条待办已处理」 |

## 4. 版本、启用、数据管理

| 编号 | 步骤 | 期望 |
|---|---|---|
| M-01 | 留一张审批中的事假。顶栏【添加新版本】得到 V2，改图并【保存】，管理里启用 V2 | 进行中的仍按提交时的图；新提交的走 V2 |
| M-02 | 【数据管理】看审批中的行：工具栏【编辑】、点单元格 | 【编辑】点不了或提示不能改；单元格不能内联改；详情里能看进度，**没有**【通过】【驳回】 |
| M-03 | 【管理已有版本】看启用中那一行 | 没有【停用】【编辑】【删除】。要点另一份设计中的【启用流程】，原来那份才变成设计中 |
| M-04 | 启用另一版之后看首页和应用内三入口 | 上一张还在审批的卡片还在，能【通过】【驳回】【撤回】；工作台只要还有一版启用中，底部仍是【保存草稿】【提交】 |
| M-05 | 已通过且有实例：发起人 A 在【我发起的】打开 | 只能看，没有【提交】 |
| M-06 | A 在【数据管理】（【表单发布】里【编辑】开着）改事由点【提交】 | 状态回到审批中，按**此刻启用中**的图走；【考勤台账】暂时挑不到 |
| V-01 | 下拉当前是「流程版本 (V1)」，点【添加新版本】 | 得到「流程版本 (V2)」，图画的是 V1 的拷贝，状态设计中，并切到 V2 |
| V-02 | 启用中的版本：画布拖节点、改属性、点【保存】和【保存并启用】；管理弹窗看这一行 | 拖不动、属性改不了、【保存】【保存并启用】都点不了；这一行没有【停用】【编辑】【删除】 |
| V-03 | 下拉当前是启用中的 V1，添加 V2 并【保存】，管理里对 V2 点【启用流程】 | V2 变成启用中且没有按钮；V1 变成设计中（有启用 / 编辑 / 删除）；新提交走 V2，上一张待办还在 |
| V-04 | 删一份设计中的版本 | 要确认「删除后不能恢复」；删光后画布仍有「流程版本 (V1)」和一个开始节点 |
| V-05 | 设计中点【保存并启用】，确认框点取消 | 仍是设计中；画布改动能继续【保存】 |
| M-07 | 发布页关掉【编辑】 | 【数据管理】没有【编辑】 |
| M-08 | 能进数据管理但不是发起人的人打开 A 的已通过行 | 只能看，没有【编辑】 |
| M-09 | 发布页【删除】开着，删一条已通过 | 列表没了；【我发起的】卡片标「数据已删除」，打开抽屉点【流程】只能看进度，不能改 |
| M-10 | 删一条草稿 | 列表没了；【我发起的】也没了 |
| M-11 | 【我发起的】抽屉 | 没有【删除】 |
| M-12 | 【表单发布】看导入、下载导入模版 | 流程表这两项是关的且不能打开；【数据管理】没有导入和下载模版 |
| M-13 | 发布页【删除】开着，发起人删一条**异常**单 | 列表没了；【我发起的】卡片也没了，不会再出现一张只能【重试】的死卡片 |

## 5. 异常与重试

| 编号 | 步骤 | 期望 |
|---|---|---|
| E-01 | 部门经理角色下暂时没有启用用户，提交事假 | 进异常，不是「审批中但没人有待办」；【我发起的】能【重试】【撤回】 |
| E-02 | 把经理丙停用（销售就没有可用的部门经理了），把员工 A 挂到「销售」，再提交一张事假 | 异常文案带节点名，类似「节点「部门审批」在发起人所在部门没有可用的审批人」 |
| E-03 | 派发后把唯一审批人停用，发起人再打开【我发起的】这张卡片 | 状态自己变成「异常」，写「审批人已停用，请重试重新派发审批人」；点【流程】，进度里那个人标着「审批人已停用」；底部出现【重试】 |
| E-04 | 异常单连点两次【重试】 | 第二次不另造一套待办（幂等） |
| E-05 | 只有使用权的人打开【数据管理】里**别人**发起的异常请假单 | 能看详情；底部**没有**【重试】。谁能点见权限专项 F-05～F-07 |
| E-06 | E-02 的异常单：重新启用丙（销售重新有了部门经理），回到【我发起的】点【重试】；测完把员工 A 挂回「研发」 | 停在**部门审批**并派给丙；**不会**跳过部门审批直接到人事备案；小图高亮的还是部门审批 |
| E-07 | E-03 的异常单：把刚停用的那个人重新启用，点【重试】 | 派发成功不报错，他的【我的待办】里这张卡片又回来了；不会提示重复或失败 |
| E-08 | 会签的人事备案里张三已【通过】、李四被停用，发起人打开单据后点【重试】 | 单据保持「异常」，提示这一轮解析出的审批人都已通过、请先恢复被停用成员的账号；**不会**变成「审批中」却没有待办；张三那条仍是「已通过」，不用他再批一次 |
| E-08a | E-08 之后把李四的账号恢复启用，再点【重试】 | 单据回到「审批中」，待办只派给李四；李四批完流程继续往下走 |
| E-09 | 张三先打开人事备案的待办抽屉，此时把 MongoDB 停掉，再点【通过】——写回失败，单据进异常；把 MongoDB 启回来，发起人点【重试】 | 重试后【数据管理】里的事由是**张三改过的内容**，不是他改之前的；会签里还有人没批时单据回到「审批中」等他（不会直接变「已通过」），人都批完才继续往下走 |
| E-10 | 异常单点【重试】，同时另一个人把这张单撤回 | 只有一边生效；不会出现「已撤回但又派出了待办」 |

## 6. 没有使用权的审批人

第 1 期只有应用所有者能进【人事】。用「不是所有者的经理」当审批人即可。

| 编号 | 步骤 | 期望 |
|---|---|---|
| P-01 | 经理甲不是【人事】所有者，打开首页【我的待办】 | 能打开请假单抽屉 |
| P-02 | 看请假类型、字典字段 | 显示「事假」这种中文，不是 code |
| P-03 | 节点允许改选择数据 `data` 时打开弹窗 | 只列出源表已通过的行 |
| P-04 | 他直接访问【人事】或调该应用字典 / 数据管理接口 | 进不去，当应用不存在 |
| P-05 | 失权发起人（发起人被移出使用范围后，首页【我发起的】还能改在途单） | 改测权限专项 F-04 |

## 7. 和已有复杂能力叠在一起

| 编号 | 步骤 | 期望 |
|---|---|---|
| C-01 | 【流程设计】字段权限、分支条件里选标签页 `tabs` 里的「备注」 | 能选到；填报时隐藏该字段，页签标题还在 |
| C-02 | 审批抽屉里看子表单 `subform` | 只能只读或整表隐藏，不能加行改行 |
| C-03 | 请假单带流水号生成 `serialNumber`，审批写回事由后再看流水号 | 号不变 |
| C-04 | 【考勤台账】选择数据 `data` / 关联数据 `relate` 去挑请假单 | 只出现已通过；某条已通过被发起人再提交后，弹窗暂时没它 |
| C-05 | 已经关联上的格子 | 源记录重审期间仍显示原来的标题，不会被抹成空 |
| C-06 | 关联子表单 `relate-subform` 列请假单 | 只列出已通过的反向行 |
| C-07 | 未打开的标签页里有必填 | 【提交】仍拦，并跳到该 pane |

## 不要测

- 转办、加签、并行两条线
- 流程表单转回普通表单
- 首页【我发起的】里删除
- 流程表单导入 Excel
- 审批里编辑子表行
- 失权发起人（权限第 2 期）
- 站外通知
- 单独把启用中的流程关掉（没有【停用】按钮；只能再启用另一版）
