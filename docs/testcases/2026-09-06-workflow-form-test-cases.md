## 测试用表结构

应用名：【人事】。再准备一张普通表【加班单】（后面转流程用），一张普通表【考勤台账】（用来挑请假记录）。

### 请假单（流程表单）

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 请假人 | 人员单选 `member` | 可选范围不限 |
| 请假类型 | 下拉单选框 `select` | 选项：事假 / 病假（字典即可） |
| 开始日期 | 日期选择 `date` | |
| 结束日期 | 日期选择 `date` | |
| 事由 | 多行文本 `textarea` | 必填 |
| 单号 | 流水号生成 `serialNumber` | 默认规则（§7 组合用例 C-03 要用） |
| 附件 | 文件上传 `file` | 选填 |
| 明细 | 子表单 `subform` | 子列：说明（单行文本 `input`） |
| 更多 | 标签页 `tabs` | pane「补充」里放事由以外的一个单行文本 `input`「备注」 |

组织准备：

- 员工 A：发起人，挂部门「研发」
- 经理甲、经理乙：角色「部门经理」，同属「研发」
- 经理丙：角色「部门经理」，属「销售」（不同部门）
- 张三、李四：指定人员，不要求能进【人事】
- 另备一名账号停用的用户，测「审批人已停用」

流程画布（启用前画好）：

```text
开始 → 分支「请假类型」
  事假 → 部门审批（角色：部门经理，勾选「限定与发起人同部门」，或签）
  其他情况 → 人事备案（指定人员：张三、李四，会签）
部门审批 → 人事备案 → 结束
```

【考勤台账】放一个关联数据 `relate` 或选择数据 `data`，数据源选【请假单】。

## 2. 画布与启用

提示：版本一旦启用，画布就只读了。D-07 起每次要改节点属性，都先点顶栏【添加新版本】（复制当前图），改完再启用，别在启用中的画布上找编辑入口。

| 编号 | 步骤 | 期望 |
|---|---|---|
| D-01 | 【流程设计】左侧有审批、分支、抄送、结束；画布上已有开始 | 开始不能从左侧再拖；删开始会立刻回来并提示不能删 |
| D-01b | 点开始、点结束，右侧改节点名称，点【保存】后刷新再点 | 右侧有「节点名称」输入框；画布上的字跟着改；刷新后名称还在 |
| D-01d | 点开始，看「流程终止后是否可以修改后重新提交」；关掉后点【保存】，刷新再点开始 | 默认开着；保存刷新后仍是关。点结束没有这个开关。测完把开关改回开着再保存（后面用例按默认开测；这时还没启用过，画布直接改即可） |
| D-01e | 点开始，在字段权限里把必填的「事由」设只读、「请假类型」设不可见并勾事由简报，保存并启用。打开【添加数据】：事由灰掉不能改、请假类型不出现。只填其余能看见、能改的项（开始日期、结束日期等），点【提交】 | 能交出去，不要弹出「请填写事由」或「请填写请假类型」。待办卡片摘要按简报约定带事由（空着也可以）。开始节点设成只读 / 不可见的字段不再拦必填。退回发起人待办同样：事由不能改、请假类型不出现，再交也不因这两项空着被拦 |
| D-01g | 点开始，看「开启流程超时」。默认关着。打开后选有效时长 2 分钟或指定截止时间，保存并启用 | 关掉时没有时长和截止时间。细项回流程超时专项 T-01～T-08。测完把开关关掉再启用，避免后面用例被自动驳回 |
| D-01f | 点开始，把必填的子表单 `subform`「请假明细」设不可见，保存并启用。【添加数据】只填看得见、能改的项，不填请假明细，点【提交】 | 能交出去，不要弹出 `[请假明细]不能为空`。填报里看不到请假明细 |
| D-01h | 接着 D-01f：部门审批把「事由」设成可编辑（请假明细保持只读或不可见，审批节点本来就不能改子表）。经理打开【我的待办】，只填能改的项点【同意】 | 能通过。不要弹出 `[请假明细]不能为空`。待办被处理掉，流程往下走 |
| D-02 | 分支线配「请假类型 = 事假」，另一条勾「其他情况」 | 保存后再打开条件与「其他情况」勾选还在 |
| D-02b | 点中「请假类型 = 事假」那条线，右侧点【添加过滤条件】，弹框里选「请假类型」「等于」「事假」后确定；右侧显示【已添加筛选条件】；点【保存】后刷新再点这条线 | 再点【已添加筛选条件】弹框里条件还在；提交事假确实走部门审批 |
| D-02c | 同一条线再点【已添加筛选条件】加第二行，选一个用了数据字典的字段 | 值那一栏能拉出字典选项，不是空下拉；保存刷新后两行都在 |
| D-02d | 开始节点已连到「部门审批」，再拖一条线连到第二个审批节点；或审批节点已连到下一审批，再拖一条线连到另一个审批 | 第二条线立刻消失，提示不能同时连多个审批节点，需先加分支再分别连；分支节点仍可连多条线到不同审批 |
| D-02e | 【添加新版本】：把「事假」那条线的过滤条件清掉，改成「开始日期」操作选「选择范围」，起止填本月 1 号到月末（或任意能罩住今天的区间），另一条仍勾「其他情况」，保存并启用。交一张开始日期落在这个区间里的单；再交一张开始日期在区间外的单 | 区间内的单进部门审批（经理甲/乙待办）；区间外的单直接进人事备案（张三、李四待办），经理没有。不要两张都落到「其他情况」。测完再加新版本把条件改回「请假类型 = 事假」并启用 |
| D-03 | 部门审批：指定角色选「部门经理」，「限定与发起人同部门」默认勾上；取消勾 | 提示该角色下所有部门的人都会收到待办 |
| D-04 | 人事备案：指定人员选张三、李四，会签；事由设为可编辑，子表单 `subform` 只能只读或不可见 | 属性里子表没有「可编辑」；关联子表单 `relate-subform`、分割线不出现在字段权限里 |
| D-04b | 部门审批节点：「通过时意见必填」默认不勾、「拒绝时意见必填」默认勾；取消「拒绝时意见必填」后保存刷新 | 勾选状态与刚才一致。测完把「拒绝时意见必填」重新勾上再保存（F-08 仍按默认必填被拦） |
| D-04c | 人事备案指定人员选张三，点【保存】后刷新页面，再点该审批节点看「指定人员」 | 标签显示「张三」，不是「已删除」。抄送节点同样：选好人后刷新再点，仍是姓名 |
| D-05 | 故意去掉分支的「其他情况」或删光审批节点，点【保存】后打开【管理已有版本】点【启用流程】 | 顶部逐条列出错误，弹框还在，这一版仍是设计中 |
| D-05b | 同样坏图点【保存并启用】，确认框点确定 | 顶部逐条列出错误，这一版仍是设计中 |
| D-06 | 配好后【保存】，管理里点【启用流程】 | 该版变成启用中；从未启用过时工作台仍不能填，要等启用成功。不要去找顶栏开关 |
| D-07 | 部门审批不指定人员、角色、表单人员字段，只勾「发起人所属部门的负责人」，点【保存】再【启用流程】 | 能启用，顶部没有「没有审批人」 |
| D-08 | 部门审批字段权限：事由、开始日期默认勾了简报，请假类型、附件默认没勾。把请假类型也勾上，保存并启用。提交一张填了这几项的事假 | 经理待办卡片摘要含事由、开始日期、请假类型，不含附件。把简报全不选再保存启用，新单卡片只剩记录编号一类的兜底 |
| D-09 | 请假单有部门单选 `dept`、人员单选 `member`（如直接领导），节点简报勾上这两项后保存启用并提交 | 待办卡片摘要是部门名、姓名，例如「研发部」「李四」，不要出现纯数字 id |
| D-10 | 部门审批字段权限保持默认（事由等显示为只读），不点成可编辑，保存启用后提交一张事假 | 经理打开【我的待办】抽屉，事由等格子不能改 |

## 3. 发起、或签、会签、驳回、撤回

| 编号 | 步骤 | 期望 |
|---|---|---|
| F-01 | 【添加数据】不填事由点【提交】 | 提示请填写事由，【数据管理】没有新行 |
| F-02 | 点【保存草稿】 | 【数据管理】状态「草稿」；首页【我的待办】没有；发起人【我发起的】有这张卡片；【考勤台账】选请假单看不到它 |
| F-03 | 提交事假 | 研发的经理甲、乙首页【我的待办】各多一张；销售经理丙没有；张三还没有；【我发起的】能【撤回】 |
| F-03b | 经理甲打开事假待办 | 默认【表单】页签，请假字段铺满；事由等没标可编辑的格子不能改；点【流程】才看到小流程图和审批进度；进度**最上面**是发起人「开始 · 已提交」，下面是审批待办 |
| F-04 | 再提交一张病假（人事备案会签） | 不经部门审批；张三、李四【我的待办】都有卡片 |
| F-05 | 经理甲打开事假待办，意见不填点【同意】 | 成功；甲的卡片进【我处理的】；乙的待办消失；张三、李四出现待办；打开新待办点【流程】，小图高亮人事备案 |
| F-06 | 张三在人事备案把事由改几个字（节点标了可编辑）点【同意】 | 流程仍停在人事备案，李四待办还在，状态不是已通过 |
| F-07 | 李四点【同意】 | 整单已通过；【考勤台账】现在能挑到这条 |
| F-08 | 另提事假，经理甲【驳回】且意见留空 | 拦「请填写驳回意见」（节点默认「拒绝时意见必填」） |
| F-08b | 顶栏【添加新版本】，取消部门审批的「拒绝时意见必填」，【保存并启用】，经理甲驳回且意见留空 | 能驳回成功 |
| F-09 | 写上意见【驳回】 | 状态已驳回；数据详情【流程】小图**不要**高亮结束（默认开着「终止后再交」），走过的审批节点可以是绿的；发起人【我发起的】改成病假点【再次提交】；进度里多一条「开始 · 再次提交」；本轮没有经理待办，直接到张三、李四 |
| F-09b | 顶栏【添加新版本】，点开始关掉「流程终止后是否可以修改后重新提交」，【保存并启用】。另提一张事假，经理甲驳回 | 【我发起的】打开只能看，没有【保存草稿】【再次提交】。【数据管理】这行也没有【编辑】。打开【流程】小图高亮结束。草稿、异常单仍能改。测完再【添加新版本】把开关改回开着并启用（M-06 要用） |
| F-10 | 顶栏【添加新版本】，把人事备案改成或签，【保存并启用】，再提交一张病假 | 张三、李四都有待办；张三【同意】后李四待办取消，整单已通过 |
| F-11 | 再提一张或签病假，两人几乎同时点【同意】 | 一人成功，另一人提示「这条待办已处理」 |
| F-12 | 用人事备案仍是会签的版本（或另添加新版本改回会签并启用）再提一张病假，张三【驳回】 | 李四待办取消，状态已驳回；无论或签会签，任一人驳回即整单驳回 |
| F-13 | 审批中的单，发起人点【撤回】 | 回到草稿；待办消失 |
| F-14 | 一人点【撤回】、另一人同时点【同意】 | 只有一边成功；失败方看到「审批人已开始处理，不能撤回」或「这条待办已处理」 |

## 4. 版本、启用、数据管理

| 编号 | 步骤 | 期望 |
|---|---|---|
| M-01 | 留一张审批中的事假。顶栏版本下拉里点【添加新版本】得到 V2，改图并【保存】，管理里启用 V2 | 进行中的仍按提交时的图；新提交的走 V2 |
| M-02 | 【数据管理】看审批中的行：工具栏【编辑】、点单元格 | 【编辑】点不了或提示不能改；单元格不能内联改；详情默认【表单】，点【流程】能看进度，**没有**【同意】【驳回】 |
| M-03 | 【管理已有版本】看启用中那一行 | 没有【停用】【编辑】【删除】。要点另一份设计中的【启用流程】，原来那份才变成设计中 |
| M-04 | 启用另一版之后看首页和应用内四入口 | 上一张还在审批的卡片还在：审批人打开抽屉仍能【同意】【驳回】，发起人打开仍能【撤回】/【保存草稿】/【再次提交】；工作台只要还有一版启用中，底部仍是【保存草稿】【提交】 |
| M-05 | 已通过且有实例：发起人 A 在【我发起的】打开 | 只能看，没有【提交】 |
| M-06 | A 在【数据管理】（【表单发布】里【编辑】开着）改事由点【提交】 | 状态回到审批中，按**此刻启用中**的图走；【考勤台账】暂时挑不到 |
| M-06b | 顶栏【添加新版本】，点开始关掉「流程终止后是否可以修改后重新提交」，【保存并启用】。A 打开已通过那行 | 【数据管理】没有【编辑】；【我发起的】仍只能看；打开【流程】，小图高亮结束节点 |
| V-01 | 下拉当前是「流程版本 (V1)」，点【添加新版本】 | 得到「流程版本 (V2)」，图画的是 V1 的拷贝，状态设计中，并切到 V2 |
| V-02 | 启用中的版本：画布拖节点、改属性、点【保存】和【保存并启用】；管理弹窗看这一行 | 拖不动、属性改不了、【保存】【保存并启用】都点不了；这一行没有【停用】【编辑】【删除】 |
| V-03 | 下拉当前是启用中的 V1，添加 V2 并【保存】，管理里对 V2 点【启用流程】 | V2 变成启用中且没有按钮；V1 变成设计中（有启用 / 编辑 / 删除）；新提交走 V2，上一张待办还在 |
| V-04 | 删一份设计中的版本 | 要确认「删除后不能恢复」；删光后画布仍有「流程版本 (V1)」和一个开始节点 |

## 5. 异常与重试

| 编号 | 步骤 | 期望 |
|---|---|---|
| E-01 | 部门经理角色下暂时没有启用用户，提交事假 | 进异常，不是「审批中但没人有待办」；【我发起的】能【重试】【撤回】 |
| E-02 | 把经理丙停用（销售就没有可用的部门经理了），把员工 A 挂到「销售」，再提交一张事假 | 异常文案带节点名，类似「节点「部门审批」在发起人所在部门没有可用的审批人」 |
| E-03 | 派发后把唯一审批人停用，发起人再打开【我发起的】这张卡片 | 状态自己变成「异常」，写「审批人已停用，请重试重新派发审批人」；点【流程】，进度里那个人标着「审批人已停用」；底部出现【重试】 |
| E-04 | 异常单连点两次【重试】 | 第二次不另造一套待办（幂等） |
| E-05 | 只有使用权的人打开【数据管理】里**别人**发起的异常请假单 | 能看详情；底部**没有**【重试】。谁能点见权限专项 F-05～F-07 |
| E-06 | E-02 的异常单：重新启用丙（销售重新有了部门经理），回到【我发起的】点【重试】；测完把员工 A 挂回「研发」 | 停在**部门审批**并派给丙；**不会**跳过部门审批直接到人事备案；小图高亮的还是部门审批 |
| E-07 | E-03 的异常单：把刚停用的那个人重新启用，点【重试】 | 派发成功不报错，他的【我的待办】里这张卡片又回来了；不会提示重复或失败 |
| E-08 | 会签的人事备案里张三已【同意】、李四被停用，发起人打开单据后点【重试】 | 单据保持「异常」，提示这一轮解析出的审批人都已通过、请先恢复被停用成员的账号；**不会**变成「审批中」却没有待办；张三那条仍是「已通过」，不用他再批一次 |
| E-08a | E-08 之后把李四的账号恢复启用，再点【重试】 | 单据回到「审批中」，待办只派给李四；李四批完流程继续往下走 |
| E-09 | 张三先打开人事备案的待办抽屉，此时把 MongoDB 停掉，再点【同意】——写回失败，单据进异常；把 MongoDB 启回来，发起人点【重试】 | 重试后【数据管理】里的事由是**张三改过的内容**，不是他改之前的；会签里还有人没批时单据回到「审批中」等他（不会直接变「已通过」），人都批完才继续往下走 |
| E-10 | 异常单点【重试】，同时另一个人把这张单撤回 | 只有一边生效；不会出现「已撤回但又派出了待办」 |
| E-11 | 会签人事备案：张三【同意】时写回失败进异常（李四待办还在）→ 发起人在【我发起的】改完点【再次提交】 | 李四原来那条待办从【我的待办】消失（进度里是「未处理（已取消）」）；新一轮按改后的内容从头走。李四不能再拿旧待办把新一轮驳回 |

## 9. 转交、加签、退回

预备：组织里另备一名启用用户**王五**（不必能进【人事】）。添加新版本，把人事备案改回**会签**（张三、李四），勾上「允许转交」「允许加签」，部门审批和人事备案都把「事由」标成可编辑，【保存并启用】。退回不用配（默认就有）。用事假单走到人事备案。A-09 用：给员工 A 临时加上「部门经理」角色，让发起人自己也在部门审批的名单里（测完移除）。

| 编号 | 步骤 | 期望 |
|---|---|---|
| A-01 | 【流程设计】点部门审批，看右侧「审批操作」 | 只有「允许转交」「允许加签」，默认都不勾。没有「允许退回」一类勾选 |
| A-02 | 经理打开事假待办（还在部门审批） | 有【同意】【驳回】【退回至发起人】；没有【转交】【加签】；也没有【退回至上一审批节点】（前面没有审批节点） |
| A-03 | 人事备案待办点【退回至上一审批节点】，填「请补事由」确定 | 卡片和数据管理仍是审批中；张三、李四在人事备案的待办取消；甲的【我的待办】又有部门审批（乙若或签已被取消则没有）；甲打开能改本节点标了可编辑的字段 |
| A-04 | 甲改事由点【同意】 | 写回成功，流程再到人事备案，人事那边又有待办 |
| A-05 | 人事备案点【退回至发起人】，填意见确定 | 状态仍审批中，不是已驳回；发起人 A 的【我的待办】有「待发起人修改」；【我发起的】底部没有「再次提交」当主路径 |
| A-06 | A 在这条待办里改结束日期点【提交】 | 仍审批中，部门审批重新出现待办；没有同意/驳回，底部是【提交】 |
| A-07 | 另一张事假走到人事备案，张三【转交】给王五 | 张三这条进【我处理的】；王五【我的待办】有这张；李四的待办不被清掉（会签下转交只替换张三这一席） |
| A-07b | 王五想把单转给已有待办的李四 | 拦「该用户已有待办」。王五【同意】后仍停在本节点等李四，李四也【同意】才到结束 |
| A-08 | 另一张事假走到人事备案，张三【加签】王五后自己点【同意】 | 仍停在本节点，等李四和王五；两人都【同意】后才往下；【流程】里王五「待处理」在「张三 加签 王五」说明下面 |
| A-09 | 同一人既是发起人又是部门审批：分别退回至上一审批节点和退回至发起人 | 上一节点待办底部是同意/驳回；退回发起人待办底部是提交，字段按开始节点字段权限可改 |
| A-10 | 部门审批勾上「允许加签」并启用。事假交到部门审批后，甲【加签】王五（可写「你也来看看」），再自己【驳回】。打开【流程】页签看进度 | 从上到下：甲加签王五 → 甲驳回 → 王五「未处理（已取消）」。已取消不能排在加签或驳回前面 |

## 不要测

- 减签、退回任意指定节点、批量转交、并行两条线
- 流程表单转回普通表单
- 首页【我发起的】里删除
- 流程表单导入 Excel
- 审批里编辑子表行
- 失权发起人（权限第 2 期）
- 站外通知
- 单独把启用中的流程关掉（没有【停用】按钮；只能再启用另一版）
- 把抄送放进【我的待办】，或跟【我处理的】混在一起
- 抄送人在抽屉里改表单或填意见
- 从结束连出抄送
- 抄送未读点、已读未读
