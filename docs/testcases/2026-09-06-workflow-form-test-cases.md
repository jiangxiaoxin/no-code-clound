# 流程表单手工测试用例

日期：2026-09-06  
范围：建表时选【流程表单】、【流程设计】画布、【添加数据】提交、首页和应用内【我的待办】/【我发起的】/【我处理的】、【数据管理】里的流程状态。  
对照设计：`docs/superpowers/specs/2026-09-05-workflow-form-design.md`  
对照使用说明：`docs/guides/2026-09-06-workflow-form-usage.md`

流程不是调色板控件。用例里的字段仍写调色板中文名和 `type`。

---

## 测试用表结构

应用名：【人事】。再准备一张普通表【加班单】（后面转流程用），一张普通表【考勤台账】（用来挑请假记录）。

### 请假单（流程表单）

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 请假人 | 人员单选 `member` | 可选范围不限 |
| 请假类型 | 下拉单选框 `select` | 选项：事假 / 病假（字典即可） |
| 开始日期 | 日期选择 `date` | |
| 结束日期 | 日期选择 `date` | |
| 事由 | 多行文本 `textarea` | 必填 |
| 附件 | 文件上传 `file` | 选填 |
| 明细 | 子表单 `subform` | 子列：说明（单行文本 `input`） |
| 更多 | 标签页 `tabs` | pane「补充」里放事由以外的一个单行文本 `input`「备注」 |

组织准备：

- 员工 A：发起人，挂部门「研发」
- 经理甲、经理乙：角色「部门经理」，同属「研发」
- 经理丙：角色「部门经理」，属「销售」（不同部门）
- 张三、李四：指定人员，不要求能进【人事】
- 另备一名账号停用的用户，测「审批人已停用」

流程画布（发布前画好）：

```text
开始 → 分支「请假类型」
  事假 → 部门审批（角色：部门经理，勾选「限定与发起人同部门」，或签）
  其他情况 → 人事备案（指定人员：张三、李四，会签）
部门审批 → 人事备案 → 结束
```

【考勤台账】放一个关联数据 `relate` 或选择数据 `data`，数据源选【请假单】。

## 0. 冒烟

| 编号 | 步骤 | 期望 |
|---|---|---|
| S-01 | 【人事】→ 新建表单，名称「请假单」，表单类型选【流程表单】→ 确定 | 树里出现【请假单】；打开设计顶栏有【表单设计】【流程设计】【表单发布】【数据管理】 |
| S-02 | 先不进【流程设计】，工作台打开【请假单】→【添加数据】 | 顶部写「这张表单还没有配置流程，暂时不能填报」 |
| S-03 | 填一事由，点【保存草稿】，再点【提交】 | 两次都提示还没配置流程；【数据管理】没有新行 |
| S-04 | 【数据管理】点【新增】 | 同样提示，不出现可保存的新数据 |
| S-05 | 切到【流程设计】，按上面的图画完，点【发布】 | 成功；顶部出现「当前已发布版本 v1」；【启用流程】为开 |
| S-06 | 回【添加数据】，请假类型选事假，填必填，点【提交】 | 提示「已提交，等待「部门审批」」；【数据管理】该行流程状态是「审批中」 |

## 1. 建表、页签、转换

| 编号 | 步骤 | 期望 |
|---|---|---|
| W-01 | 再建一张【普通表单】「加班单」，打开设计 | 顶栏只有【表单设计】【表单发布】【数据管理】，没有【流程设计】 |
| W-02 | 浏览器打开加班单设计并在地址后加 `?tab=workflow` | 回到【表单设计】，不出现流程画布 |
| W-03 | 加班单先保存几条数据。表单树 ⋯ →【转为流程表单】 | 确认框写明已有数据将记为已通过，且发布流程之前不能再填报 |
| W-04 | 确定转换 | 顶栏出现【流程设计】；旧数据【数据管理】流程状态是「已通过」；点开详情流程区写「转为流程表单之前保存，没有审批记录」，没有空流程图，没有【编辑】【提交】 |
| W-05 | 【考勤台账】用选择数据 `data` / 关联数据 `relate` 去挑加班单旧数据 | 能挑到这些已通过的旧行 |
| W-06 | 看【请假单】树菜单 | 没有「转为普通表单」 |

## 2. 画布与发布

| 编号 | 步骤 | 期望 |
|---|---|---|
| D-01 | 【流程设计】左侧只有审批、分支、结束；画布上已有开始 | 开始不能从左侧再拖；删开始会立刻回来并提示不能删 |
| D-02 | 分支线配「请假类型 = 事假」，另一条勾「其他情况」，可上移下移 | 保存后再打开顺序还在 |
| D-03 | 部门审批：指定角色选「部门经理」，「限定与发起人同部门」默认勾上；取消勾 | 提示该角色下所有部门的人都会收到待办 |
| D-04 | 人事备案：指定人员选张三、李四，会签；事由设为可编辑，子表单 `subform` 只能只读或隐藏 | 属性里子表没有「可编辑」；关联子表单 `relate-subform`、分割线不出现在字段权限里 |
| D-05 | 故意去掉分支的「其他情况」或删光审批节点，点【发布】 | 顶部逐条列出错误，不是只 toast 一句失败 |
| D-06 | 配好后【发布】 | 成功后【启用流程】为开；从未发布过时开关是关的，强行打开会被拒绝 |

## 3. 发起、或签、会签、驳回、撤回

| 编号 | 步骤 | 期望 |
|---|---|---|
| F-01 | 【添加数据】不填事由点【提交】 | 提示请填写事由，【数据管理】没有新行 |
| F-02 | 点【保存草稿】 | 【数据管理】状态「草稿」；首页【我的待办】没有；发起人【我发起的】有这张卡片；【考勤台账】选请假单看不到它 |
| F-03 | 提交事假 | 研发的经理甲、乙首页【我的待办】各多一张；销售经理丙没有；张三还没有；【我发起的】能【撤回】 |
| F-04 | 再提交一张病假（人事备案会签） | 不经部门审批；张三、李四【我的待办】都有卡片 |
| F-05 | 经理甲打开事假待办，意见不填点【通过】 | 成功；甲的卡片进【我处理的】；乙的待办消失；张三、李四出现待办；小图高亮人事备案 |
| F-06 | 张三在人事备案把事由改几个字（节点标了可编辑）点【通过】 | 流程仍停在人事备案，李四待办还在，状态不是已通过 |
| F-07 | 李四点【通过】 | 整单已通过；【考勤台账】现在能挑到这条 |
| F-08 | 另提事假，经理甲【驳回】且意见留空 | 拦「请填写驳回意见」 |
| F-09 | 写上意见【驳回】 | 状态已驳回；发起人【我发起的】改成病假点【再次提交】；本轮没有经理待办，直接到张三、李四 |
| F-10 | 把人事备案改成或签并发布，再提交一张病假 | 张三、李四都有待办；张三【通过】后李四待办取消，整单已通过 |
| F-11 | 再提一张或签病假，两人几乎同时点【通过】 | 一人成功，另一人提示「这条待办已处理」 |
| F-12 | 会签单里张三【驳回】 | 李四待办取消，状态已驳回 |
| F-13 | 审批中的单，发起人点【撤回】 | 回到草稿；待办消失 |
| F-14 | 一人点【撤回】、另一人同时点【通过】 | 只有一边成功；失败方看到「审批人已开始处理，不能撤回」或「这条待办已处理」 |

## 4. 版本、启用、数据管理

| 编号 | 步骤 | 期望 |
|---|---|---|
| M-01 | 留一张审批中的事假，改画布后【发布】成 v2 | 进行中的仍按提交时的图；新提交的走 v2 |
| M-02 | 【数据管理】看审批中的行：工具栏【编辑】、点单元格 | 【编辑】点不了或提示不能改；单元格不能内联改；详情里能看进度，**没有**【通过】【驳回】 |
| M-03 | 关掉【启用流程】，【添加数据】再保存一条 | 底部回到【保存】；状态「已通过」；详情写「流程停用期间保存，没有审批记录」；【考勤台账】能挑到 |
| M-04 | 关掉期间看首页和应用内三入口 | 上一张还在审批的卡片还在，能【通过】【驳回】【撤回】 |
| M-05 | 已通过且有实例：发起人 A 在【我发起的】打开 | 只能看，没有【提交】 |
| M-06 | A 在【数据管理】（发布页【编辑】开着）改事由点【提交】 | 状态回到审批中，按**当前已发布**图走；【考勤台账】暂时挑不到 |
| M-07 | 发布页关掉【编辑】 | 【数据管理】没有【编辑】 |
| M-08 | 能进数据管理但不是发起人的人打开 A 的已通过行 | 只能看，没有【编辑】 |
| M-09 | 发布页【删除】开着，删一条已通过 | 列表没了；【我发起的】卡片标「数据已删除」，只能看进度，不能改 |
| M-10 | 删一条草稿 | 列表没了；【我发起的】也没了 |
| M-11 | 【我发起的】抽屉 | 没有【删除】 |
| M-12 | 【表单发布】看导入、下载导入模版 | 流程表这两项是关的且不能打开；【数据管理】没有导入和下载模版 |

## 5. 异常与重试

| 编号 | 步骤 | 期望 |
|---|---|---|
| E-01 | 部门经理角色下暂时没有启用用户，提交事假 | 进异常，不是「审批中但没人有待办」；【我发起的】能【重试】【撤回】 |
| E-02 | 发起人部门没有该角色的人（销售没有部门经理） | 异常文案带节点名，类似「节点「部门审批」在发起人所在部门没有可用的审批人」 |
| E-03 | 派发后把唯一审批人停用 | 进度里能看到「审批人已停用」；【重试】后重新派人 |
| E-04 | 异常单连点两次【重试】 | 第二次不另造一套待办（幂等） |
| E-05 | 只有使用权的人打开【数据管理】里**别人**发起的异常请假单 | 能看详情；底部**没有**【重试】。谁能点见权限专项 F-05～F-07 |

## 6. 没有使用权的审批人

第 1 期只有应用所有者能进【人事】。用「不是所有者的经理」当审批人即可。

| 编号 | 步骤 | 期望 |
|---|---|---|
| P-01 | 经理甲不是【人事】所有者，打开首页【我的待办】 | 能打开请假单抽屉 |
| P-02 | 看请假类型、字典字段 | 显示「事假」这种中文，不是 code |
| P-03 | 节点允许改选择数据 `data` 时打开弹窗 | 只列出源表已通过的行 |
| P-04 | 他直接访问【人事】或调该应用字典 / 数据管理接口 | 进不去，当应用不存在 |
| P-05 | 失权发起人（发起人被移出使用范围后，首页【我发起的】还能改在途单） | 改测权限专项 F-04 |

## 7. 和已有复杂能力叠在一起

| 编号 | 步骤 | 期望 |
|---|---|---|
| C-01 | 【流程设计】字段权限、分支条件里选标签页 `tabs` 里的「备注」 | 能选到；填报时隐藏该字段，页签标题还在 |
| C-02 | 审批抽屉里看子表单 `subform` | 只能只读或整表隐藏，不能加行改行 |
| C-03 | 请假单带流水号生成 `serialNumber`，审批写回事由后再看流水号 | 号不变 |
| C-04 | 【考勤台账】选择数据 `data` / 关联数据 `relate` 去挑请假单 | 只出现已通过；某条已通过被发起人再提交后，弹窗暂时没它 |
| C-05 | 已经关联上的格子 | 源记录重审期间仍显示原来的标题，不会被抹成空 |
| C-06 | 关联子表单 `relate-subform` 列请假单 | 只列出已通过的反向行 |
| C-07 | 未打开的标签页里有必填 | 【提交】仍拦，并跳到该 pane |

## 不要测

- 转办、加签、并行两条线
- 流程表单转回普通表单
- 首页【我发起的】里删除
- 流程表单导入 Excel
- 审批里编辑子表行
- 失权发起人（权限第 2 期）
- 站外通知
