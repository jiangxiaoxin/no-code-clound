# 表单字段公式手工测试用例

日期：2026-09-11  
规格见 `docs/superpowers/specs/2026-09-11-formula-design.md`。公式不是调色板里的新控件，是六类字段（单行文本 `input`、多行文本 `textarea`、数字 `number`、日期选择 `date`、时间选择 `time`、日期时间 `datetime`）在属性面板上的「计算公式」配置。配了公式的字段在填写页只读、值自动算，保存时服务端按公式重算覆盖。

改引用字段后公式**立即重算**（没有防抖），不用等 1 秒。涉及服务端重算、导入、接口篡改的用例（§5）需要本地起着服务端；接口篡改要用浏览器开发者工具或 curl。

---

## 测试用表结构

登录后打开**自己的应用**，新建一张「订单统计」表，拖完字段点设计器 **保存**。

根上：

| 字段标题 | 组件 `type` | 配置 / 条件 | 示例数据 |
|---|---|---|---|
| 商品名称 | 单行文本 `input` | 自定义 | `螺丝` |
| 单价 | 数字 `number` | 自定义 | `2.5` |
| 订单标记 | 单行文本 `input` | 公式 §0 配：`CONCATENATE('订单-', $'商品名称')`，§2 改成带 IF 的版本 | `订单-螺丝` |
| 到货日期 | 日期选择 `date` | 公式 §2 配：`DATEDELTA(TODAY(), 7)` | 今天 +7 天的日期 |
| 下单时刻 | 日期时间 `datetime` | 公式 §2 配：`NOW()` | 保存那一刻 |
| 订单合计 | 数字 `number` | 公式 §3 配：`SUM($'明细.金额')` | `17.5` |
| 流水号生成 | 流水号 `serialNumber` | 默认规则（分隔符 `-`、当天日期、计数）；§5 F-32 再补「表单字段」段 | `20260911-00001` |

子表「**明细**」（子表单 `subform`，默认行数 `2`）：

| 字段标题 | 组件 `type` | 配置 / 条件 | 示例数据 |
|---|---|---|---|
| 备注 | 单行文本 `input` | 自定义（用来测聚合参数报错，不配公式） | 随意 |
| 数量 | 数字 `number` | 自定义 | 第 1 行 `3`、第 2 行 `4` |
| 金额 | 数字 `number` | 公式 §3 配（行内）：`$'数量' * $'单价'`，单价在「主表字段」分组 | `7.5`、`10` |
| 含税金额 | 数字 `number` | 公式 §3 配（行内）：`ROUND($'金额' * 1.13, 2)` | `8.48`、`11.3` |

「明细」子表勾选显示「备注、数量、金额、含税金额」四列。

## 怎么测

1. 先做 **§0 冒烟**。过不了就停。
2. 再按 §1～§4 做编辑器报错、四类字段计算、子表行内与聚合、只读与列表。
3. §5 服务端兜底需要起服务端；F-30 接口篡改用开发者工具的 Network 面板或 curl。
4. 公式重算是**同步的**：引用字段一变立刻出值。若要点「确定」后没看到状态变化，先看状态行是不是红字。

## 1. 编辑器输入与报错

除 F-33（候选面板）、F-36（原始内容）、F-37（帮助文档）外，「确定」置灰 + 底部红字是每条的公共期望，表里只写红字内容。报错都带**第几行第几列**定位（单行公式都是第 1 行）。

| 编号 | 步骤 | 期望 | 结果 |
|---|---|---|---|
| F-05 | 给「订单合计」输入 `$'商品名称' +` | 红字「公式语法错误：第 1 行第 N 列附近（…）」 | |
| F-06 | 手打 `$'price2'` | 红字「公式引用了不存在的字段 …」；点字段插入的引用不会报这个错 | |
| F-07 | 输入 `SUMIF($'明细.数量', 1)` | 红字「公式不支持函数 SUMIF」 | |
| F-08 | 输入 `IF($'单价' > 1)`；再给单行文本字段输入 `TEXT($'单价')` | 红字「函数 IF 参数个数不正确：用法 IF(条件, 结果1, 结果2)，要 3 个参数，现在给了 1 个」；第二个红字把 `TEXT(值, 格式)` 的用法和「要 2 个参数，现在给了 1 个」都写出来，照着补成 `TEXT($'单价', '0.00')` 就变绿 | |
| F-09 | 给「订单合计」（数字）输入 `ROUND('abc', 2)` | 红字「函数 ROUND 参数类型不正确」 | |
| F-10 | 给「订单合计」输入 `SUM($'明细.备注')`（备注是单行文本） | 红字「聚合函数参数请选择子表单数字字段」；换成 `SUM($'明细.数量')` 应变绿「公式可以保存」 | |
| F-11 | 给「到货日期」（日期）配 `CONCATENATE('a', 'b')` | 红字「公式结果类型与字段不匹配」；给单行文本配同样公式**不报错**（文本收任何结果） | |
| F-12 | 输入框清空 | 红字「请填写公式」，「确定」置灰 | |
| F-13 | 配 `CONCATENATE($'商品名称', '-', $'单价')` | 下方出现两个 chip：商品名称、单价，一一对应引用的字段标题 | |
| F-14 | 新建两个数字字段 A、B：A 配 `$'b' + 1` 保存；再给 B 配 `$'a' + 1`（编辑器里能过，因为单条看是合法的），保存表单 | **保存表单被拦**，提示含「公式存在循环引用」，表单保存失败；把 B 的公式清掉再保存就成功 | |
| F-15 | 给「商品名称」先勾「必填」，再配公式并确定 | 「校验设置」整块消失（必填、不允许重复值都勾不了），之前勾的必填被自动清掉 | |
| F-16 | 选中「订单标记」点「清除」 | 摘要回「未设置」、清除按钮消失；保存表单后填写页该字段恢复可手动填写 | |
| F-33 | 在公式输入区依次试：打 `$`；打 `单`；删掉改成打 `SUM`；在 `'订单-` 这样的字符串里继续打字 | 打 `$` 弹出候选面板「当前表单字段」，列出全部可引用字段并带类型（如「单行文本」）；打 `单` 只剩标题含「单」的字段；打 `SUM` 只剩「函数」区的 `SUM`（没有 SUMIF）；↑↓ 高亮、回车或 Tab 插入：字段插成一颗蓝底标签、函数插成 `SUM()` 且光标在括号里；鼠标点选同样能插入；Esc 或点面板外面关掉；**在字符串里打字不弹候选** | |
| F-34 | 配好 `CONCATENATE('订单-', $'商品名称')` 后：Ctrl+A 全选 → Ctrl+C → 点「清空」→ Ctrl+V；再试选中一段（含字段标签）Ctrl+X | 复制出去的是 `CONCATENATE('订单-', $'商品名称')` 这种**按字段标题写**的文本（粘到记事本该长这样）；粘回来字段仍是**一颗颗蓝底标签**，公式和复制前一模一样、状态行仍是绿的「公式可以保存」；Ctrl+X 等于复制＋删掉选中部分；从带换行的文本粘贴进来会压成一行 | |
| F-35 | 把公式配成 `CONCATENATE('订单-', $'商品名称', $'单价')`，然后按这几种姿势删字段：① 光标停在「单价」标签右边按退格 ② 用鼠标点一下「商品名称」标签中间再按退格 ③ 光标停在「单价」标签左边按 Delete ④ 拖选横跨两颗标签后按退格 ⑤ Ctrl+A 后按退格 | 每次都是**整颗标签一起消失**，不会出现「标签上的字没了、引用却还在」这种删不掉的状态；公式、`/ 2000` 字数、「已引用字段」三处同步变化；删空后回到灰字示例、状态行「请填写公式」、「确定」置灰；删完再补一颗标签仍然正常 | |
| F-36 | 配好 `CONCATENATE('订单-', $'商品名称')`，点公式内容右上角「清空」右边的「原始内容」 | 输入区下方展开一块「原始内容（存库写法，字段是 key）」，里面写的是 `CONCATENATE('订单-', $'bb48af63-…')` 这种**字段 key** 形态（和输入区里的标题形态对照着看），能选中复制；按钮变成「收起原始内容」，再点收起、输入区高度弹回；点「清空」后按钮和面板都不出现；关掉弹窗重新打开是收起状态 | |
| F-37 | 点弹窗左下角「帮助文档」 | 弹出独立的帮助弹窗（可拖拽）：左栏按 数学 / 逻辑 / 文本 / 日期 / 聚合 列出全部函数，带搜索框（输入 `TEXT` 只剩 TEXT）；点「TEXT」，右栏显示签名 `TEXT(值, 格式)`、一句话说明、参数表（「值」「格式」各一条）、返回值，以及**使用示例**（`TEXT($'单价', '0.00')` → 结果 `2.50`；`TEXT($'下单日期', 'YYYY年MM月DD日')` → `2026年09月11日`），示例区末尾有「字段只是示意、实际从字段栏点选」的提示；点「SUM」能看到示例 `SUM($'明细.金额')` → `17.5`；关掉帮助弹窗，公式内容不变 | |

测完 F-14 把 A、B 两个临时字段删掉（或清公式），避免影响后面。

## 6. 不要测 / 见到就算失败

不要测：

- 调色板里找「公式」控件——公式不是控件，是六类字段的配置。
- MAPX 等高级函数、跨表聚合（公式直接引用「选择数据 / 关联数据」带进的源表列）、仪表盘——本期不做。
- 时间选择 `time` 配公式后的细粒度格式（`HH:mm` 与 `HH:mm:ss` 由字段自身格式决定，专项不展开）。
- 多行文本 `textarea` 配公式的独立用例——与单行文本同路径，冒烟覆盖单行即可。

见到就算失败：

- 填写页或编辑弹窗里能手动改公式字段的值。
- 列表里公式列能内联编辑。
- 保存后列表里的公式值和填写页看到的不一致。
- 配了公式的字段还显示必填红星，或必填拦截提交。
- 引用字段变化后公式值不变（等也没有）。
- 编辑器输入框里、属性面板摘要里出现 `$'bb48af63-…'` 这种字段 id，而不是字段标题（重名字段的后一个会带 `(2)`，这是正常的）。
