# 流程超时手工测试

日期：2026-09-11  
测【流程设计】开始节点上的「开启流程超时」。这是整张流程的截止时间，不是某个审批节点的办理时限。

开始前：先执行 `server/sql/2026-09-11-workflow-process-timeout.sql`（已有库补 `dueAt` 列）。新环境若已跑过 `2026-09-09-schema-bootstrap.sql` 且该文件已含 `dueAt`，不必再跑本脚本。请假单按流程专项搭好并启用。

## 测试用表结构

沿用请假单：请假类型、事由、开始日期、结束日期。流程：开始 → 分支（事假 / 其他情况）→ 部门审批 / 人事备案 → 结束。

| 编号 | 步骤 | 期望 |
|---|---|---|
| T-01 | 点开始节点，看「开启流程超时」 | 默认关着。关掉时看不到时长或截止时间。不配也能【保存并启用】 |
| T-02 | 打开开关，选「有效时长」，填 2、单位选「分钟」，【保存并启用】。马上交一张事假 | 【我的待办】卡片和抽屉【流程】页签写「请于 xxx 前完成」，时间大约是提交后 2 分钟 |
| T-03 | 等过 2 分钟，不要点同意，刷新【我的待办】或再打开抽屉 | 单据变成已驳回，待办消失。进度里能看出系统自动驳回。发起人在【我发起的】能再交（开始节点允许终止后再交时） |
| T-04 | 【添加新版本】改成「指定截止时间」，选一个已经过去的年月日时分秒，启用后交一张 | 打开待办或等下一分钟扫库后，立刻变成已驳回 |
| T-05 | 再改成一个明天的截止时间，启用后交一张 | 卡片写明天的截止时间；没到点不能自动驳回；审批人仍可【同意】 |
| T-06 | 打开开关但不填截止时间，点【保存并启用】 | 顶部提示「开始节点已开启流程超时，请填写截止时间（年月日时分秒）」，这一版仍是设计中 |
| T-07 | T-03 那张被超时驳回的单，发起人改完再【提交】 | 新的截止时间按这次提交重算，不是沿用上一轮 |
| T-08 | 审批中退回至发起人，发起人再交 | 截止时间还是第一轮提交算出来的那个，不要往后推 |
| T-09 | 时长设 1 分钟，交一张事假。卡在刚好到期时点【同意】（或让同事同时打开这张待办触发超时） | 不能出现「同意成功」但单据其实已驳回。要么同意生效、流程往下走；要么提示「流程已超时」，待办消失、单据已驳回。刷新后【我的待办】和数据管理的流程状态要一致，不要一个还在审批中、一个已驳回 |
| T-10 | 时长设 1 分钟。先把部门经理角色下的人全部停用，再交一张事假，单据进异常。等过截止时间后，发起人在【我发起的】打开这张单点【重试】（或等下一分钟扫库后再打开） | 提示「流程已超时」或打开时已经是已驳回。不能重新派出待办，更不能再批到通过。进度里能看出系统自动驳回。测完把部门经理重新启用 |
| T-11 | 同 T-10 再造一张异常单并等到过截止时间。不要点【重试】，改事由后点【提交】或【保存草稿】（【我发起的】和【数据管理】都试） | 提示「流程已超时」或打开时已经是已驳回。事由还是超时前的内容，单据不能重新变成审批中。开始节点允许终止后再交时，要等它先变成已驳回，再按 T-07 另交一轮 |
| T-12 | 时长设 1 分钟，交一张事假。还没人点同意，等过截止时间后发起人立刻点【撤回】 | 提示「流程已超时」，单据已驳回，不能退回草稿。刷新后【我发起的】不是草稿，也不能靠撤回再交躲过这次超时 |
