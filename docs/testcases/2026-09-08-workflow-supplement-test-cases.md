配套：先按 `2026-09-06-workflow-form-test-cases.md` 的「测试用表结构」搭好【人事】【请假单】并启用流程；本文件编号都是 B-，只写专项之外的部分。

## 测试用表结构（补充）

组织准备在主专项之外再加：

- **王五**：启用用户，不必能进【人事】（转交、加签、抄送的对象）
- **员工 B**：不挂任何部门（测「发起人没有部门」；测完不用恢复）

【人事】【请假单】补充字段（表单设计里加，保存后按用例提示在节点权限里用）：

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 报销单号 | 单行文本 `input` | 勾「唯一」 |
| 紧急程度 | 下拉单选框 `select` | 选项：普通 / 加急；必填 |
| 登录人 | 登录人姓名 `currentUser` | 只读控件，不用配 |

再建一个应用和一张流程表，测跨应用隔离和表单人员字段审批人：

- 应用【行政】，表【采购申请】（新建时选**流程表单**）：

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 采购内容 | 单行文本 `input` | 必填 |
| 对接人 | 人员单选 `member` | 选填 |

- 采购申请流程 V1：开始 → 审批「采购审批」（审批人：指定人员**张三**）→ 结束，【保存并启用】。
- 用【使用范围】给张三加上【行政】的使用权（他要能进这个应用看应用内入口）。

用例要改节点配置时，一律按版本管理来：顶栏版本下拉里【添加新版本】复制当前版 → 改配置 → 【保存并启用】。

## 1. 入口与列表

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-01 | 张三提一张采购申请（走 V1，王五审批），再让【人事】里有一张派给张三的待办；张三打开首页【我的待办】 | 两张卡片都有；首页卡片带应用名（如「人事 / 请假单」「行政 / 采购申请」） |
| B-01b | 张三进【行政】左侧【我的待办】 | 只有采购申请，没有请假单 |
| B-01c | 张三进【人事】左侧【我的待办】 | 只有请假单，没有采购申请 |
| B-01d | 张三在两个应用里分别看【我发起的】【我处理的】【抄送我的】 | 同样只显示本应用的单，别的应用的不出现 |
| B-01e | 看数字：首页【我的待办】的未处理条数、应用内【我的待办】的条数 | 首页是所有应用合计；应用内只算本应用 |
| B-01f | 用一个没有任何待办的账号，分别打开首页和应用内的【我的待办】 | 首页空状态写「还没有待办」；应用内写「本应用还没有待办」这类，让人知道范围不同 |
| B-02 | 打开【请假单】【数据管理】 | 列表多一列**流程状态**，各行显示草稿 / 审批中 / 已通过 / 已驳回 / 异常，没有空值 |
| B-02b | 列表上方的「流程状态」下拉里分别选草稿、审批中、已通过、已驳回、异常 | 每次只剩对应状态的行；选「全部」恢复 |
| B-02c | 打开【加班单】【数据管理】 | 没有流程状态列，也没有这个下拉（要在专项 W-03 把加班单转流程**之前**看这条） |
| B-02d | 加班单转流程（专项 W-03/W-04）后，原填报人打开首页【我发起的】 | 转换回填的那些已通过旧行**不出现**（它们没有流程实例） |

## 2. 审批人来源

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-03 | 采购申请【添加新版本】得 V2：采购审批审批人改成只勾**「表单人员字段」**选「对接人」，取消指定人员，【保存并启用】。提交一张对接人填**张三**的采购申请 | 张三【我的待办】有这张 |
| B-03b | 再提交一张**对接人留空**的采购申请 | 进异常，文案写「节点「采购审批」没有可用的审批人」；发起人【我发起的】能【撤回】。不再测重试（专项 E 组已覆盖） |
| B-04 | 采购申请 V3：审批人同时勾「表单人员字段：对接人」和「指定人员：张三」，【保存并启用】。提交对接人填**张三**的单 | 张三只有**一条**待办（两处来源命中同一人只派一条） |
| B-04b | 提交对接人填**王五**的单 | 张三、王五各一条 |
| B-04c | 提交对接人留空的单 | 只有张三一条，不进异常（还有别的来源能派到人） |
| B-05 | 请假单【添加新版本】：部门审批**取消勾**「限定与发起人同部门」，【保存并启用】。员工 A 提交事假 | 研发的经理甲、乙**和销售的经理丙**都收到待办。测完：再添加新版本勾回去并启用（在途单不受影响） |
| B-06 | 版本勾着「限定与发起人同部门」时，员工 B（不挂任何部门）提交事假 | 部门审批派给全公司有「部门经理」角色的人（甲、乙、丙都收到）；打开【流程】页签，进度里有一条「发起人没有所属部门，本节点按角色全公司派发」，单据不进异常 |

## 3. 审批写回

以下用例里人事备案都是会签（张三、李四），「事由」在该节点标了可编辑（主专项 D-04 的配置）。

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-07 | 一张事假走到人事备案：张三把事由改成「张三版」点【通过】；李四再把事由改成「李四版」点【通过】 | 整单已通过后，【数据管理】里事由是**李四版**（后提交的覆盖先提交的），不是张三版 |
| B-08 | 另一张事假走到人事备案：张三把事由改几个字后点【驳回】，写上意见 | 驳回成功后，【数据管理】里事由仍是**改之前的值**——驳回不落库他改的字段；意见在进度里 |
| B-09 | 另一张事假走到人事备案：张三把事由清空点【通过】 | 被拦，提示哪个必填字段没填；流程不停在已通过也不往下走 |
| B-10 | 先让一张单报销单号填 R1 走完整单。另一张走到人事备案（人事备案节点把「报销单号」也标成可编辑），张三把报销单号改成 R1 点【通过】 | 提示重复，【通过】失败；改成没被占用的 R2 后【通过】成功。整单的流水号从头到尾不变 |

## 4. 转交、退回的进度与限制

预备：人事备案是**会签**并勾了「允许转交」「允许加签」（专项 §9 的版本）。用事假单走到人事备案。

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-11 | 张三、李四都有待办时，张三点【退回至上一审批节点】填意见确定 | 李四那条待办从【我的待办】消失，打开【流程】页签能看到它标「未处理（已取消）」和取消原因；单据仍是审批中，不是已驳回 |
| B-12 | 接着 B-11：甲在部门审批点【同意】→ 张三再点【退回至发起人】→ 发起人在【我的待办】点【提交】。打开【流程】页签看时间线 | 能按时间看到「退回至上一审批节点」「退回至发起人」「已重新提交」各一条，带操作人和意见；单据全程审批中 |
| B-12b | 用专项 A-07 / A-08 转交、加签过的单再看【流程】页签 | 转交那条显示「转交」；加签后王五的待办以「待处理」出现在进度里 |
| B-13 | 张三打开待办点【转交】，选人框里选**自己**确定 | 提示「不能转交给自己」，不产生新待办 |
| B-13b | 点【转交】或【加签】打开选人框 | 右侧名单里**看不到停用账号**，选不了停用的人 |

## 5. 抄送的时机

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-14 | 请假单添加新版本：从**开始**拉一条线到抄送（指定人员王五），【保存并启用】。提交一张事假 | 王五【抄送我的】马上多一张，不用等任何审批节点 |
| B-14b | 这张被经理【驳回】后，发起人改完点【再次提交】 | 王五又多一张（每一轮提交各发一张，两轮两张） |
| B-14c | 另一张提交后，发起人马上【撤回】成草稿 | 王五的抄送数量不变（撤回不补发也不撤回已发的） |
| B-15 | 从分支「按请假类型」也拉一条线到抄送（指定王五），【保存并启用】。提交一张事假 | 走到分支、选好事假那条线时王五就收到，部门审批还没通过也收到了；分支到抄送的线上没有条件可配，也不占「恰好一条其他情况」的名额 |
| B-16 | 造一张进异常的单（部门经理角色下暂时没有启用用户，见专项 E-01），期间开始上挂着抄送给王五：提交 → 王五收到一张 → 发起人点【重试】 | 抄送**不再多**一张（重试只重派卡住的审批，不重发抄送）；审批人改过可编辑字段后，王五再打开这条进行中的单，看到的是最新数据 |

## 6. 版本与设计器

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-17 | 流程设计里拖动一下节点（不保存），点版本下拉想切到另一版 | 弹「当前版本有未保存的修改，切换将丢失。确定切换吗？」；点取消留在当前版，改动还在 |
| B-17b | 画布仍有未保存修改时，打开【管理已有版本】对一份设计中的版本点【编辑】 | 同样先弹上面的确认 |
| B-17c | 画布有改动没保存，在管理弹窗里点【启用流程】 | 提示「请先保存」，不启用、不校验画布上没保存的内容 |
| B-18 | 采购申请添加新版本：拖一个分支，条件线配「采购内容 包含 xx」能保存；回表单设计**删掉**「采购内容」字段；再回流程设计启用这一版 | 启用被拦，提示「分支…的连线用了已删除的字段」。测完把字段加回、把这一版删掉 |
| B-19 | 请假单有流水号生成 `serialNumber`（单号）和登录人姓名 `currentUser`（登录人）：流程设计点人事备案看字段权限 | 这两项只有「只读 / 隐藏」，**没有「可编辑」**；「登录人」勾简报后卡片摘要显示姓名，不是账号 |

## 7. 可选（要额外预备）

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-20 | 预备：手工执行 `UPDATE workflow_version SET enabled = 0 WHERE formId = <请假单的表 id>;`（模拟旧表「曾经启用过、后来停用」的遗留，界面上关不掉）。打开【添加数据】 | 底部回到【保存】（没有【保存草稿】【提交】）；保存后【数据管理】状态列是「已通过」，详情里写「流程停用期间保存，没有审批记录」，没有空的流程图；别的表选记录弹窗能挑到它；在途单照常审批。测完把 `enabled` 改回 1 |
| B-21 | 不走前端：填好除必填「事由」外的字段，用接口工具（或浏览器开发者工具构造请求）直接调工作台提交接口 `POST /api/apps/:appId/forms/:formId/records`，body 带 `intent: 'submit'` | 服务端返回「事由」没填的提示，不产生一条审批中的半截单；首页「我发起的」也没有 |

## 不要测

- 首页【我的待办】再按应用筛选（本期首页保持全站，不加筛选项）
- 数据管理流程状态列在「列设置」里开关（本期这列固定出现，不受列设置控制）
- B-20 之外的停用遗留场景（界面上没有【停用】入口）
- 加签的独立进度文案（加签只体现为被加签人的待处理记录）
