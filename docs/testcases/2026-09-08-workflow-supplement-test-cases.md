## 测试用表结构（补充）

组织准备在主专项之外再加：

- **王五**：启用用户，不必能进【人事】（转交、加签、抄送的对象）
- **员工 B**：不挂任何部门（测「发起人没有部门」；测完不用恢复）

【人事】【请假单】补充字段（表单设计里加，保存后按用例提示在节点权限里用）：

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 报销单号 | 单行文本 `input` | 勾「唯一」 |
| 紧急程度 | 下拉单选框 `select` | 选项：普通 / 加急；必填 |
| 登录人 | 登录人姓名 `currentUser` | 只读控件，不用配 |

再建一个应用和一张流程表，测跨应用隔离和表单人员字段审批人：

- 应用【行政】，表【采购申请】（新建时选**流程表单**）：

| 字段标题 | 调色板控件 | 配置 |
|---|---|---|
| 采购内容 | 单行文本 `input` | 必填 |
| 对接人 | 人员单选 `member` | 选填 |

- 采购申请流程 V1：开始 → 审批「采购审批」（审批人：指定人员**张三**）→ 结束，【保存并启用】。
- 用【使用范围】给张三加上【行政】的使用权（他要能进这个应用看应用内入口）。

用例要改节点配置时，一律按版本管理来：顶栏版本下拉里【添加新版本】复制当前版 → 改配置 → 【保存并启用】。

## 3. 审批写回

以下用例里人事备案都是会签（张三、李四），「事由」在该节点标了可编辑（主专项 D-04 的配置）。

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-07 | 一张事假走到人事备案：张三把事由改成「张三版」点【同意】；李四再把事由改成「李四版」点【同意】 | 整单已通过后，【数据管理】里事由是**李四版**（后提交的覆盖先提交的），不是张三版 |
| B-08 | 另一张事假走到人事备案：张三把事由改几个字后点【驳回】，写上意见 | 驳回成功后，【数据管理】里事由仍是**改之前的值**——驳回不落库他改的字段；意见在进度里 |
| B-09 | 另一张事假走到人事备案：张三把事由清空点【同意】 | 界面直接拦下（不发请求）：提示哪个必填字段没填，表单自动跳到那个字段；张三的待办**还在**【我的待办】里，单据状态不变——补上事由再点【同意】就能正常走 |
| B-10 | 先让一张单报销单号填 R1 走完整单。另一张走到人事备案（人事备案节点把「报销单号」也标成可编辑），张三把报销单号改成 R1 点【同意】 | 提示重复，【同意】失败；改成没被占用的 R2 后【同意】成功。整单的流水号从头到尾不变 |

## 4. 转交、退回的进度与限制

预备：人事备案是**会签**并勾了「允许转交」「允许加签」（专项 §9 的版本）。用事假单走到人事备案。

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-11 | 张三、李四都有待办时，张三点【退回至上一审批节点】填意见确定 | 李四那条待办从【我的待办】消失，打开【流程】页签能看到它标「未处理（已取消）」和取消原因；单据仍是审批中，不是已驳回 |
| B-12 | 接着 B-11：甲在部门审批点【同意】→ 张三再点【退回至发起人】→ 发起人在【我的待办】点【提交】。打开【流程】页签看时间线 | 能按时间看到「退回至上一审批节点」「退回至发起人」「已重新提交」各一条，带操作人和意见；单据全程审批中 |
| B-12b | 用专项 A-07 / A-08 转交、加签过的单再看【流程】页签 | 转交那条显示「转交」；加签后王五的待办以「待处理」出现在进度里 |
| B-13 | 张三打开待办点【转交】，选人框里选**自己**确定 | 提示「不能转交给自己」，不产生新待办 |
| B-13b | 点【转交】或【加签】打开选人框 | 右侧名单里**看不到停用账号**，选不了停用的人 |
| B-22 | 张三已点过【通过】、李四还有待办：李四点【转交】，选人框里选**张三**确定 | 提示「该用户已在本节点处理过，不能转交」，不产生新待办；李四自己的待办还在，单据不受影响 |
| B-23 | 同样场景李四点【加签】，选**张三**确定 | 提示「所选人员已在本节点处理过，不能加签」；选一个还没批过的人（如王五）则照常加签成功 |

## 5. 抄送的时机

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-14 | 请假单添加新版本：从**开始**拉一条线到抄送（指定人员王五），【保存并启用】。提交一张事假 | 王五【抄送我的】马上多一张，不用等任何审批节点 |
| B-14b | 这张被经理【驳回】后，发起人改完点【再次提交】 | 王五又多一张（每一轮提交各发一张，两轮两张） |
| B-14c | 另一张提交后，发起人马上【撤回】成草稿 | 王五的抄送数量不变（撤回不补发也不撤回已发的） |
| B-15 | 请假单再【添加新版本】：从分支「按请假类型」也拉一条线到抄送（指定王五），【保存并启用】。提交一张事假 | 走到分支、选好事假那条线时王五就收到，部门审批还没通过也收到了；分支到抄送的线上仍会出现条件配置，但配不配都不影响抄送发出，也不占「恰好一条其他情况」的名额 |
| B-16 | 造一张进异常的单（部门经理角色下暂时没有启用用户，见专项 E-01），期间开始上挂着抄送给王五：提交 → 王五收到一张 → 发起人点【重试】 | 抄送**不再多**一张（重试只重派卡住的审批，不重发抄送）；审批人改过可编辑字段后，王五再打开这条进行中的单，看到的是最新数据 |

## 6. 版本与设计器

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-17 | 流程设计里拖动一下节点（不保存），点版本下拉想切到另一版 | 弹「当前版本有未保存的修改，切换将丢失。确定切换吗？」；点取消留在当前版，改动还在 |
| B-17b | 画布仍有未保存修改时，打开【管理已有版本】对一份设计中的版本点【编辑】 | 同样先弹上面的确认 |
| B-17c | 画布有改动没保存，在管理弹窗里点【启用流程】 | 提示「请先保存」，不启用、不校验画布上没保存的内容 |
| B-18 | 采购申请添加新版本：拖一个分支，选中分支线点【添加过滤条件】，弹框里配「采购内容 包含 xx」后确定，能保存；回表单设计**删掉**「采购内容」字段；再回流程设计启用这一版 | 启用被拦，提示「分支…的连线用了已删除的字段」。测完把字段加回、把这一版删掉 |
| B-19 | 请假单有流水号生成 `serialNumber`（单号）和登录人姓名 `currentUser`（登录人）：流程设计点人事备案看字段权限 | 这两项只有「只读 / 隐藏」，**没有「可编辑」**；「登录人」勾简报后卡片摘要显示姓名，不是账号 |
| B-22 | 采购申请【添加新版本】：开始节点把「对接人」设**不可见**，【保存并启用】。提交一张（对接人在填报里就没有） | 填报里看不到对接人；张三打开待办也没有；【数据管理】列表和详情都看不到对接人。用接口工具直调提交接口带上对接人的值，库里也不写对接人（测完删这一版） |
| B-23 | 接着 B-22 再【添加新版本】：开始节点把「采购内容」设**只读**，「采购审批」节点把「采购内容」设**可编辑**，【保存并启用】。提交一张（发起人填不了采购内容；开始节点只读的字段不拦必填，空着也能提交），张三在待办里填上采购内容点【同意】走完整单；发起人从【数据管理】点【编辑】 | 编辑抽屉里采购内容是张三填的值但改不了；改「对接人」点【提交】重新走审批，再通过后【数据管理】里对接人是新值，**采购内容仍是张三填的原值**（测完删这一版） |

## 7. 可选（要额外预备）

## 8. 评审修复回归（2026-09-08）

以下用例对应 `docs/reviews/2026-09-08-workflow-form-code-review.md` 修复的问题，都是回归用例：修过的行为不要改坏。

| 编号 | 步骤 | 期望 |
|---|---|---|
| B-24 | 请假单【添加新版本】：表单里加一张子表单 `subform`（明细），内含必填子列「设备名」（单行文本 `input`）；流程设计里开始节点把「设备名」设为**不可见**（或整张明细设为不可见），【保存并启用】。提交一张明细不填的单 | 能正常提交，不再报「[明细.设备名]不能为空」这类看不见的字段的错；把「设备名」改回可见后，空着不填会被拦。测完删掉这一版 |
| B-25 | 请假单启用着 V1 时，用户先【添加数据】存一张**草稿**不提交；配置者【添加新版本】V2（在部门审批后面加一个「总监审批」）并【保存并启用】；用户再打开那张旧草稿点【提交】 | 流程按 **V2** 走：总监审批收到待办，【流程】页签能看到这个节点；和 V2 启用后新建提交的单走法一致，不是按存草稿那天的 V1 跑 |
| B-26 | 流程设计画布：点选一个审批节点按 Backspace 或 Delete | 节点删掉；点**开始节点**按 Backspace 提示「开始节点不能删除」，节点还在；Ctrl+Z 能把删掉的节点撤回来，Ctrl+Shift+Z 或 Ctrl+Y 再重做；选中一条连线按 Delete 只删这条线 |
| B-27 | 画布连线限制：从审批节点拖一条线连回【开始】；再把一个节点拖线连**自己**；拖一条从【结束】连出去的线被拦下后按 Ctrl+Z | 连回开始提示「不能连回开始节点」、连线消失；连自己提示「节点不能连接自己」；撤销后**被拦的那条线不会回来**，之前画好的合法连线也不丢。选节点按 Ctrl+C / Ctrl+V 没有反应（画布复制粘贴已不支持） |
| B-28 | 流程设计点**开始节点**看字段权限，找子表单 `subform`、登录人姓名 `currentUser`、所在部门 `currentUserDept`、流水号 `serialNumber` 这几行 | 开始节点上有「可编辑 / 只读 / 隐藏」三档可选（默认可编辑），不是空着没选中项；换到审批节点看，这几行仍然只有「只读 / 隐藏」两档（和 B-19 一致） |
| B-29 | 故意启用一份过不了的版本（如 B-18 里删了字段的那版），点【保存并启用】 | 红色错误区**逐条列出**每个问题（每条一行中文），不是空白，也不是「Request failed with status code 400」这类英文报错 |
| B-30 | 角标同步：发起人在【数据管理】详情里把一张被驳回的单改完点【提交】；再到工作台【我的待办】里处理一张（同意或驳回） | 两个动作之后，顶栏【我的待办】角标数字**立刻**跟着变，不用刷新页面；工作台左侧【我的待办】计数同样跟着变 |
| B-31 | 造一条僵尸待办：找一张正停在审批节点的单（如张三的事假停在部门审批），在数据库执行 `INSERT INTO workflow_task (instance_id, node_key, round, assignee_id, status) SELECT instance_id, node_key, round + 100, assignee_id, 'pending' FROM workflow_task WHERE id = <这条真实待办的 id>;`。刷新【我的待办】列表和顶栏角标 | 列表里**不会**多出这条复制的假待办（轮次对不上，判定为僵尸待办被过滤），角标数字也不含它；真实待办照常显示和处理。测完执行 `DELETE FROM workflow_task WHERE instance_id = <这张单的实例 id> AND round > <实例当前轮次>;` 清掉造数数据 |
