# 子表单 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 在 `master` 上改，不开分支。未经使用者要求不 commit。

**Goal:** 做成主表「子表单」：可设计子字段、填多行、入库校验，支持图片/文件/选择数据，以及行内联动和整表联动。

**Architecture:** 子表存在主表记录 `data[subformKey]` 的对象数组里。纯逻辑放 `subformField.js`。填报表格 `FormSubform.vue`，画布用同一套表头预览。行内联动复用 `linkageRuntime.js`，条件值 = 主表 values + 当前行。整表联动查到 1 条主表记录后，按 `fieldMappings` 把它的子表数组覆盖到当前子表。

**Tech Stack:** Vue 3、Element Plus、现有 `queryFormRecordsApi`、前端 `node:test`、后端 Jest。

**Spec:** `docs/superpowers/specs/2026-08-30-subform-design.md`

## Global Constraints

- 开发在 `master`，不开分支、不建 worktree。
- 按 Task 1→9 顺序做，前一步能用再做下一步。

- 图标必须从 `@element-plus/icons-vue` 确认导出后再 import。子表已用 `Tickets`。
- 不删不改使用者已有注释和 `console.log`。
- 不勾 `front/README.md`。

- 不把子表做成独立 Mongo 集合。
- `hasLinkage(field)` 只认主表那种 `sourceKey`。整表联动用单独的 `hasSubformLinkage(field)`（看 `sourceSubformKey` + `fieldMappings`），不要把两种混在一个函数里误判。

    { key: 'qty', type: 'number' },

    mappings: [{ sourceKey: 'a', targetKey: 'name' }],
    targetFields: [{ key: 'name', type: 'input' }],

  assert.deepEqual(rows, [{ name: '螺丝' }])
