# 表单字段公式设计

日期：2026-09-11
状态：已确认（参考简道云公式功能：帮助中心《公式》hc.jiandaoyun.com/doc/9031、9032、22048）
范围：给已有字段配置「计算公式」，填写和修改数据时字段值按公式自动算出、只读不可手改，结果随记录入库并在数据管理列表展示。支持子表单行内公式和主表对子表字段的聚合求和。不包含新控件：公式不是调色板里的新组件，而是单行文本 `input`、多行文本 `textarea`、数字 `number`、日期选择 `date`、时间选择 `time`、日期时间 `datetime` 这六类字段的一种配置。

对照：数据联动是「从别的表按条件取一条数据写进当前字段」，公式是「本表单字段之间按表达式实时算」。流水号是「新增时后端生成一个编号，之后不变」，公式字段是「每次保存都按最新数据重算」。公式与数据联动可以叠加：联动把值写进来，公式拿它继续算。

## 1. 需求核对（原描述 → 判定 → 本期怎么定）

| 原描述 | 判定 | 本期怎么定 |
|---|---|---|
| 参考简道云为字段添加公式编辑选项 | 清楚 | 属性面板新增「计算公式」配置行 + 「编辑公式」按钮打开弹窗 |
| 公式编辑器要能引用字段、插函数 | 清楚 | 弹窗左侧函数列表（按类分组、点击插入）+ 字段列表（主表字段和子表字段分开展示），中部多行输入框，底部实时报错并定位行列 |
| 函数做多大范围 | 已确认 | 精简起步集 22 个函数 + 四则/比较运算符，函数注册表可扩展，后续按需补 |
| 公式在哪里算 | 已确认 | 填写页前端实时算（所见即所得）+ 提交时服务端按同一公式重算覆盖（防篡改）。两端共用同一套测试用例（fixtures）保证结果一致 |
| 子表单行内公式 | 已确认 | 支持。行内字段可引用本行其他子表字段 + 主表字段；主表公式可用 SUM 等聚合函数对「子表单.字段」整列求值 |
| 配了公式的字段还能手填吗 | 清楚 | 不能。填写页只读（对齐流水号的展示方式），数据管理里也不可内联编辑 |
| 公式字段的值入库吗 | 清楚 | 入库。数据管理列表直接展示计算值；修改记录时按最新数据重算覆盖 |
| 引用字段变化时 | 清楚 | 填写页实时重算（对齐简道云「跟随引用字段变化」） |
| 必填、不允许重复值 | 已确认 | 公式字段不提供。属性面板隐藏这两个开关；保存时若字段上残留必填/重复值标记则后端 400 |
| 循环引用 | 清楚 | 设计器保存表单时检测并拒绝；编辑器保存按钮在自身校验不过时不可点 |
| 编辑时引用的字段被删了 | 清楚 | 保存表单时后端校验「字段不存在」直接 400；编辑器里保存前也能看到提示 |

本期不做：SUMIF/SUMIFS/COUNTIF 等条件聚合、MAPX 等跨表函数（跨表取值请用数据联动/选择数据）、RMBCAP 人民币大写、UUID/RECNO 等高级函数、仪表盘统计、公式嵌套层数上限（表达式本身限制 2000 字符）、移动端专项适配。

## 2. 和现有能力怎么区分

| 能力 | 干什么 | 库里存什么 |
|---|---|---|
| 数据联动 | 条件满足后从**他表**取值写入当前字段 | 当前字段自己的值 |
| 选择数据 / 关联数据 | 人选一条他表数据，按映射带值 | 源记录 id + 映射值 |
| 流水号生成 | 新增时后端生成编号，之后不变 | 一条字符串，创建后不变 |
| 公式 | 本表字段按表达式实时计算，保存时重算 | 按字段类型存计算结果，随每次保存刷新 |

## 3. 哪些字段能配公式

调色板中文名与 `type` 对照（与 `docs/testcases/README.md` 一致）：

| 调色板中文名 | type | 公式结果要求 |
|---|---|---|
| 单行文本 | `input` | 任意（自动转文本） |
| 多行文本 | `textarea` | 任意（自动转文本） |
| 数字 | `number` | 数字 |
| 日期选择 | `date` | 日期或毫秒时间戳（存为年月日） |
| 时间选择 | `time` | 日期或毫秒时间戳（存为时分秒） |
| 日期时间 | `datetime` | 日期或毫秒时间戳 |

子表单 `subform` 里同类型的子字段同样可配。下拉单选框 `select`、人员单选 `member`、流水号 `serialNumber`、选择数据 `data` 等其余控件不提供公式入口（对齐简道云只开放文本/数字/日期类的做法）。

公式字段自动关闭：必填、不允许重复值、单条数据内不允许重复值（设计器隐藏开关 + 编辑公式时清掉已勾选的标记 + 后端保存拦截）。

## 4. 属性面板与公式编辑器

属性面板：选中上述六类字段后，「字段说明」下方出现「计算公式」一行。没配时显示「未设置」；配置后显示公式摘要（超长截断）+「编辑公式」「清除」两个按钮。清除即删掉 `formula` 配置，恢复普通可填字段。

公式编辑器弹窗（可拖拽）里横向并排三栏：函数 | 字段 | 公式内容。

1. 「函数」栏（最左）是一个独立面板，有自己的标题栏、搜索框和滚动条。按 数学 / 逻辑 / 文本 / 日期 / 聚合 分组显示函数名，标题栏右侧写「悬停看说明」；鼠标停在函数上弹出它的一句话说明（限宽，好读）。搜索框只过滤函数名和说明，没命中显示「没有匹配的函数」。
2. 「字段」栏（中间）同样自带标题栏、搜索框和滚动条，标题栏右侧写「点一下就插进公式」。里面按分组列字段：主表公式显示主表字段（含标签页里的字段，只写标题）和各子表数字列（写成「子表单标题.字段标题」，如「物料清单.物料数量」）；子表行内公式显示本行字段（**同样**写成「子表单标题.字段标题」）+ 主表字段（只写标题）。当前字段自身不出现。字段上带类型文字（如「数字」）。搜索框只过滤字段标题，没命中显示「没有匹配的字段」；表单里本来就没有可引用字段时显示「暂无可引用字段」。点函数插入 `函数名()` 并把光标落在括号里（`TODAY()` 这类无参函数落在括号后），点字段把一颗标签插到光标处。
3. 「公式内容」（最右）是公式输入区，点哪里就在哪里打字。字段引用是**一颗不可拆的蓝色标签**（显示字段标题）。删标签由编辑器自己接管：光标在标签里、光标紧贴标签左边按退格、紧贴标签右边按 Delete、或选中范围碰到标签，都是**整颗删掉**——浏览器对 `contenteditable=false` 元素的原生行为两种毛病都有（有时毫无反应，有时只删掉标签上的字、引用却还留着，表现成「字段删不掉」）。函数名紫色、字符串绿色，其余按原文。打字时按光标前那个词弹候选：打 `$` 列出全部可引用字段，打字段标题或函数名列出匹配项，面板分「函数」和「当前表单字段」两段（字段带类型），↑↓ 移动、回车/Tab 或鼠标点选插入（手打过的同名函数/字段标题会被替换掉，不会拼成 `SUMUM()`），Esc 或点外面关掉；在字符串里打字不弹。复制粘贴用 Ctrl+C / Ctrl+X / Ctrl+V：复制出去的是按字段标题写的文本（`CONCATENATE($'商品名称')`），粘回来还是同一颗颗标签、同一个公式。输入区下面是状态行 + 「已引用字段」列表，右上角依次是公式长度（按存库的 `$'key'` 形态算，对齐 2000 上限）、「清空」、「原始内容」三个操作：「清空」清掉整个公式；「原始内容」在下方展开一块只读框，显示这份公式**存库时的原样**（字段写成 `$'字段key'`，和输入区里的标题写法对照着看），可以选中复制，按钮随即变成「收起原始内容」，公式为空时按钮不显示，弹窗关掉再打开是收起状态。每次输入实时校验：通过显示绿色「公式可以保存」；不通过显示红色错误（含第几行第几列）。校验不通过时「确定」按钮置灰。
4. 弹窗底部左边是「帮助文档」，点开一个独立帮助弹窗（可拖拽）：左栏按 数学 / 逻辑 / 文本 / 日期 / 聚合 列出全部函数，带搜索框；点某个函数，右栏显示它的详细文档——签名、一句话说明、注意事项、参数表（参数名取自签名，说明手写）、返回值，以及**使用示例**（每条示例都写清算出什么结果），末尾提示示例里的字段名只是示意、实际从字段栏点选。帮助内容跟着函数定义走（`front/src/components/form-design/formulaHelp.js`），`formulaHelp.spec.js` 会把每条示例真跑一遍，保证文档里写的示例和结果是对的。

**编辑器里显示的是字段标题，存下来的仍是字段 key**（`field.formula.expr` 里是 `$'字段key'`）。人在界面上只认标题、也不该背 key，所以输入框和属性面板摘要都按标题渲染，保存前再翻译回 key；手打的 `$'字段标题'` 也会认成标签。标题重名时后一个显示成「标题(2)」，翻译回各自的 key；标题里单双引号都有时没法写进 `$'…'`，那一个退回显示 key。

确定后把公式挂到字段上：`field.formula = { expr: 公式文本, refs: 引用的字段 key 列表 }`，同时清掉必填/重复值标记。

## 5. 公式怎么写

### 5.1 语法

- 字段引用写成 `$'字段标题'`（编辑器点字段自动插入，不用手打，也不用人去认 key）；引用子表字段是 `$'子表单标题.字段标题'`（如 `$'物料清单.物料数量'`），行内公式引用本行字段也写成这个带子表单标题的样子，界面上叫法统一。加引号才不会和减号混淆。编辑器下方会列出每个引用对应的字段标题，方便核对。存库时会被翻译回 `$'字段key'` / `$'子表key.子字段key'`（行内公式的本行字段存 `$'子字段key'`），字段改名不影响已存的公式。
- 字符串用单引号或双引号，如 `'未付款'`；数字直接写 `1.5`；真/假写 `TRUE` / `FALSE`（不分大小写）。
- 全部英文标点。运算符：`+ - * / %`、`== != > < >= <=`，括号改变优先级，函数参数用英文逗号分隔。
- 函数名不区分大小写（`IF` 与 `if` 等价），但引用字段名区分。

### 5.2 类型规则

- 数字字段公式必须返回数字；日期类字段返回日期或毫秒时间戳；文本字段收什么都可以（数字自动转文本，`1.5` 显示为 `1.5`）。
- 参与算术时：日期字符串和毫秒时间戳都按毫秒处理（对齐简道云）；`+` 两边只要有一边是文本就做拼接，其余做加法；文本想转数字用 `VALUE`。
- 比较结果为真/假，主要用于 `IF` 的条件。

### 5.3 函数清单（22 个）

| 分类 | 函数 | 说明 |
|---|---|---|
| 逻辑 | `IF(条件, 真值, 假值)` | 条件成立取真值，否则取假值；只计算用到的分支 |
| 逻辑 | `AND(…)`、`OR(…)`、`NOT(x)` | 与 / 或 / 非 |
| 文本 | `CONCATENATE(…)` | 把各参数连成一段文本，空值跳过 |
| 文本 | `LEFT(s,n)`、`RIGHT(s,n)`、`MID(s,start,n)` | 取左边 / 右边 / 中间 n 个字符；`start` 从 1 数 |
| 文本 | `LEN(s)` | 文本长度 |
| 文本 | `TEXT(x,格式)` | 日期按 `YYYY-MM-DD` 等格式转文本；数字按 `0.00` 这类写法保留小数位 |
| 文本 | `VALUE(s)` | 文本转数字，转不了返回空 |
| 文本 | `ISEMPTY(v)` | 空值（未填、空文本、空数组）为真 |
| 数学 | `SUM($'子表.数字列')` 或 `SUM(a,b,…)` | 求和；子表列按行求和，空值跳过 |
| 数学 | `AVERAGE(…)`、`MAX(…)`、`MIN(…)` | 平均 / 最大 / 最小，规则同 SUM；全空返回空 |
| 数学 | `ROUND(n,位数)` | 四舍五入到指定位数 |
| 数学 | `ABS(n)` | 绝对值 |
| 日期 | `TODAY()` | 今天 0 点（毫秒时间戳） |
| 日期 | `NOW()` | 当前时刻（毫秒时间戳） |
| 日期 | `DATEDIF(起,止,单位)` | 相差几年 / 几月 / 几天，单位 `Y`/`M`/`D`，不足整年整月舍去 |
| 日期 | `DATEDELTA(日期,天数)` | 日期加（正）/减（负）若干天，返回毫秒时间戳 |

聚合函数（SUM/AVERAGE/MAX/MIN）在主表公式里对 `子表key.子字段key` 整列求值；行内公式不需要也不支持聚合整列。除以 0、类型转不了、引用为空导致的算不出来：字段显示为空，不拦提交。

## 6. 填写时怎么算

- 配了公式的字段在填写页、修改数据弹窗里都是只读，样式对齐流水号（置灰输入框），标题旁带「按公式自动计算」提示图标。
- 打开填写页先按当前值算一遍；之后引用字段一变（含子表行内变化、增删行）立刻重算。
- 子表行内公式逐行计算：本行其他子字段 + 主表字段参与；主表聚合公式在子表行变化后重算。
- 求值出错（比如引用字段还没填）时该字段显示为空，不打断填写。
- 标签页 `tabs` 里的字段正常参与：没打开的页签里字段有值就算，和现有联动语义一致。

## 7. 保存与入库

| 动作 | 行为 |
|---|---|
| 新增保存 | 前端提交含计算值；服务端先丢掉客户端传的公式值，按公式重算覆盖，再做必填/唯一校验、生成流水号 |
| 修改保存 | 同样重算覆盖（区别于流水号只生成一次） |
| Excel 导入 | 模板可不含公式列；每一行导入后按该行数据重算 |
| 数据管理列表 | 公式字段是普通展示列（按字段类型格式化），不可内联编辑 |

服务端重算与前端同一套公式语义，两端共用 `formula.fixtures.json`（表达式 + 输入 + 期望输出）做契约测试，避免「填写时看到 3，提交后变 4」。求值失败（配置非法或引用缺失）字段留空并记日志，不拦提交——配置错误在保存表单 schema 时就被拦住了。

## 8. 保存表单时的校验（5 类，对齐简道云报错分类）

| 报错 | 提示示例 |
|---|---|
| 语法错误 | 公式语法错误：第 1 行第 9 个字符附近（附原因） |
| 字段不存在 | 公式引用了不存在的字段 `price2` |
| 函数不支持 | 公式不支持函数 SUMIF |
| 参数个数不符 | 函数 TEXT 参数个数不正确：用法 TEXT(值, 格式)，要 2 个参数，现在给了 1 个 |
| 参数类型不符 | 函数 ROUND 参数类型不正确 / 聚合函数参数请选择子表单数字字段 |

另有：循环引用（`a` 算 `b`、`b` 又算 `a`）→「公式存在循环引用」；公式字段带必填/重复值标记 →「公式字段不支持必填和不允许重复值」；不支持的控件类型配了公式 →「该字段不支持公式」。全部中文 400 提示，在保存表单设计时返回。

## 9. 数据形状

字段节点新增：`formula: { expr: "公式文本（引用形如 $'key'）", refs: ['引用的 key', '子表key.子字段key'] }`。`refs` 由保存时解析写入（按出现顺序去重），供排查和快速判断；运行时两端都以重新解析为准。公式配置存在 `app_form.fields` JSON 列里，不需要新建表、没有 SQL 脚本。

入库值按字段类型归一化：数字存数字；文本存文本；日期存 `YYYY-MM-DD`；时间存 `HH:mm:ss`；日期时间存 ISO 时间。这样公式结果和手填值在列表、详情、联动引用里长得一样。

## 10. 验收

1. 六类字段属性面板有「计算公式」入口，其他控件没有；配了公式后必填/重复值开关消失。
2. 编辑器：点函数/字段能插入；语法错、引用不存在的字段、参数个数不对时底部红字带行列定位，「确定」置灰。
3. 数字字段配 `单价*数量`（都在子表单里）：行内填单价数量，金额列实时出值；增删行后主表 `SUM` 求和跟着变。
4. 文本字段配 `CONCATENATE('订单-',流水号引用)` 之类拼接；日期字段配 `DATEDELTA(TODAY(),7)` 得到一周后。
5. 引用字段清空后公式字段显示为空，不拦提交。
6. 提交后数据管理列表展示计算值；修改引用字段再保存，计算值更新。
7. 绕过前端直接调接口提交篡改的公式值，入库值仍是服务端重算结果。
8. 把两个公式字段互相引用，保存表单被拦「公式存在循环引用」。
9. 公式字段在填写页只读；数据管理里不可内联编辑。
10. 导入一批数据后公式字段有值；流水号规则里引用公式字段时（field 段），号码里是重算后的值。
