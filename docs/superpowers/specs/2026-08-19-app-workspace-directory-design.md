# 应用内功能目录

日期：2026-08-19  
范围：从「我的应用」点进某个应用，左侧维护本应用的分组与表单目录。右侧主区域本期空着。

## 目标

登录用户点击自己的应用后，进入该应用的工作台：左侧树管理分组和表单（新建、改名、删除、按名称搜索）；点表单只高亮，不打开设计器。

## 本期不做

- 多层分组（分组里再套分组）
- 拖拽排序、移动表单到另一分组
- 表单字段、布局、设计器、填报
- 右侧主区域任何业务内容
- 应用改名/删除

## 布局

整页左右分栏，需登录；未登录走现有守卫到 `/login`。

**左栏（自上而下）**

1. 一行：左侧返回箭头，右侧应用名称。点箭头回到 `/`（「我的应用」）。
2. 下一行左右排布：搜索框（按名称过滤分组和表单）+ 加号。加号为下拉：新建表单、新建分组，都建在树的根上。
3. 再往下：分组和表单树。

**右栏**

空着。点表单不往这里渲染内容。

## 树与交互

- 分组一层：分组下只挂表单，不能再套分组。
- 表单可以不进分组，直接挂在根上。
- 顺序：根上先全部分组（`createdAt` 倒序），再未分组表单（`createdAt` 倒序）；分组内表单同样 `createdAt` 倒序。
- 点分组：只展开/收起。点表单：该节点高亮，右侧仍空。
- 行右侧下拉（三个点）：
  - 分组：新建（在该分组下建表单）、删除分组、修改分组名
  - 表单：删除、改表单名字
- 搜索：名称包含匹配，大小写不敏感，只过滤左栏已加载的树。
  - 表单命中：仍显示它所在分组（即使分组名不匹配）。
  - 分组命中：显示该分组及其下全部表单。
  - 无匹配：树区域空状态。
- 新建、改名用对话框，名称 trim 后 1–32 字，必填。
- 删表单、删空分组：二次确认。
- 分组内还有表单时不能删，不弹确认，提示「请先删除分组内的表单」。

## 进入与权限

- 「我的应用」点应用卡片进入 `/apps/:id`。
- 所有目录接口需 JWT，且 `application.ownerId` 为当前用户。
- 应用不存在或不属于当前用户：接口 `404`，`message` 为「应用不存在」；前端回 `/` 并展示该文案。

## 数据模型

TypeORM `synchronize` 仍为 `false`。建表须使用者同意后再执行 `CREATE TABLE`。

现有 `application` 表不改。

分组和表单都用 `id` 区分，名称允许重复。库上不对 `name` 做唯一约束，也不按名字查重。

### `app_group`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | int | 主键，自增 | 分组标识 |
| applicationId | int | 非空，索引 | 所属应用 |
| name | varchar(32) | 非空 | trim 后入库，可与其它分组同名 |
| createdAt | datetime | 非空 | TypeORM 自动 |
| updatedAt | datetime | 非空 | TypeORM 自动 |

### `app_form`

`groupId` 为空表示挂在根上。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | int | 主键，自增 | 表单标识 |
| applicationId | int | 非空，索引 | 所属应用 |
| groupId | int | 可空，索引 | 所属分组；空为根上 |
| name | varchar(32) | 非空 | trim 后入库，可与其它表单同名 |
| createdAt | datetime | 非空 | TypeORM 自动 |
| updatedAt | datetime | 非空 | TypeORM 自动 |

不建数据库外键。`groupId` 有值时，业务上必须属于同一 `applicationId` 的分组。

## HTTP 接口

统一响应仍为 `{ code, message, data }`，`code === 0` 成功。均需登录。

名称规则与现有应用名相同：trim，1–32 字。同名允许，不返回 `409`。

`groupId` 指向不存在、或属于其他应用的分组：`400`，`message` 为「分组不存在」。

### `GET /api/apps/:id`

成功 `200`，`data` 为 `{ id, name, icon }`。  
找不到或不属于自己：`404`，「应用不存在」。

### `GET /api/apps/:id/directory`

成功 `200`，`data` 为：

```json
{
  "groups": [
    {
      "id": 1,
      "name": "人事",
      "forms": [{ "id": 10, "name": "入职登记", "groupId": 1 }]
    }
  ],
  "forms": [{ "id": 11, "name": "未分组表单", "groupId": null }]
}
```

`groups` 为根上全部分组（含各自 `forms`）；`forms` 仅为未分组表单。排序同「树与交互」。

### 分组

- `POST /api/apps/:id/groups` 入参 `{ name }`，成功 `201`，`data` 为 `{ id, name }`
- `PATCH /api/apps/:id/groups/:groupId` 入参 `{ name }`，成功 `200`，`data` 为 `{ id, name }`
- `DELETE /api/apps/:id/groups/:groupId` 成功 `200`，`data` 为 `null`  
  组内还有表单：`400`，「请先删除分组内的表单」  
  分组不存在或不属于该应用：`404`，「分组不存在」

### 表单

- `POST /api/apps/:id/forms` 入参 `{ name, groupId? }`。不传或 `null` 建在根上。成功 `201`，`data` 为 `{ id, name, groupId }`（根上 `groupId` 为 `null`）
- `PATCH /api/apps/:id/forms/:formId` 入参 `{ name }`，成功 `200`，`data` 为 `{ id, name, groupId }`
- `DELETE /api/apps/:id/forms/:formId` 成功 `200`，`data` 为 `null`  
  表单不存在或不属于该应用：`404`，「表单不存在」

本期不改表单的 `groupId`（没有移动）。

## 前端

| 路由 | 页面 | 访问条件 |
|------|------|----------|
| `/apps/:id` | 应用工作台 | 未登录则重定向到 `/login` |

- 首页卡片可点击，进入对应 `/apps/:id`。
- 工作台用 Element Plus：`el-container` / `el-aside` / `el-main`、`el-tree`、`el-dropdown`、`el-dialog`、`el-input`。
- 左栏搜索为受控过滤，不调搜索接口。同名节点会一起出现。
- 新建/改名成功后更新左栏树，不整页刷新。
- 树节点、下拉操作、高亮都以 `id` 为准，不用名字当键。

## 后端模块

在现有 `application` 模块上扩展：应用详情、directory、分组与表单的 CRUD。  
新增 entity：`AppGroup`、`AppForm`。不新开一层「通用树」抽象。

## 测试

后端：

- 主人可取应用详情与 directory；非主人 / 不存在 → 404
- 根上建分组、建表单；带 `groupId` 建表单
- 同一应用内可建两个同名分组、两张同名表单
- 非法 `groupId` → 400
- 非空分组不可删 → 400；删空分组、删表单成功
- 改名成功

前端：手动走通 点应用进入 → 建分组/表单 → 搜索 → 改名 → 删除。本期不做前端 E2E。

## 成功标准

1. 点自己的应用进入工作台，左栏显示应用名，箭头能回到「我的应用」
2. 能在根上建分组和表单，能在分组下建表单，能改名、能删
3. 非空分组删不掉；搜索能按名称过滤分组和表单
4. 点表单仅左侧高亮，右侧仍为空
5. `app_group`、`app_form` 仅在使用者同意后创建
