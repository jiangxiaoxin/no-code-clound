# 人员单选 / 人员多选设计

日期：2026-08-31  
状态：待确认  
范围：主表字段 `type: 'member'`（人员单选）、`type: 'member-multiple'`（人员多选）的设计配置、弹框选人、填报入库、数据联动。不包含部门选择控件本身、按人员列筛选的复杂条件、跨应用、子表单内人员。

对照：组织数据用管理后台已有的部门、角色、人员（一人一部、一人多角色）。选人弹框对齐「选择数据」的 `el-dialog`（可拖拽）。取值来源对齐地址/图片：自定义手选，或数据联动写入。

## 1. 需求核对（原描述 → 补齐）

| 原描述 | 判定 | 本期怎么定 |
|---|---|---|
| 表单里展示被选人的名字；全部显示；每人一个清除 icon，点了直接去掉 | 清楚 | 控件上是人名标签，不是下拉摘要。点人名旁的清除只删该人，不打开弹框。点控件空白打开弹框 |
| 用系统自带的部门、角色、人员 | 清楚 | 读管理后台同一套表。填报不能走 `/admin/*`（那些接口要管理权限），另开登录即可用的组织查询接口 |
| 必填 / 禁用 / 可修改 | 清楚 | 与现有公共字段属性相同 |
| 点组件出弹框选人；可按部门、按角色、按人员清单选 | 清楚 | 运行时选人弹框的三种浏览方式，和下面「可选范围」不是同一件事 |
| 可选范围：全部 / 自定义 / 按部门字段 | 清楚 | 决定**谁能被选**。自定义是部门∪角色∪指定人；按部门字段以当前表单某个部门字段的值为根 |
| 取值来源：自定义选择 / 数据联动 | 清楚 | 决定**默认怎么带出人选**。自定义=运行时手选；数据联动=按条件从他表写入。没有「设计器里预选默认人」 |
| （未写）单选和多选是一个组件还是两个 | 缺口 | 两个字段类型，对齐下拉单选/下拉多选。调色板现有 `member` 改名为人员单选，新增 `member-multiple` 人员多选 |
| （未写）库里存什么 | 缺口 | 存用户 id。单选一个整数，多选整数数组。展示时按 id 查当前 `displayName`，改名后刷新即跟进 |
| （未写）停用、删除的人 | 缺口 | 弹框里不能新选停用/删除的人。已经选中的 id 仍显示：人还在库里就用现名，人不在了显示「已删除」 |
| （未写）部门选择控件还没做 | 缺口 | 「按部门字段」只认 `type === 'dept'` 的字段。本期不实现部门选择；没有可选字段时该选项仍在，下拉为空并提示先添加部门选择 |
| （未写）列表 / 导入 / 单元格 | 缺口 | 列表显示姓名；不可单元格内联编辑。导入继续跳过（`IMPORT_SKIP_TYPES` 已含 `member`，再加 `member-multiple`） |

本期不做：在设计器里预置默认选中的人、人数上限配置、按人员列筛选/排序（多选不建 `data.*` 索引）、选人时看手机号/工号等扩展资料、跨应用、子表单内人员、把「登录人姓名」和人员选择混成一个控件。

## 2. 和现有能力怎么区分

| 能力 | 干什么 | 库里存什么 |
|---|---|---|
| 登录人姓名 `currentUser` | 只读展示当前登录人 | 不入库 |
| 登录人部门 `currentUserDept` | 只读展示当前登录人部门 | 不入库 |
| 人员单选 / 多选 | 从组织里选人 | 用户 id / id 数组 |
| 部门选择 `dept`（未完成） | 从表单里选一个部门 | 部门 id（人员「按部门字段」会读它） |
| 下拉「系统字典」 | 固定选项 | 字典项 value |
| 数据联动 | 条件变化后自动写入 | 当前字段自己的值（这里是用户 id） |

人员选择用的是**平台组织**（管理后台那套人），不是某张表里的记录。

## 3. 字段配置

公共项：标题、占位、必填、宽度、tips、禁用、可修改。

人员专有（拖入时写入默认值）：

```json
{
  "type": "member",
  "memberScope": "all",
  "optionSource": "custom"
}
```

多选只是 `type` 换成 `member-multiple`，其余默认相同。

`memberScope` 只允许 `all`、`custom`、`dept_field`；缺省或非法按 `all`。

选 `custom` 后还要有：

```json
"memberScopeConfig": {
  "departmentIds": [1, 2],
  "roleIds": [3],
  "userIds": [10, 11]
}
```

三者并集为候选人。数组缺省当 `[]`。三个都空则运行时没有候选人（打开弹框是空的，并提示「没有可选择的人员」）。

选 `dept_field` 后还要有：

```json
"sourceDeptFieldKey": "dept1"
```

只允许指向当前表单（含标签页内部）`type === 'dept'` 的字段。保存字段设计时若该 key 已不存在或类型不对，当作未配置：运行时没有候选人。

属性面板（紧挨必填，不要用 `el-space`）：

1. 可选范围：全部 / 自定义 / 按部门字段  
2. 自定义时：设置按钮，点开弹框勾选部门、角色、人员（可拖拽）。已设置时文案为「已设置可选范围」，右侧清除要二次确认  
3. 按部门字段时：下拉当前表单的部门选择字段；没有可选字段时下拉为空，提示「请先添加部门选择字段」  
4. 取值来源：自定义 / 数据联动（`hasLinkageSource` 含 `member`、`member-multiple`）

画布：禁用的人名区占位（单选可显示占位文字，多选为空标签区），不打开选人弹框。已配联动时标题旁仍显示联动图标。

## 4. 值形状

人员单选：

```json
42
```

人员多选：

```json
[42, 7, 15]
```

规则：

- id 必须是正整数，对应用户表主键。
- 多选去重、保序（按选中先后；联动按收集顺序）。
- 空：单选不写该 key；多选空数组在提交时按现有 `serializeValue` 空值规则不写或 `clearEmpty` 时写 `null`。
- 后端 `coerce`：`member` 仍收单个整数（已有）；`member-multiple` 收整数数组。不要和 `dept` 继续共用「只收一个整数」而不加多选分支。
- 不把姓名写入 Mongo。列表、详情、填报回显都按 id 查 `displayName`。查询记录时把人员字段里的 id 并进现有 `loadUserNames`，随记录返回不够用的再让前端用组织查询补。为避免列表再打 N 次请求：查询/详情接口对人员字段额外带 `*Name` 不单独改 data 形状，而是扩展现有 names map，前端用 id 换成名字。

前端控件内部可以用 `{ id, name }[]` 做展示，提交前压回 id / id 数组。

## 5. 可选范围（候选人）

只统计 **启用中** 的用户（`status === 'active'`）。停用部门、停用角色不往池子里贡献新人，但不把「因部门停用」而仍启用的用户从「全部」里拿掉——「全部」按人的启停，不按部门启停。

| `memberScope` | 候选人 |
|---|---|
| `all` | 所有启用用户。未分配部门的人只出现在「人员」清单里，不出现在部门树节点下 |
| `custom` | 启用用户中，属于所选部门（含这些部门的下级部门）**或**拥有所选角色之一**或** id 落在 `userIds` 的，三者并集 |
| `dept_field` | 引用字段当前值为某个部门 id 时：该部门及其下级里的启用用户。引用字段为空、不是合法部门 id：候选人为空 |

一人一部，所以部门树下的人不会在两个节点重复出现。角色与部门交叉只发生在自定义并集里。

运行时改部门字段的值：按部门字段范围的人员控件要重算候选人；已选但不在新范围内的人**清掉**（单选清空；多选去掉不合格项）。禁用字段仍可被联动写入，但手选弹框打不开。

## 6. 运行时选人弹框

点控件（清除 icon 除外）打开 `el-dialog`，默认 `draggable`。标题：人员单选为「选择人员」，多选为「选择人员」。宽度约 720px。

弹框结构：

1. 顶部：按姓名 / 用户名搜索。失焦、回车或点清除时按当前关键词过滤一次，输入过程中不重算列表。
2. 搜索下方是已选区：展示当前弹框内已选的人（单选一人、多选多人），每人一个标签和删除图标，点删除只改弹框草稿、不关弹框。无人时显示「未选择人员」。点确定才写入控件。
3. 主体分栏（flex，不要为了「看起来整齐」上 grid）：
   - 左侧切换：**部门** / **角色** / **人员**。按部门字段时不提供「角色」（避免和根部门交叉放大范围），只留部门树（以引用部门为根）和人员清单（该子树内的人）。
   - 右侧：当前分类下的人员列表。
4. 底部：取消、确定。单选点一行只改弹框内选中态，不关闭；点确定才写入并关弹框。多选勾选后确定，可重复打开继续改。取消不改控件上的人选。

部门树用现有部门父子关系。点部门节点，右侧列出该节点及其下级的候选人（在当前 `memberScope` 内）。点角色，右侧列出拥有该角色且落在范围内的启用用户。人员清单是范围内的扁平列表。

禁用或（编辑已有记录且 `editable === false`）：不能打开弹框，不能点清除。联动仍可写入（对齐图片/地址）。

已选中但不在当前候选人里的人（例如后来被移出部门）：标签上仍显示，可清除；弹框里不再勾选他们。

## 7. 控件展示

- 所有已选人名都展示出来，flex 换行，不省略成「等 N 人」。
- 每个人名旁一个清除 icon，必须从 `@element-plus/icons-vue` 导入（用库里已有的 `Close`）。
- 点清除只去掉该人，`@click.stop`，不要打开弹框或打开记录详情。
- 未选时显示占位文字。
- 必填：一个有效 id 都没有则拦提交。

## 8. 组织查询接口

管理后台的 `/admin/users`、`/admin/departments`、`/admin/roles` 继续只给有对应管理权限的人用。填报选人新增一套**登录即可**的只读接口，只返回启用中的组织数据，不含密码、邮箱不是必出：

- `GET /api/org/departments`：启用部门树（id、name、parentId、children）
- `GET /api/org/roles`：启用角色（id、name、code）
- `GET /api/org/users`：启用用户（id、displayName、departmentId、roleIds），支持 `keyword`、`departmentId`（含下级）、`roleId`

前端选人弹框只打这些接口。不要在填报页复用管理端的增删改。

## 9. 数据联动

把 `member`、`member-multiple` 加入 `LINKAGE_VALUE_TYPES`。触发字段只列出源表同类型字段。`listFormFields` 的 `OPTION_FIELD_TYPES` 增加这两项。「其他表数据」树里不出现人员字段（`FormFieldSourcePicker` 排除）。

| 当前字段 | 0 条 / 0 人 | 1 人 | 多人 |
|---|---|---|---|
| 人员单选 | 清空，不提示 | 写入该 userId | 按**匹配记录条数**：多于 1 条则清空并提示 `[ 标题 ] 字段联动查询出多条数据`（有说明则带说明）。一条记录里只应有一个 id |
| 人员多选 | 清空为 `[]`，不提示 | 写入去重后的 id 数组 | 查询 `pageSize: 100`，按记录收集 id、按 id 去重保序后全部写入；不截取、不设人数上限 |

下拉那套「多条变选项」不适用于人员。联动写入的人若当时不在可选范围内：单选仍写入（联动优先于范围，和禁用字段可被联动写入一致）；多选同样写入。手选仍受范围限制。

## 10. 列表、导入、索引

- 数据管理列显示姓名（多个顿号或空格分隔，`title` 看全称）。不可单元格内联编辑。
- 导入跳过这两列。
- 人员单选沿用已有 `member` 可筛选/可建 `data.*` 索引。人员多选不筛选、不建该列索引。

## 11. 验收

1. 调色板能拖「人员单选」「人员多选」；属性有可选范围和取值来源。
2. 可选范围=全部：弹框能按部门树、角色、人员清单选到启用用户；停用用户不出现。
3. 可选范围=自定义：只出现并集内的人；三个名单都空时弹框提示没有可选人员。
4. 可选范围=按部门字段：改部门字段后，人员控件候选人跟着变，超出范围的已选被清掉。没有部门字段时不能配出有效引用。
5. 控件上所有人名都看得见，点清除去掉对应的人且不打开弹框。
6. 禁用：不能打开弹框、不能清除；允许下载类能力不适用于人。
7. 不可修改：新增能选；打开已有记录编辑时不能改人选。
8. 必填未选不能保存。
9. 改用户 `displayName` 后刷新列表/详情，人员列跟新名字。
10. 联动：源表人员字段能带出；单选匹配多条记录时清空并出现多条文案。
11. 没有管理后台权限的普通登录账号也能打开选人弹框（走 `/api/org/*`，不要 403）。

## 12. 实现时建议拆分

1. `/api/org/*` 只读接口和前端选人弹框（范围=全部）。
2. 控件展示、清除、必填/禁用/可修改、入库 coerce。
3. 自定义范围、按部门字段。
4. 数据联动与列表姓名回显。
