# 画布 JSON 解读辅助

日期：2026-09-01  
状态：已确认  
范围：在应用工作台和表单设计页提供只读辅助，把粘贴的画布 JSON 转成带字段名、表名注释的文本。不写回表单，不改画布，不进应用后台。

## 1. 背景与目标

画布配置里字段用 `key`、跨表引用用 `sourceFormId` 等，读原始 JSON 对不上中文名。需要一个当前应用内的解读工具：左边贴配置，点转换，右边得到同一份结构并在对应行末标出名称。

本期只做解读，方便对照配置。不追求性能，不缓存请求。

## 2. 出现位置

以下路由显示入口，其余页面不显示：

- `app-workspace`：`/apps/:id`
- `app-workspace-form`：`/apps/:id/forms/:formId`
- `form-design`：`/apps/:id/forms/:formId/design`

首页、登录、管理后台、应用后台 `/apps/:id/backend` 不出现。

所有登录用户都能看到。在 `App.vue` 用常量开关包一层：

```js
// 画布 JSON 解读辅助。改成 false 即隐藏左侧按钮和抽屉，不必改路由。
const SHOW_CANVAS_JSON_HELPER = true
```

## 3. 界面

- 视口左侧垂直居中一个半圆图标按钮，吸附窗口左缘，盖在侧栏之上。
- 点击后从左侧打开 `el-drawer`（抽屉不可拖拽）。
- 抽屉内三列：
  - 左：多行输入，空白，占位「粘贴表单画布 JSON」。打开时不预填。改字不触发转换。
  - 中：**转换** 按钮。
  - 右：可编辑文本域，展示带注释的结果，可全选复制。未成功转换前为空。

## 4. 转换

点击 **转换** 才执行，一次性完成：

1. 左栏去掉首尾空白后必须是合法 JSON（数组或对象均可，通常是画布 `fields`）。
2. 按当前路由的 `appId` 重新请求应用目录（表 id → 表名）和启用字典（编码 → 名称）。不缓存。
3. 从本次 JSON 收集出现过的 `sourceFormId`，对每一张源表重新请求完整字段。不缓存。
4. 按 §5 写出带行末注释的文本，写入右栏。

左栏改动不会自动更新右栏。

## 5. 注释规则

右栏是同一份 JSON，`JSON.stringify(..., null, 2)` 的缩进，只在对应行末追加 ` // 名称`。

### 5.1 要加注释的属性

**表**

- `sourceFormId`

**字段**

- `key`
- `sourceFieldKey`
- `sourceKey`
- `targetKey`
- `fieldKey`
- `displayFieldKeys` 等字段 key 数组里的每一项
- 过滤 / 联动条件里指向字段的 `key`

**字典**

- `dictCode`

不注释选项 value、与表/字段/字典无关的 id。

### 5.2 名称从哪来

按顺序查，先命中先用：

1. 本次 JSON 里同时带 `key` 和 `title` 的对象（当前画布字段、子表列、标签页内字段）。
2. 本次拉到的源表字段（跨表引用）。
3. 系统列：`createdBy` 创建人、`updatedBy` 更新人、`createdAt` 创建时间、`updatedAt` 更新时间。
4. 表：应用目录里的表 id → 表名；源表接口返回的表名作补充。
5. 字典：当前应用启用字典的 `code` → `name`。

查到则 `// 姓名` / `// 客户表`。查不到则该行仍加注释：`// 未查找到`。查不到名字**不算失败**。

示例：

```json
"key": "fld_name",          // 姓名
"sourceFormId": 12,         // 客户表
"sourceFieldKey": "fld_n1"  // 客户名称
"dictCode": "leave_type"    // 请假类型
"sourceFieldKey": "gone"    // 未查找到
```

## 6. 失败

只在这些情况失败，用 `ElMessage` 提示原因，右栏保持上一次成功结果（从未成功过则为空）。不做半成品输出，不做兼容或跳过。

| 情况 | 提示方向 |
|---|---|
| 左栏为空 | 请粘贴画布 JSON |
| 不是合法 JSON | JSON 无法解析 |
| 目录或源表请求失败 | 沿用接口错误文案 |

使用的人保证自己贴的是正确配置。工具不试图修 JSON、不补默认值、不忽略未知字段类型。

## 7. 实现要点

- 一个浮层组件，与 `RouterView` 并排挂在 `App.vue`，用路由名判断是否显示。
- 注解逻辑做成纯函数，便于单测：输入（解析后的配置 + 表名表 + 字段名表）→ 带注释的字符串。
- 现有 `getDirectoryApi`、`getFormApi`、`listDictionaryOptionsApi` 够用，不新增后端接口。
- 不写 `docs/testcases/`：这是开发辅助，不改变表单设计 / 填报行为。

## 8. 测试

单测即可：

1. 合法画布片段 + 名字表 → 对应行末有字段名、表名。
2. 名字表缺一项 → 该行 `// 未查找到`，其余行正常，整体仍成功。
3. 空串、非法 JSON → 抛错或返回失败，调用方不改右栏。
