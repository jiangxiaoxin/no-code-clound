# 流程版本管理 需求设计

日期：2026-09-07  
状态：已定稿  
范围：流程设计里对同一张表维护多份流程图版本：新增、查看、编辑、删除、启用。同一时间最多一版启用。启用中的不能单独关掉，只能再启用另一版，原来那版变回设计中。  
相关：`docs/superpowers/specs/2026-09-05-workflow-form-design.md`（本设计替换其中 §4.3、§5.5、§13 的「一份草稿 + 发布即启用」模型；画布节点、审批人、填报和待办仍以那份为准）

---

## 1. 一句话说清

一张流程表可以有多份流程图（V1、V2、V3）。正在用的那份标 **启用中**，新提交的请假单走它。其它份是 **设计中**：可以改、可以删，改完不会马上影响填报。要换流程就启用另一版（先做现在发布那套校验），原来那版自动变成设计中。启用中的只能看，不能改、不能删，也没有【停用】。从来没有启用过时还不能填。

已经在审批的单仍按提交当时那张图走，不跟着你切启用版而变。

---

## 2. 和现在有什么不同

现在流程设计顶栏是【保存】【发布】和「启用流程」开关：发布成功就覆盖唯一一份已发布图并自动启用。

改成：

- 没有【发布】按钮，也没有顶栏总开关。
- 左边是 **流程版本 (Vn)** 下拉，列出所有版本。
- 【保存】只写入当前正在看的、且状态是设计中的那一版，不会切换启用。
- 【保存并启用】先保存当前画布，再启用这一版（要点确认）。若已有启用中的版本，那一版会变成设计中。
- 【启用流程】仍出现在下拉里的管理弹窗里，作用同样是「让这一版成为唯一启用版」（要先保存）。

能不能填报，看的是 **此刻有没有一版处于启用中**，不再看「有没有点过发布」。

## 3. 流程设计顶栏

打开某张流程表的【流程设计】：

1. 若这张表还没有任何版本：自动生成 **流程版本 (V1)**，画布只有一个开始节点，状态设计中，并选中它。
2. 顶栏左侧是当前版本名称，例如「流程版本 (V2)」。名称旁有状态点：橙色设计中，绿色启用中。
3. 点名称打开下拉：
   - 上面列出所有版本，启用中的在前，其余按版本号从大到小。当前正在看的那一行左侧打勾。
   - 启用中右侧绿色标「启用中」；设计中橙色标「设计中」。
   - 横线下面：**添加新版本**、**管理已有版本**。
4. 顶栏右侧是【保存】和【保存并启用】（当前是设计中才可点）。不要【发布】，不要「启用流程」开关，也不做【预览】【测试】。

点下拉里某一版：画布换成那一版的图。若当前画布有未保存的修改，先问「当前版本有未保存的修改，切换将丢失。确定切换吗？」确定才切。

- **设计中**：画布可改，可【保存】，可【保存并启用】。
- **启用中**：画布只读（点节点仍能看右侧属性，改不了、存不了）。【保存】【保存并启用】都点不了。管理弹窗里没有【编辑】；要看这一版，从顶栏下拉切过去。

### 3.1 添加新版本

复制**下拉里当前选中**的那一版（图原样拷一份）。新版本号 = 现有最大号 + 1，名称「流程版本 (V3)」这种，状态设计中，并立刻切到新版去改。不弹命名框。本期不支持自定义版本名。

一张都没有时走 §3 第 1 条，不会走到添加。

### 3.2 管理已有版本

弹框标题 **管理已有版本**，可拖拽，列出全部版本（同样启用中在前）。每一行：名称、状态标、右侧按钮。

| 这一版的状态 | 右侧按钮 |
|---|---|
| 设计中 | 【启用流程】【编辑】【删除】 |
| 启用中 | 没有按钮 |

【编辑】：只出现在设计中。关掉弹框，切到这一版去改。有未保存修改时同样先确认。启用中不能编辑，行上没有【编辑】。

【删除】：只设计中能删。二次确认，文案写清「删除后不能恢复」。删的若是当前正在看的那一版，删完切到启用中的那一版；没有启用中则切到剩余里版本号最大的；一版都不剩则按 §3 第 1 条再生成 V1。启用中不能删，行上没有删除。

【启用流程】：见 §4。启用中那一行没有【停用】。

---

## 4. 启用

同一张表同一时刻最多一版是启用中。启用中的版本不能单独关掉。

### 4.1 启用

两条路都能启用当前这张图：

- 顶栏【保存并启用】：弹出确认「确定保存并启用当前版本吗？……」。点取消什么都不做。点确定后先写入画布，再启用这一版。
- 管理弹窗里某份设计中的【启用流程】：用**已保存**的图做校验。画布上改了没保存的，不拿来启用，先提示「请先保存」。

校验内容和现在点【发布】要拦的一样（孤点、环、缺结束、分支缺「其他情况」、审批人没配或人员/角色已停用等，见流程表单规格 §5.6）。

1. 校验失败：流程设计页顶部列出原因，不切换启用。从管理弹窗点的，弹框留着。
2. 成功：这一版变成启用中；若原先有别的启用中，那一版变回设计中（可以再改、再删、再启用）。没有单独的【停用】按钮。
3. **第一次有启用中的版本之后**，这张表才能按流程填报（工作台【保存草稿】/【提交】解开）。

启用不另存一份「发布图」：启用中的那一行里的图就是新提交要用的图。因为启用中不能改，所以不会出现「启用着却在画布上改了一半」的情况。

### 4.2 没有启用中时怎么填

界面上不能把最后一版启用中关掉。只有两种情况表上没有启用中：

- **从来没有启用过**：工作台提示「这张表单还没有配置流程」，【保存草稿】/【提交】都拦，一条数据都不写。
- **迁库遗留**（旧表曾经发布过、当时开关是关的）：新数据按普通表单保存并记为已通过、不建实例，详情写「流程停用期间保存，没有审批记录」。已经在走的审批继续按当时那张图走完。

第一次启用成功会记下「曾经启用过」，不清掉。这不是给界面上的【停用】用的。

## 5. 填报用哪一版

| 人在做什么 | 用哪张图 |
|---|---|
| 【提交】、草稿第一次【提交】 | 当前启用中的那一版（把版本号和图拷进实例）。没有启用中：按 §4.2 / 「还没有配置流程」 |
| 审批中、已驳回后再【再次提交】 | 这条实例提交时钉死的图，不换成现在启用的 |
| 已通过后在【数据管理】再【提交】 | 换成**此刻启用中**的那一版，从开始重新走。没有启用中：按停用期间保存，不重审 |
| 流程设计里改某一版并【保存】 | 只改这一版。若改的不是启用中（启用中本来就不能改），不影响任何人 |

实例上仍保存 `definitionVersion`（版本号）和整份 `graph` 快照。以后那一版被删掉，在途单还能画小流程图。

## 6. 怎么存

新建表 `workflow_version`（命名仍按项目习惯：表名单数，列名驼峰）：

| 人怎么理解 | 存什么 |
|---|---|
| 属于哪张表 | `appId`、`formId` |
| 第几版 | `version` 整数，从 1 递增；同一张表里唯一 |
| 流程图 | `graph`（JSON，和现在草稿图同一套节点/线） |
| 是不是正在用 | `enabled`，默认否。同一张表最多一行是是 |

普通索引：`formId`；唯一：`formId + version`。同一张表只能有一行 `enabled = 1` 由服务端保证（启用时先把该表其它行关掉再打开这一行），不要依赖数据库部分唯一索引。

原来的 `workflow_definition` 保留一行（仍按 `formId` 唯一），用来记 **曾经启用过**（`hasBeenEnabled`，第一次启用成功置真，停用不清）。上面的 `draftGraph`、`publishedGraph`、`publishedVersion`、`publishedAt`、`enabled` 迁完后不再给运行时用，实现时删这些列。**取当前流程图只认版本表里 `enabled = 1` 的那一行**；没有就是未启用。

谁能增删改启用：和现在能进【流程设计】的人相同（所有者或配置名单）。

## 7. 旧数据怎么迁

上线时对已有 `workflow_definition` 逐张表：

1. 有已发布图：插入一版，`version` 用原来的 `publishedVersion`（至少为 1），图用 `publishedGraph`；原来 `enabled` 为真则这一版启用中，否则设计中。
2. 有草稿图，且和已发布图不是同一份（或从未发布过）：再插入一版设计中，版本号 = 现有最大号 + 1，图用 `draftGraph`。从未发布、只有草稿：只生成 V1 设计中。
3. 定义行在、两份图都空：不插版本，`hasBeenEnabled` 为假；等人打开流程设计时按 §3 第 1 条生成 V1。
4. 原来已发布且当时是启用的：迁出的那一版启用中，`hasBeenEnabled` 为真。原来已发布但开关关着：迁出的已发布图为设计中，`hasBeenEnabled` 仍为真（停用过）。从未发布：`hasBeenEnabled` 为假。
5. 正在跑的实例不改：它们已经自带图快照。

SQL 手写、上线时执行一次，不要靠 TypeORM `synchronize`。

## 8. 接口（给人办事的）

仍挂在表单下，鉴权与现在流程设计相同。

| 人做的事 | 接口 |
|---|---|
| 打开流程设计，看到版本列表和当前正在看的图 | `GET .../workflow`，带上 `versions`（id、version、enabled、名称）和当前图；可带正在审批条数 |
| 保存当前设计中的版本 | `PUT .../workflow/versions/:versionId`，body 为图。启用中拒绝 |
| 添加新版本 | `POST .../workflow/versions`，body 指出从哪一版复制 |
| 启用 | `POST .../workflow/versions/:versionId/enable` |
| 删除设计中的版本 | `DELETE .../workflow/versions/:versionId` |

去掉现在的 `POST .../workflow/publish` 和按整表拨 `enabled` 的用法。工作台提交仍走现有 records 接口；服务端取图改为「当前启用的版本」。

## 9. 前端改哪里

- 【流程设计】顶栏：版本下拉 + 管理弹窗；画布按当前版本只读或可编辑；【保存】只写入当前设计中版本；【保存并启用】二次确认后先保存再启用。
- 工作台【添加数据】：有启用中的版本才出现【保存草稿】/【提交】；从来没启用过仍是「还没有配置流程」。没有【停用】按钮，界面上不能把最后一版启用中关掉。
- 文案里「已发布版本」改成「启用中的版本」：数据管理再提交、异常提示、设计页说明「审批中的 N 条仍按提交时的版本走」都跟着改。

---

## 10. 本期不做

- 自定义版本名、备注、复制到别的表
- 单独的预览页、用假数据测试跑流程
- 同时启用多版、按部门/条件启用不同版
- 从回收站恢复已删版本
- 对比两版差异

---

## 11. 手工怎么验收（实现时写入 `docs/testcases/`）

至少覆盖：添加新版本是复制当前选中的图；启用中不能改不能删也不能单独停用；启用前校验失败不切换；启用成功后新提交走新图、原来那版变回设计中、在途单仍走旧图；删设计中版本要确认；旧表迁完能看到原来的已发布图。
