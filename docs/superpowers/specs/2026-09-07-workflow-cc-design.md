# 流程抄送节点 需求设计

日期：2026-09-07  
状态：已定稿  
范围：流程设计增加抄送节点；提交或审批通过时旁路通知抄送人；首页和应用内增加【抄送我的】。抄送不挡主路、不能改表单、不填意见、不能再连出线。

## 1. 一句话说清

从开始、审批或分支可以再拉一条线到 **抄送**。主路仍只走原来那一条线；流程离开这个节点往下走时，把抄送人请进【抄送我的】看当时的单。抄送人只能看，不能改格子、不能填意见、没有【同意】【驳回】。抄送节点自己不能再连向别的节点。

---

## 2. 和现在有什么不同

现在左侧只有审批、分支、结束；规格写明抄送不做。

改成：

- 左侧多一个 **抄送节点**。
- 首页和应用内待办入口从三个变成四个，多【抄送我的】。
- 开始 / 审批仍是一条主出线，但可以另外连到抄送。分支原来的条件线不变，也可以另外连到抄送。

主路还是一次只走一条，不是并行审批。

---

## 3. 流程设计里怎么画

打开【流程设计】，左侧节点里增加 **抄送节点**，和审批、分支、结束并列。拖到画布上，默认名称「抄送」。可以改名称、可以删除。

### 3.1 怎么连线

- 只能从 **开始、审批、分支** 连到抄送。
- 抄送 **没有出线点**，不能再连向任何节点（和结束一样）。
- 结束仍然不能出线，所以不能从结束连到抄送。流程结束时要抄送：从最后一个审批同时拉两条线，一条到结束，一条到抄送。
- 一个节点可以连多个抄送；一个抄送也可以被多条线进来（几条支路抄给同一批人）。

主路规则不变：

| 节点 | 主出线 | 连到抄送 |
|---|---|---|
| 开始 | 必须恰好一条，连到审批 / 分支 / 结束 | 可以另拉若干条，只能连到抄送 |
| 审批 | 必须恰好一条，连到审批 / 分支 / 结束 | 同上 |
| 分支 | 至少两条条件线，恰好一条「其他情况」 | 连到抄送的线不配条件，也不算进这两条 |
| 抄送 / 结束 | 不能有出线 | — |

启用时：抄送能从开始走到、没有出线就行。 **可以不配抄送人**。不会因为「没配抄送人」拦住启用。若抄送人选了已经从表单删掉的人员字段，启用时提示，和审批一样。

从抄送往外拉线，或开始 / 审批多出来的线没连到抄送：启用拦住，顶部列出原因。

启用中的版本仍然只读，抄送节点也改不了。

### 3.2 点抄送时右侧有什么

1. **节点名称**。
2. **抄送人**：和审批同一套四种来源，可组合（指定人员、指定角色、表单内人员字段、发起人所属部门的负责人）。指定角色默认勾「限定与发起人同部门」。没有或签 / 会签，没有意见必填。
3. **字段权限**：每行只有 **不可见** 和 **简报**。没勾不可见的字段，抄送人打开后是只读；勾了不可见的不显示。简报勾上的出现在【抄送我的】卡片摘要里。默认和审批一样：单行文本 `input`、多行文本 `textarea`、数字 `number`、时间选择 `time`、日期选择 `date`、日期时间 `datetime` 勾上简报，其它自己勾。

抄送没有「可编辑」。没勾不可见的字段（含子表单 `subform`）都是只读。关联子表单 `relate-subform`、分割线、标签页容器本身不出现在权限表里，和审批节点相同。

---

## 4. 什么时候发出抄送

主路真正离开某个节点、往下一跳时，把从这个节点连出去的所有抄送一起发出去。主路照旧只走那一条主出线。

| 抄送挂在 | 什么时候发出 |
|---|---|
| 开始 | 点【提交】（草稿第一次交、驳回后再交、已通过后在数据管理再交也算） |
| 审批 | 这个节点【同意】，流程继续往下 |
| 分支 | 走到这个分支、已经选好要走哪条条件线时 |

【驳回】【撤回】不离开节点往下走，不发这个节点上的抄送。

同一轮、同一个抄送节点、同一个人只收到一张。没配人或运行时解析出 0 个人（停用、没部门负责人、人员字段是空等）：不写抄送记录，进度里写一句「没有可抄送的人」，主路继续。

发出抄送和派下一审批人在同一次流转里做：先按挂在本节点上的抄送写记录，再走向下一个停留点。下一审批没人导致整单进异常时，已经发出的抄送留着，不撤回。

## 5. 【抄送我的】

### 5.1 入口

首页产品名旁、应用内左侧应用名下面，都加一行 **【抄送我的】**，和【我的待办】【我发起的】【我处理的】并列。

- 首页：所有应用里抄送给当前用户的。
- 应用内：只看本应用。必须带当前应用 id 在服务端过滤。
- 不配未读数字（抄送不需要人处理）。
- 空状态：首页「还没有抄送」；应用内「本应用还没有抄送」。

没有该应用权限的人只走首页，不必、也不能进那个应用。

### 5.2 卡片

和另外三处同一套卡片 + 底部分页（10 / 20 / 50 / 100）。每张写：

- 表单名；首页再加应用名（如「人事 / 请假单」）
- 节点名（如「抄送」或改过的名称）
- 发起人、抄送到的时间
- 按该抄送节点勾了 **简报** 的摘要（人员显示姓名，部门显示部门名，不要数字 id）

点整张卡片打开右侧抽屉。列表按抄送时间从新到旧。

### 5.3 抽屉

默认【表单】页签。按该抄送节点的不可见 / 简报展示：不可见的不出现，其余只读，格子都不能改。没有意见框，没有【同意】【驳回】。

【流程】页签：只读小流程图会画出抄送节点；进度里抄送显示「已抄送」和收到的人，没有意见。没人可抄时只有那句「没有可抄送的人」。

进行中的单被抄送的人也能打开；之后审批人改了可编辑字段，再打开看到的是最新数据（和【我处理的】再看一样）。

同一个人既是当前审批人又被抄送：【我的待办】和【抄送我的】各一张，互不影响。【我处理的】列出我点过同意、驳回、转交、两种退回或再次提交的单，不会把抄送混进去。

数据被删：卡片标「数据已删除」，还能点【流程】看进度，表单不能改。

打开抽屉、读这一条，只看：当前用户是这条抄送记录的接收人。不要先校验是不是应用成员。读表结构、字典、本条数据走现有 `/api/workflow/...` 窄接口，不能顺着翻该表其它行。

---

## 6. 异常、重试、再交一轮

抄送发出去之后，主路若在下一步卡住（例如下一审批没人），整单仍进异常。已经发出的抄送留在【抄送我的】。发起人【重试】只重新派当前卡住的审批，**不会把已经发出的抄送再发一遍**。

驳回后再交、已通过后在数据管理再交，都是新一轮：挂在开始上的抄送会再发一张（同一人两轮两张卡片）。进行中的单仍按提交当时那张图，不因为后来改了流程设计而补发或收回抄送。

---

## 7. 怎么存

不新建表。抄送写成现有 `workflow_task` 一行：

- 接收人写在 `assigneeId`
- `status` 一写就是 `done`（没有待处理）
- `action` 为 `cc`
- `comment` 空
- `finishedAt` 等于发出时间
- 仍走原来的唯一约束：同一实例、同一节点、同一人、同一轮只有一行

【抄送我的】按 `assigneeId + action = cc` 查。【我的待办】仍只查 `pending`。【我处理的】只查 `done` 且动作在同意、驳回、转交、两种退回、再次提交里，`cc` 和加签不出现。

进度列表把 `action = cc` 的行写成「某人 · 节点名 · 已抄送」。

节点类型存流程图里：`type` 为 `cc`，抄送人结构与审批的 `approver` 相同，字段权限只有 `hidden`（没写或其它值都当可见只读），另有 `briefFieldKeys`。

---

## 8. 本期不做

- 站外通知（邮件、企微）
- 抄送未读点、已读未读
- 抄送人在抽屉里改数据或填意见
- 把抄送放进【我的待办】，或跟【我处理的】混在一起
- 从结束节点连出抄送
- 并行两条审批线同时批（抄送挂旁边不是并行审批）

## 9. 手工怎么验收（实现时写入 `docs/testcases/`）

请假单从部门审批再拉一条线到抄送，抄给张三，启用。

- 员工交事假：经理【我的待办】还在；张三【抄送我的】多一张；打开只能看、没有【同意】【驳回】；经理待办数字不包含这张抄送。
- 经理驳回：张三那张抄送还在。
- 经理【同意】：若人事备案也挂了抄送，那时才发给对应的人。
- 故意不配抄送人仍能启用；交单后进度写「没有可抄送的人」。
- 从抄送往外拉线，启用被拦住。
- 张三既是抄送人又是下一审批人：两个入口各一张。
- 【我处理的】没有这张抄送。
