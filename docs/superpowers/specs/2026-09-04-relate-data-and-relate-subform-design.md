# 关联数据、关联子表单 需求设计

日期：2026-09-04
状态：待确认

范围：调色板里两个还没实现的控件——**关联数据 `relate`**、**关联子表单 `relate-subform`**。

---

## 1. 一句话说清这两个控件

- **关联数据**：在当前表单里选中另一张表（也可以是当前表单自己）的**一条已有数据**，把两条数据**真正挂在一起**。库里存的是对方那条数据的 id，所以对方改了名字，这边刷新就跟着变。
- **关联子表单**：装在**被关联的那张表**上的一块**只读表格**。查看这张表某条数据的详情时，能看到「有哪些表的哪些数据关联了我」，可以翻页。

两者是同一条关系的两头：关联数据是**正向去挑**，关联子表单是**反向看回来**。所以关联子表单必须先有关联数据，不能单独用。

## 2. 贯穿全文的例子

准备两张表：

**工厂表**

| 字段 | 调色板控件 |
|---|---|
| 工厂编码 | 单行文本 `input` |
| 工厂名称 | 单行文本 `input` |

**人员表**

| 字段 | 调色板控件 |
|---|---|
| 工人名 | 单行文本 `input` |
| 工人编号 | 单行文本 `input` |
| 所属工厂 | **关联数据 `relate`**，数据源选「工厂表」 |

于是：

- 在人员表填报时，「所属工厂」点开弹窗，从工厂表里挑一条，比如「F001 / 一号厂」。
- 在工厂表画布上拖一个**关联子表单 `relate-subform`**，选「人员表」。打开一号厂的数据详情，下面就有一块表格，列出所有「所属工厂 = 一号厂」的人员，可翻页。
- 人员表就是这条关系里的**子表**，工厂表是**主表**。

## 3. 和现有几个像的能力怎么区分

设计和答疑时最容易混的五个控件，按「人在界面上做什么」分：

| 控件 | 人在填报时做什么 | 库里留下什么 | 源表事后改了值 |
|---|---|---|---|
| 下拉单选框 `select` + 选项来源「其他表数据」 | 从下拉里挑一个**值** | 那个值的文本 | 已提交的数据不变 |
| 数据联动（字段属性里的「数据联动」） | 人不挑，条件一满足系统自己带出来 | 带出来的值 | 已提交的数据不变 |
| 选择数据 `data` | 弹窗挑一条，把它的几个字段**拷**到本表其他字段 | 本字段存那条数据的 id（只为了回显），被填充字段存拷贝值 | 本控件回显跟着变；**拷出去的值不变** |
| **关联数据 `relate`** | 弹窗挑一条，**建立关系** | 本字段存那条数据的 id，这个 id 就是关系 | 显示字段跟着变；拷出去的值不变 |
| **关联子表单 `relate-subform`** | 不填、点不动，只看 | **什么都不存**，每次打开现查 | 子表数据一改，详情里就是新的 |

选择数据和关联数据长得很像，配置项也几乎一样，但产品含义不同：选择数据是「挑一行来抄」，关联数据是「指向那一行」。**两个控件并存，谁也不改成谁**，也不要把下拉「其他表数据」改成存 id。

## 4. 关联数据 `relate`

### 4.1 设计器里配什么

从调色板拖「关联数据」到画布，右侧属性面板除公共项（标题、占位提示、必填、宽度、字段说明、禁用、是否可修改）外，从上到下是：

1. **数据源**：一个「请选择表单」的下拉，列出本应用**已保存**的表单。和选择数据不同的是，**当前表单自己也在列表里**，用来做上下级关系。
2. 选好数据源后才出现下面四项：
   - **显示字段**（必配，单选一个源表字段）：控件收起时显示它的值，数据管理列表那一列也显示它。没配就在属性面板提示「请选择显示字段」。
   - **显示在表单中的字段**（可选，多选）：选中数据后在控件下方以「字段名：值」的小卡片展示。**只展示，不入库。**
   - **填充到表单中的字段**（可选）：把源表某字段的值拷到当前表单**已有**的字段里。规则和选择数据完全一样，也是一次性拷贝。
   - **选择过程设置**（可选）：配填报弹窗里表格显示哪些列、默认过滤条件。快捷搜索、分页固定有，不需要配。

复用选择数据现成的三个弹框（显示字段多选、填充规则、选择过程设置）和表单选择器，不要另做一套界面。

**换数据源**：允许换。一换就把显示字段、卡片字段、填充规则、弹窗列、过滤条件**全部清空**（和选择数据换表一致）。如果这张表已经有填报数据，那些老 id 在新数据源里查不到，列表和填报会显示「已删除」。

**关联当前表单**：一张表**最多一个**数据源指向自己的关联数据字段。再拖第二个并选自己时，提示「已有关联本表字段」，不保存这次选择。关联别的表的数量不限。

**能放哪里**：可以放在标签页 `tabs` 的任一页签里。**不能拖进子表单 `subform`**，拖入应被拒绝。

### 4.2 画布上看到什么

- 没选数据源：标题下面一行灰字「请选择主表」。
- 选了数据源：和选择数据同款的灰色占位框（点不开，也不查数据）；若配了卡片字段，下面按字段名列出示例行，值都是「—」。

### 4.3 填报时怎么用

- 收起时显示所选数据**显示字段**的当前值；没选过就显示占位提示。
- 点一下打开「选择数据」弹窗：表格按配置的列显示，右上角快捷搜索，底部分页，**一次只能勾一条**，点「确定」写入。
- 确定后：控件显示那条数据的显示字段；配了卡片字段就在下方展示；配了填充规则就把值写进目标字段。
- 目标字段标题前的「会受 [ … ] 字段影响」提示，要把关联数据字段也算进去（现在只统计了选择数据）。
- **清空**：非必填时收起态右侧出现清空图标，点了只去掉这条关系，**不清**之前被填充的其他字段，也不再发请求。
- **禁用**：点不开弹窗。**不可修改**：新增时能选，编辑已有数据时锁住。
- 关联当前表单时，弹窗里**看不到正在编辑的这条数据**，选不了自己。新增（还没有 id）时不排除任何数据。

### 4.4 源表改了值，这边跟不跟

| 配置项 | 源表改了值以后 |
|---|---|
| 显示字段、显示在表单中的字段 | 刷新（重新打开详情、重进列表）就是**新值** |
| 填充到表单中的字段 | 不变，还是当时拷过来的值 |

三种查不到的情况：

| 情况 | 收起态显示 | 卡片显示 |
|---|---|---|
| 源数据被删了 / 没权限 | 已删除 | 全部「—」 |
| 显示字段在源表被删了 | 显示存的 id | 缺的那行「—」 |
| 数据源被换过、id 对不上 | 已删除 | 全部「—」 |

「已删除」时那条 id 还留在库里，人可以清空或改选别的数据，系统不自动清、也不级联删。

### 4.5 树形关系怎么做（不给专门控件）

上下级（树）关系**没有**专门的控件。做法是：

1. 建一张表，比如「组织表」，字段有「名称」和「上级」，其中**上级**用关联数据、数据源选组织表自己。这样每条数据指向自己的父节点，一层一层就串成了树。
2. 想在别的表单里**一级一级往下选**，不用关联数据，而是放**多个下拉单选框 `select`**：第一级选项来源选「其他表数据」取组织表；第二级配**数据联动**，条件是「组织表的上级 = 第一级下拉选中的值」；第三级同理挂在第二级上。

关联数据本身只表达**相邻两层**（我指向我的父），不在控件里选爷节点。本期也不检测 A→B→A 这种环，只禁止选自己。

### 4.6 数据管理列表、详情、导入

- **列表**：这一列显示「显示字段」的文本，不显示 id。单元格**不能**内联编辑（和选择数据一致），要改就打开详情或编辑抽屉。
- **筛选、排序**：仍然按存进去的 id 精确匹配，不支持按显示文本模糊搜（登记后续）。
- **详情（只读态）**：点显示文本能打开源表那条数据的只读详情抽屉。打不开（已删除、没权限）就弹一条提示，不跳。编辑态点它仍然是打开选择弹窗。
- **导入**：和选择数据一样，**导入模版里没有这一列**，导入也不会写它。要建立关系，得进表单里选。

### 4.7 关联数据本期不做

| 项 | 说明 |
|---|---|
| 一次关联多条 | 主表侧只关联一条；要多条就在对面用关联子表单看 |
| 拖进子表单 | 子表单不接受这个控件 |
| 弹窗里「允许新增源表数据」 | 选择数据也还没有 |
| 填充到「新建字段」 | 只能填到已有字段 |
| 源表改值后同步已填充字段 | 填充就是拷贝 |
| 删源数据时级联清空 / 级联删子表数据 | 只显示「已删除」 |
| 跨应用、聚合表 | 和选择数据、数据联动同一限制 |
| 关联字段数量上限 | 不设配额 |
| 按 Excel 导入建立关系 | 导入模版不含这一列 |

## 5. 关联子表单 `relate-subform`

### 5.1 用之前必须先有关联数据

关联子表单能选的表，只有**已经用关联数据指向当前表单**的那些表。按第 2 节的例子：人员表里有「所属工厂」（关联数据，数据源=工厂表），所以在**工厂表**里加关联子表单时，「人员表」才会出现在候选里。

简道云在拖入时会问「从已有关联表选择，还是新建一张空白表」。**本项目简化：只有「从已有关联表选择」**，不提供新建空白表。

### 5.2 设计器里配什么

从调色板拖「关联子表单」到画布，弹出「选择关联表单」弹框：

- 列出本应用里**所有含关联数据字段、且该字段的数据源是当前表单**的表单。同一张表如果有两个关联数据字段都指向当前表单（比如人员表有「所属工厂」和「常驻工厂」），就按**表单 + 关联字段**分别列成两条，让人分得清挂的是哪条关系。
- 一条都没有时，弹框里显示「还没有表单关联本表单，请先在其他表单里添加关联数据并选择本表单」，点确定不往画布放东西。
- 选好一条点确定，字段才落到画布上，标题默认取「<子表名>」，可以改。

属性面板（选定之后）：

1. **关联表单**：只读展示选中的表 + 关联字段，比如「人员表 · 所属工厂」。要换就删掉字段重新拖（避免留下配错的列）。
2. **显示的列**：多选子表里可展示的字段，决定详情里那张表格有哪几列。默认勾上子表前 5 个可展示字段；一列都不勾时详情里提示「请先配置显示的列」。
3. **是否可查看详情**：开关，**默认关闭**。开启后，主表详情里点表格某一行，会打开子表那条数据的只读详情抽屉，字段和数据与在子表数据管理里点开一致；关闭时行不可点，也不会弹抽屉。
4. 公共项里只保留**标题**、**字段说明**。**没有字段宽度**：关联子表单固定占整行，和子表单一样。必填、禁用、是否可修改、占位提示、每页条数对它没意义，**不显示**这些开关。每页条数在详情里看表时再选。

**能放哪里**：可以放进标签页 `tabs`。**不能拖进子表单 `subform`**，也不能嵌在另一个关联子表单里，拖入应被拒绝。一张表可以放多个关联子表单，但**同一个「表单 + 关联字段」只能放一个**，重复添加时提示「已添加该关联表单」。

### 5.3 画布上看到什么

标题下面是一块和子表单类似的表格占位，**占整行**：表头一格一格显示「显示的列」的**字段标题**（如「工人名」「工人编号」），不是字段 key；表体一行空格子。标题左侧有链式图标，悬停提示「关联子表单，详情里只读查看关联本表的数据」。表格下方有灰字「保存数据后，在数据详情里查看关联数据」。没有「添加」按钮，也不能点列头改配置。**画布不查关联记录**；为了显示标题，会读一次子表字段定义。

### 5.4 添加数据时看到什么

工厂表点「添加数据」，抽屉里**只有**工厂编码、工厂名称等可填字段——**不出现**关联子表单这块区域（没有标题、没有占位灰字）。因为还没有这条数据的 id，查不到谁关联了它，也没有必要占位置。

它不参与必填校验，也不写进库：保存后这条工厂数据的字段里没有关联子表单这个 key。

### 5.5 查看详情时看到什么

数据管理点开一号厂的详情，除工厂编码、工厂名称外，下方多出一块表格。标题左侧同样有链式图标和上述悬停提示。

- 表头是配好的「显示的列」；每行是一条「所属工厂 = 一号厂」的人员数据。
- 底部有**分页**，可选每页 10 / 20 / 50 / 100 条（和项目其它列表同一套），改完立刻重新查；默认按更新时间倒序（和数据管理列表一致）。
- 一条都没有时显示「暂无关联数据」。
- 若设计器里开启了「是否可查看详情」，点某一行会打开**子表**那条数据的**只读**详情抽屉，抽屉里按子表完整表单回显（含关联数据、显示字段等）；关掉回到主表详情，页码不丢。开关关闭时，行不可点，也不弹抽屉。
- 加载中显示 loading；查询失败显示「加载失败」和重试入口，不影响详情其余部分。

**主表数据详情里点「编辑」以后**：这块表格仍然只读，能翻页、能点开子表数据的只读详情，但不能在这里改、删、加行。保存主表数据不会动子表数据。

想新增、修改、删除人员，去**人员表**自己的工作台或数据管理里做。简道云在这里提供「可新增 / 可编辑 / 可删除」的开关，**本项目暂不做这些开关和对应功能**。

### 5.6 放在标签页里

关联子表单可以放进标签页的任一页签，切过去能看到表格、能翻页。打开详情时每个关联子表单各查一次（页签内容本来就是一起渲染的，不为它单独做懒加载）。

### 5.7 关联子表单本期不做

| 项 | 说明 |
|---|---|
| 拖入时「新建空白关联表」 | 只支持从已有关联表选择 |
| 在这块表格里新增 / 编辑 / 删除子表数据 | 去子表自己的页面做 |
| 简道云那种**自动生成**的「关联标签页」 | 反向数据必须由人在主表画布里显式加这个控件 |
| 按子表列筛选、排序、汇总 | 只有分页 |
| 出现在数据管理列表里当一列 | 列表不显示这个字段，也不进导入模版、不进导出 |
| 换关联表单 | 删掉重加 |
| 跨应用 | 同现有限制 |

## 6. 字段 JSON

**关联数据**（仅 `type: 'relate'` 有意义，键名沿用选择数据，语义分开）：

```json
{
  "type": "relate",
  "key": "field_8",
  "title": "所属工厂",
  "sourceFormId": 12,
  "titleKey": "field_1",
  "displayFieldKeys": ["field_1", "field_2"],
  "displayFieldLabels": { "field_1": "工厂名称" },
  "fillMappings": [{ "sourceKey": "field_2", "targetKey": "field_5" }],
  "pickerColumnKeys": ["field_1", "field_2"],
  "optionFilters": null
}
```

| 键 | 含义 |
|---|---|
| `sourceFormId` | 源表（主表）的表单 id；等于当前表单 id 就是关联本表 |
| `titleKey` | 「显示字段」，收起态和列表列显示它 |
| `displayFieldKeys` / `displayFieldLabels` | 「显示在表单中的字段」，只展示不入库 |
| `fillMappings` | 「填充到表单中的字段」，源字段 → 本表已有字段 |
| `pickerColumnKeys` | 填报弹窗表格列；空则按选择数据现有默认 |
| `optionFilters` | 弹窗默认过滤条件，结构复用选择数据 |

入库：`data[key]` = 源数据 id 字符串（已有的 `coerceFieldValue` 就是这么处理 `relate` 的），空值不写这个 key。

**关联子表单**（`type: 'relate-subform'`，**不入库**）：

```json
{
  "type": "relate-subform",
  "key": "field_9",
  "title": "人员表",
  "childFormId": 30,
  "childRelateKey": "field_8",
  "columnKeys": ["field_1", "field_2"],
  "canViewDetail": false
}
```

| 键 | 含义 |
|---|---|
| `childFormId` | 子表（含关联数据那张表）的表单 id |
| `childRelateKey` | 子表里那个关联数据字段的 key，指明挂的是哪条关系 |
| `columnKeys` | 详情表格显示哪些列 |
| `canViewDetail` | 是否允许点行打开子表数据的只读详情抽屉；默认 `false` |

`childFormId` 或 `childRelateKey` 缺失视为没配好：画布和详情都只显示提示，不发查询。校验、保存、导入导出一律跳过这个字段（和 `divider` 一样属于不填报字段）。

## 7. 需要后端配合的三处

现有接口基本够用，缺三个小口子：

1. **弹窗里排除自己**（关联本表用）：记录查询接口 `POST /apps/:appId/forms/:formId/records/query` 加一个可选的 `excludeIds`（字符串数组），不传时行为和现在完全一致。
2. **按 id 批量取数据**（列表补显示字段用）：数据管理一页最多 100 条，逐条查太碎。给同一个查询接口加一个可选的 `ids`（字符串数组），只返回这些 id 的数据，一次把本页要显示的标题取回来。
3. **表单字段清单要带上关联数据字段**：`GET /apps/:appId/form-fields` 现在会把 `relate` 类型过滤掉，关联子表单就没法找出「谁关联了我」。给 `include` 参数加一个 `relate`（和现有 `include=subform` 同一个位置），返回的关联数据字段里带上它的 `sourceFormId`。

关联子表单查数据不需要新接口：直接用子表的记录查询，条件是「那个关联数据字段 = 当前主表数据 id」，分页照常。`relate` 已经在可筛类型里，也已经建了 `data.<key>` 索引。

## 8. 验收场景（照着点就能验）

1. **挑一条、存的是关系**：人员表新增，「所属工厂」点开弹窗，勾「一号厂」确定，收起态显示「一号厂」。保存后进详情，还是「一号厂」。
2. **源表改名，这边跟进**：把工厂表里「一号厂」改成「一号厂（新）」。回到人员表刷新，那条人员的「所属工厂」显示「一号厂（新）」；如果当时配了填充规则把工厂编码拷进人员表某字段，那个字段**不变**。
3. **卡片不入库**：给「所属工厂」配「显示在表单中的字段 = 工厂编码」。选中后控件下方显示「工厂编码：F001」。保存后再看这条数据，工厂编码仍能显示（现查的），但人员表自己没有多出一个存工厂编码的字段。
4. **弹窗列和搜索**：选择过程设置里只勾工厂编码、工厂名称。填报弹窗表格就只有这两列（加序号、勾选列），快捷搜索和分页可用。
5. **没配数据源**：新拖一个关联数据不选表，画布提示「请选择主表」，填报里点它没有反应。
6. **源数据删了**：删掉「一号厂」。人员那条数据还在，「所属工厂」显示「已删除」，可以清空或改选别的工厂。
7. **关联本表、选不到自己**：组织表加「上级」，数据源选组织表自己。先建「总部」（上级留空），再建「华东分部」，弹窗里能选到「总部」；编辑「华东分部」时弹窗里看不到「华东分部」自己。
8. **关联子表单的候选表**：工厂表拖关联子表单，弹框里能看到「人员表 · 所属工厂」；把人员表的「所属工厂」数据源改成别的表后，重新拖时这条就不在候选里了。
9. **新增看不到、详情才看到**：工厂表「添加数据」时抽屉里**没有**关联子表单（无标题、无占位）。保存后打开该工厂详情，才出现人员表格，条数对得上。
10. **翻页与点开**：给一号厂造 12 条人员。详情默认每页 10 条，第 1 页 10 条，翻到第 2 页 2 条；把每页改成 20 后重新查出 12 条、只剩 1 页。点某一行打开该人员的只读详情，关掉后仍停在刚才那一页。
11. **详情编辑态只读**：工厂详情点「编辑」，关联子表单区域没有新增 / 删除按钮，行内点不出编辑框；保存工厂后人员数据没有任何变化。
12. **换了归属就换了位置**：把某人员的「所属工厂」从一号厂改成二号厂。一号厂详情里少这一条，二号厂详情里多这一条。
13. **不能进子表单**：往子表单里拖关联数据、关联子表单，都被拒绝。
14. **标签页里也能用**：把关联子表单放进标签页第二个页签。打开工厂详情切到第二个页签，表格照样列出人员并能翻页。

## 9. 建议实现顺序

1. 关联数据的属性面板（选数据源含当前表单、显示字段、复用三个弹框、限制一个关联本表）+ 画布占位。
2. 关联数据填报控件：复用/扩展选择数据的弹窗表格，存 id、回显显示字段与卡片、执行填充；把它计入「会受 … 字段影响」提示。
3. 关联本表：表单选择器打开 `includeCurrent`，查询加 `excludeIds`。
4. 数据管理列表按 id 批量补显示字段文本；只读态点开跳源数据详情。
5. 关联子表单：`form-fields` 带上关联数据字段 → 拖入弹框选关联表 → 属性面板 → 详情里的只读表格与分页。

第 1、2 步做完就能验「挑一条、刷新跟进」；树形和列表标题放后面；关联子表单依赖第 1 步的字段配置，必须排在它后面。
