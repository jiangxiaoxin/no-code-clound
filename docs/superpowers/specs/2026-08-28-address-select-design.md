# 地址选择设计

日期：2026-08-28  
状态：已确认  
范围：主表字段 `type: 'address'` 的设计配置、级联选择、详细地址、填报入库、数据联动、Excel 导入。不包含定位地图、国外地址、按地址筛选索引。

对照：省市区数据只有一份，在仓库根 `shared/region/`（`sheng.json`、`sheng-shi.json`、`sheng-shi-qu.json`）。前端 Vite 别名 `@region`、后端 `REGION_DIR` 都读这里，不要再复制到 `front/` 或 `server/`。数据联动对齐图片/文本：条件变化后查他表，把匹配记录上的地址字段写到当前字段。

## 1. 需求核对（原描述 → 补齐）

| 原描述 | 判定 | 本期怎么定 |
|---|---|---|
| 用项目里的 JSON 配置 | 清楚 | 三种格式分别读三份 JSON，不另调接口 |
| 格式：省 / 省-市 / 省-市-区 / 省-市-区-详细地址 | 清楚 | 字段属性 `addressFormat`，默认最后一种 |
| 必填、禁用、可修改 | 清楚 | 与现有公共字段属性相同 |
| 详细地址最长 256 | 清楚 | 固定上限，不做可配；超出不能再输入 |
| 支持数据联动 | 清楚 | 只对应地址字段；整份地址值写入后再按当前格式裁切 |
| （未写）存什么 | 缺口 | `{ ids, labels, detail }`，`ids`/`labels` 与级联路径等长 |
| （未写）直辖市、港澳 | 缺口 | 树里本来就没有市级时，选到叶子即可（北京：省-市只选北京市；省-市-区为北京市→东城区） |
| （未写）列表 / 导入 / 单元格 | 缺口 | 列表拼显示文案；**支持单元格内联编辑**；**Excel 导入占一列**，按名称（或国标码）走树解析成 `{ ids, labels, detail? }` |

本期不做：地图定位、经纬度、国外行政区、按地址列筛选/排序索引、把地址拆成多个独立字段、导入别名（「山东」当「山东省」）、单元格贴 JSON。

## 2. 数据文件

节点字段只有 `id`、`fullname`、`level`，有下级才有 `districts`。叶子不带空数组。

| 格式 `addressFormat` | 数据文件 | 选择深度 |
|---|---|---|
| `province` | `sheng.json` | 一级 |
| `province-city` | `sheng-shi.json` | 到市级叶子（直辖市/港澳无下级，一级即叶子） |
| `province-city-district` | `sheng-shi-qu.json` | 到区县叶子 |
| `province-city-district-detail` | `sheng-shi-qu.json` + 输入框 | 区县叶子 + 详细地址 |

控件按当前格式 **按需动态 `import()`** 对应 JSON（`import('@region/sheng.json')` 等），避免三种格式都打进同一包。不要改 JSON 结构，也不要在 `front/`、`server/` 再留副本。

导入跑在服务端，用 `REGION_DIR`（`server/src/config/region-dir.ts`）读同一目录，把名称/国标码解析成 `ids`。部署时仓库里的 `shared/region/` 要跟着服务端一起带上（不要拷进 `dist` 当第二份源）。

级联 `el-cascader` 的 `props`：`{ value: 'id', label: 'fullname', children: 'districts' }`。`checkStrictly` 关闭，必须选到当前树的叶子。

## 3. 字段配置

公共项：标题、占位（级联用）、必填、宽度、tips、禁用、可修改。

地址专有（拖入画布时写入默认值）：

```json
{
  "type": "address",
  "addressFormat": "province-city-district-detail",
  "optionSource": "custom"
}
```

`addressFormat` 只允许上面四个值；缺省或非法时按 `province-city-district-detail`。

属性面板（紧挨必填）：

1. 地址格式：四个单选项，文案为「省」「省-市」「省-市-区」「省-市-区-详细地址」
2. 数据源：自定义 / 数据联动（`hasLinkageSource` 含 `address`）

不含：详细地址最大长度配置（写死 256）、是否可搜索（级联默认 `filterable`）。

画布：禁用的级联（及格式带详细地址时的禁用输入框），不改 JSON。已配联动时标题旁仍显示联动图标。

改格式后：已填路径按新树裁切无效段；若新格式不含详细地址则丢掉 `detail`。

## 4. 值形状

```json
{
  "ids": ["130000", "130100", "130102"],
  "labels": ["河北省", "石家庄市", "长安区"],
  "detail": "中山路 1 号"
}
```

规则：

- `ids`、`labels` 均为字符串数组，长度相同，顺序为从省到当前选中叶子。
- 北京市 + 省-市：`{ "ids": ["110000"], "labels": ["北京市"] }`
- 北京市 + 省-市-区：`{ "ids": ["110000", "110101"], "labels": ["北京市", "东城区"] }`
- 不含详细地址的格式不存 `detail`，或存了也忽略。
- 空值：`undefined`，或 `{ "ids": [], "labels": [] }`（规范化后当空）。
- `detail` 只 trim 后的文本，最长 256；空串视为没有详细地址。

显示文案：`labels` 用 ` / ` 连接；有 `detail` 时再空一格接上。例：`河北省 / 石家庄市 / 长安区 中山路 1 号`。列表展示与导入字符串不同：展示用空格接详细地址；导入用 `|`，避免街道里的空格拆错。

## 5. 运行时

### 5.1 控件 `FormAddressSelect`

- 上：`el-cascader`，`filterable`、`clearable`、`disabled` 跟字段走。
- 下：仅 `province-city-district-detail` 时渲染 `el-input`，`maxlength="256"` `show-word-limit`，占位「请输入详细地址」。
- 布局：竖排 flex，间距用 margin，不用 grid。
- 级联 `placeholder` 用字段占位，空则「请选择」。
- 清空级联时同时清空 `detail`。
- 图标：`Location`（`@element-plus/icons-vue` 已有该导出）。

### 5.2 必填 / 禁用 / 可修改

- **必填**：当前格式下路径必须选到叶子；带详细地址时 `detail` trim 后也不能空。未完成不能保存。
- **禁用**：级联和详细地址都不能改。联动仍可写入（与图片、文本相同）。
- **不可修改**：新增可填；`updating && editable === false` 时锁住，联动也不改该字段。

### 5.3 入库

`fillValues`：`address` 可填报、要持久化。空不写 key（更新 `clearEmpty` 时写 `null`）。

后端 `coerce`：只收对象；`ids`/`labels` 必须等长的字符串数组；`detail` 可选字符串，超过 256 截断。非法类型 400。不建 `data.*` 筛索引。

### 5.4 数据管理

该列显示拼接文案，超长省略 + `title` 看全文。

**单元格内联编辑**：悬停出现编辑按钮，点开后在格内用同一套 `FormAddressSelect`（级联；带详细地址时下面再跟输入框）。保存规则与填报相同（必填要选到叶子；带详细地址时 `detail` 也不能空）。

- 不含详细地址：选到叶子后即可提交（对齐下拉单选选完即存）。
- 含详细地址：改级联不立刻存，点格子外再提交，方便先选区再填街道。
- 点级联下拉面板不算点到格子外，不能误关编辑。
- `disabled`、`editable === false`、或 `optionSource === 'linkage'`：不出现编辑按钮（与现有 `isInlineEditable` 一致，单元格不跑联动）。
- 行点击打开详情时，正在编辑的格子和级联下拉不冒泡。

### 5.5 Excel 导入

地址**不加入** `IMPORT_SKIP_TYPES`。仍占**一列**（表头仍是字段标题），不要拆成省/市/区多列，也不接受 JSON 对象文本。配了数据联动的地址列同样可导入（导入不跑联动，只写入解析结果）。

单元格写成行政区路径；带详细地址时用 `|` 与街道分开。

| 字段格式 | 单元格示例 | 入库 |
|---|---|---|
| 省 | `山东省` | `{ ids: ["370000"], labels: ["山东省"] }` |
| 省-市 | `山东省 / 青岛市` | `{ ids: ["370000", "370200"], labels: ["山东省", "青岛市"] }` |
| 省-市-区 | `山东省 / 青岛市 / 市南区` | 三级 `ids` / `labels` |
| 省-市-区-详细地址 | `山东省 / 青岛市 / 市南区 \| 香港中路 1 号` | 上面再加 `detail` |

解析规则：

1. 空单元格当未填。
2. 以 `示例：` 或 `示例:` 开头的单元格当未填（给模版说明行用，见下）。
3. 先按 `|` 拆成「路径」和「详细地址」。不含详细地址的格式若出现 `|`，失败。含详细地址的格式没有 `|`、或 `|` 右侧 trim 后为空，失败。`detail` trim 后最长 256，超出截断。
4. 路径按 `/` 或 `／` 分段，段前后 trim；不要用 `-` 分段。
5. 每一段：若全是数字则按节点 `id` 匹配，否则按 `fullname` **精确**匹配。从树根往下走，只在已选中父级的 `districts` 里找；禁止全国搜同名区县。
6. 必须落到**当前格式对应树**的叶子（与填报相同）。直辖市在「省-市」下 `北京市` 即叶子；「省-市-区」必须写到区。不要按固定级数切。
7. 本期不认简称（「山东」≠「山东省」）。不认列表展示那种「空格接详细地址」。

失败（对不上、没到叶子、详细地址不合规）或必填却为空：与现有导入一致，**整行丢掉**，不要半截写入。

**下载模版**：表头一行不变。表单里只要有地址列：

- 该列表头加 Excel 批注，说明分隔符和示例。
- 第 2 行该列写入 `示例：` + 上表对应文案（其他列留空）。用户改掉或删掉这一行后从第 2 行起仍按数据导入。

没有地址字段的表单，模版仍只有表头，行为与现在相同。

## 6. 数据联动

把 `address` 加入 `LINKAGE_VALUE_TYPES`。触发字段只列出源表 `type === 'address'`。`listFormFields` 的 `OPTION_FIELD_TYPES` 增加 `address`。「其他表数据」树排除 `address`（与图片一样，不当下拉选项来源）。

运行时按文本规则，不是图片那套收集多条 URL：

- 查询 `pageSize: 2`。
- 0 条：清空，不提示。
- 1 条：取该记录地址对象，按**当前字段格式**裁切后写入（多出的级联丢掉；目标不含详细地址则丢掉 `detail`；目标含详细地址而源没有则为空串）。
- 多条：清空，提示 `[ 字段标题 ] 字段联动查询出多条数据`（有说明时为 `[ 标题，说明 ] …`）。

裁切：用目标格式对应的树，从根沿 `ids` 往下走，只保留树上存在的前缀，停在目标格式允许的最深叶子之前（不能越过目标树的叶子）。不要按固定「2 级」去切直辖市。

源格式比目标浅（源只有省，目标要省-市-区）：写入已有前缀，其余让用户补。必填在提交时再拦。

地址作为**条件字段**时，空路径视为未填，联动不发查询（与空文本相同）。

## 7. 验收

1. 四种格式各自只能选到对应深度；默认「省-市-区-详细地址」有级联 + 256 字输入。
2. 河北省能选到市、区；北京市在「省-市」下只能选北京市，在「省-市-区」下能选到东城区。
3. 必填：没选完叶子，或选了区但没填详细地址（该格式下），不能保存。
4. 禁用：不能改级联和详细地址。
5. 不可修改：新增能填；打开已有记录编辑时不能改。
6. 联动：源表地址带出；格式更浅时丢掉多余级联和详细地址；多条匹配清空并出现多条提示。
7. 数据管理看到拼接文案；未配联动且未禁用/未锁「不可修改」时，悬停可点编辑，格内改省市区（及详细地址）并能保存。
8. 画布不加载真实选择（禁用占位即可）。保存后再打开填报，值与文案一致。
9. 配了数据联动的地址列，行内不出现编辑按钮。
10. 导入模版地址列有批注和第 2 行 `示例：…`；按名称或国标码填到叶子能入库；格式要区却只写到市、或详细地址格式没有 `|`，该行不导入。示例行本身不会入库。
