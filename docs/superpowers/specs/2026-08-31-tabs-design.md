# 标签页组件设计

日期：2026-08-31  
状态：已确认  
范围：表单设计器增加 `type: 'tabs'` 布局组件；填报、详情按页签展示；内部字段仍是主表字段。不包含多个标签页组件、套娃 tab、跨 tab / 内外拖字段、复制标签页、移动端、导入导出交互改造。

## 1. 背景与目标

左侧组件清单里已有未完成的「标签页」`tabs`。当前画布、填报、入库都按一层扁平 `fields[]` 处理：点清单或拖到画布，字段加在整表末尾或某字段旁。

要用标签页把同一张表的字段分成几组来展示和编辑，同时：

- 标签页**只做视觉编组**，自己没有值、不单独建表。
- 内部字段仍是主表字段：`data` 仍是 `{ 姓名: '...', 金额: 1 }`，不会出现 `{ 标签页: { 基本信息: { 姓名 } } }`。
- 列表、联动、选择数据把内部字段当普通主表字段（能选到、能填到）；列表不出现「标签页」列，也不按 tab 分组表头。

对比：子表单才在主记录里存数组。标签页更接近分割线——分割线是一条分隔，标签页是一组可切换的分组。

### 已确认的产品决策

| 项 | 决策 |
|---|---|
| 数据 | 视觉编组；值在主表扁平 `data` |
| 数量 | 一张表只能有一个标签页组件；pane 内也不能再放标签页 |
| 位置 | 标签页上面/下面仍可放普通字段 |
| 投放 | 选中标签页或其内部字段时，点/拖清单进当前活动 tab；选中外面字段或点画布空白，加到整表 |
| 拖排序 | 只在当前 tab 内拖字段排序；不支持跨 tab、不支持主表与 tab 互拖 |
| pane 数量 | 默认 2 个，最少 2 个，最多 10 个 |
| 填报 | 添加数据、新建抽屉、详情/编辑用同一套页签；未打开的 pane 必填和联动仍生效 |
| 复制 | 画布字段复制按钮已注释，本期不考虑复制标签页或内部字段 |

## 2. 本期边界

### 本期做

- 设计器：默认 2 个 pane；属性里添加 / 删除 / 改标题 / 拖动改 pane 顺序。
- 设计器：点或拖左侧清单，向当前活动 tab 加字段；当前 tab 内字段可拖排序。
- 删除 pane：二次确认，确认后删除该分组及内部全部字段。
- 填报 / 详情：按页签切换展示；提交校验含未打开 pane。
- 入库、列表、联动、选择数据、导入字段列表：对 schema 做 `flattenFields`，内部字段当主表字段。

### 本期不做

- 多个标签页组件、tab 内再套标签页。
- 跨 tab 拖字段、主表区域与 tab 内互拖。
- 复制标签页（画布复制入口当前关闭）。
- 记住活动 tab（设计器、填报都不写入 schema / 记录）。
- 移动端；导入导出交互（只要求字段列表能摊到内部字段）。
- **实现子表单**。子表单在另一分支开发。标签页允许把 `subform` 放进 pane（与主表相同，不额外拦截）。子表单能力以那条分支为准；标签页合入后，再把子表单分支合并过来，做「标签页 + 子表单」联调，不在本期验收。

## 3. 数据与约束

根 `fields[]` 里可以有一个 `type: 'tabs'`，夹在其它字段中间：

```js
{
  type: 'tabs',
  key: 'tabs_1',
  title: '标签页',
  width: '1',
  panes: [
    { id: 'p1', title: '标签页1', fields: [] },
    { id: 'p2', title: '标签页2', fields: [] },
  ]
}
```

- `key` 与其它字段同一套唯一规则。`title` 仅设计器识别，填报不展示这条标题。
- `width` 始终 `'1'`，属性里不提供宽度。
- `id` 是 pane 的稳定标识；改标题、拖排序都不换 `id`。
- 默认两个 pane，标题「标签页1」「标签页2」。
- 内部字段 `key` 与主表字段全局唯一。
- 标签页自身不入库：`isFillable` / 后端 coerce 把 `tabs` 与 `divider` 一样跳过。

### flattenFields

所有「按字段列表干活」的地方改为先摊平。顺序：**标签页前的根字段 → 各 pane 按 `panes` 顺序 → 标签页后的根字段**。遇到 `tabs` 时进入 `panes[].fields`，**不要**进入 `subform.fields`（那是子表列，不是主表字段）。合并子表单分支后仍遵守这条，否则会把明细列误当成主表列。

`listFormFields`、导入 `importableFields`、索引、唯一值、联动/选择数据的字段下拉，都走摊平结果。

## 4. 设计器

### 选中与活动 tab

- 点页签条或 pane 空白内容区：选中整个标签页组件，右侧为标签页属性。
- 点某个 pane 标题：切到该 pane，同时选中标签页组件。
- 点 pane 内字段：选中该字段；活动 tab 仍是它所在 pane。
- 活动 tab 只存在设计器会话里，不写入 schema。

### 添加字段

- 已选中标签页，或已选中某 pane 内字段：点左侧清单，或拖到当前 pane 内容区 → 加入**当前活动 tab**（拖到某字段上则插到它前面，与现有画布一致）。
- 已选中标签页外的字段，或点画布空白（未点在标签页上）：加到整表，规则与现在相同。
- 再加一个标签页（点清单或拖入）：拦截并提示「每个表单只能有一个标签页」。
- 现有字段只在**当前 pane 的 `fields`** 里拖排序。

拖入标签页时，内部字段用与主表相同的默认属性（含尚未做完的类型）。不在标签页里单独禁子表单。

### 标签页字段属性

不展示必填、占位、宽度等填报项。只管理 pane 列表：

- 改标题：最多 32 字，不能为空，保存时 trim；允许不同 pane 重名。
- 添加：末尾增加一个 pane。标题「标签页N」，N 取现有标题中的数字最大值 + 1，没有数字则用个数 + 1。满 10 个时添加禁用。
- 拖动列表项左侧排序图标改 `panes` 顺序（不要整行拖）；画布页签顺序跟着变。活动 pane 被拖走后仍跟其 `id`。
- 删除：二次确认，说明会删除该分组及内部全部字段。只剩 2 个时删除禁用（避免只剩一个分组却还占着标签页）。删的是当前活动 pane 时，活动 tab 落到相邻 pane（优先右侧，否则左侧）。

### 删除整个标签页组件

走画布现有删除（已有 `ElMessageBox.confirm`）。确认后去掉该组件，所有 pane 及内部字段一并删除。

## 5. 填报、预览、校验、列表

### 预览

设计器顶栏「预览」目前是字段 JSON，不是填表界面。`panes` 会出现在 JSON 里，不必在该弹窗做页签切换。

### 填报 / 详情

`FormFillGrid` 按 `fields` 顺序渲染：遇到 `tabs` 画页签，内容区只显示当前 pane 的字段；标签页外的字段仍在组件前/后。

- 默认第一个 pane；切换只存在本次打开，不写进记录。
- `values` 仍按字段 `key` 存在同一层。未打开 pane 里已填的值保留。
- 联动、选择数据、选项过滤使用 `flattenFields` 后的字段列表，允许跨 tab 取值/赋值。

### 校验

提交时对摊平后的字段做现有必填等校验，包含未打开的 pane。标签页自己没有必填。若第一条错误落在某个 pane：自动切到该 pane，提示文案仍是「请填写「某某」」。列表单元格编辑只校验那一个字段，与现在相同。

### 列表

摊平后再 `isFillable`。列顺序与 flatten 顺序一致。没有「标签页」列。

## 6. 后端

- coerce：`tabs` 不写 `data`；对其它字段仍按摊平后的 schema 校验类型。
- 索引、导入字段：`tabs` 加入与 `divider` 同类的跳过集合，但先 flatten 再过滤，以便导入到 pane 内的普通字段。
- `listFormFields`：先 flatten，再转成可供他表选择的字段列表。

## 7. 主要改动面

- 新增 `flattenFields` / 默认 panes /「只能有一个标签页」等纯函数及单元测试。
- `FormDesignPanel`：投放目标（根 vs 当前 pane）、第二个标签页拦截、删除 pane / 删除组件时改嵌套 schema。
- `FormDesignCanvas` / `FormDesignCanvasField`：页签 + 当前 pane 字段；pane 内拖排序与投放。
- `FormDesignProps`：pane 列表（改标题、拖排序、添加、删除确认）。
- `FormFillGrid`：页签展示；`fillValues` 将 `tabs` 列入布局跳过，empty / validate / build 走 flatten。
- 列表、快捷搜索、联动与选择数据的字段遍历：改 flatten。
- 后端 coerce / 索引 / 导入 / `listFormFields`：flatten + 跳过 `tabs`。

联动、选择数据**不做**「只能同 tab」「只填当前 tab」等限制。

## 8. 与子表单分支的衔接

标签页在 `master`（或本功能合入的主干）实现；子表单在另一分支。两边都完成后，先合标签页，再合子表单，再做联调，而不是在标签页期内实现子表。

联调时至少确认：

1. `flattenFields` 只展开 `tabs.panes[].fields`，把整个 `subform` 当作一个主表字段，不展开 `subform.fields`。
2. pane 内可以拖入/点选添加子表单；画布与填报沿用子表单分支的控件。
3. 删除 pane 时，其中的子表单字段与其它字段一起从 schema 去掉。
4. 列表：子表单列按子表单分支的规则（摘要或隐藏），不因包在 tab 里而丢失或变成多列明细。

## 9. 测试要点

- flatten 顺序：标签页前 → 各 pane → 标签页后；`data` 无标签页自己的 key。
- 不能添加第二个标签页；只剩 2 个 pane 不能删；删 pane 后内部字段从 schema 消失。
- 选中标签页时点清单进当前 pane；选中外面字段时加到根上。
- 未打开 pane 的必填拦住提交，并切到该 pane。
- 列表列来自摊平后的填报字段，没有「标签页」列。
- flatten 遇到 `subform` 时只保留该字段本身（为合并后联调做准备，可用夹具字段测）。
