# 流水号生成设计

日期：2026-08-31  
状态：待确认  
范围：主表字段 `type: 'serialNumber'` 的设计配置、新增保存时由后端按规则生成、填报只读展示。不包含前端预览真实号段、子表单内流水号、跨表共用一个计数器。生成后手改见第 1 节记录点，本期不做。

对照：一张表只能有一个，做法对齐标签页。值在调用创建记录接口时由后端写入，不由填报人填写。规则段里的「表单字段联动」只取**本表当前这条记录**上单行文本 / 数字的值拼进号码，不去他表查，也不是数据联动。

## 1. 需求核对（原描述 → 补齐）

| 原描述 | 判定 | 本期怎么定 |
|---|---|---|
| 每个表单只能有一个流水号组件 | 清楚 | 设计器点/拖第二份时提示并拒绝；保存表单 schema 时后端也拦。可以放在标签页某个 pane 里，整表仍只算一个 |
| 新增数据时，调用保存接口以后由后台按规则生成 | 清楚 | 只在 **创建记录** 时生成。更新记录不重算、不覆盖。请求体里即便带了该字段也丢掉 |
| 右侧字段属性里设置流水号规则 | 清楚 | 规则是有序列表，每段一种类型；另有全局分隔符 |
| 规则支持：固定字符、日期时间、自动计数、表单字段联动 | 清楚 | 四类可混用。固定字符、日期、字段引用可各有多段；自动计数 0 段或 1 段（不能两段） |
| 输入框填写字符作为固定字符 | 清楚 | 原样拼进流水号，不做转义 |
| 日期时间预置格式：2025、202508、20250823、20250823102035、时间戳 | 清楚 | `20250823102035` 是年月日时分秒。另有 **毫秒时间戳**。取值用服务器生成时刻（不是填报打开时刻）。日历格式时区 `Asia/Shanghai`；毫秒时间戳与时区无关 |
| 自动计数：起始值、计数位数；默认起始 1、位数 5；可重置，周期天/周/月/季度/年 | 清楚 | 可选。没有计数段也能保存表单、也能新增数据。有计数时位数不够左侧补 0；超出位数仍输出完整数字，不截断、不报错 |
| 表单字段联动只支持主表单行文本、数字 | 清楚 | 只读当前提交值。下拉来自 `flattenFields` 后 `type` 为 `input` / `number` 的字段（含标签页内部）。不进子表单列，不去他表 |
| 几种规则类型不分顺序，可随意配置 | 清楚 | 按列表顺序取出各段内容，再用分隔符拼起来 |
| 设置好的选项可以拖动排序、删除 | 清楚 | 属性面板里拖手柄排序，每段可删 |
| （补）分隔符 | 已确认 | 输入框，`trim` 后为空则各段直接相连；默认 `-` |
| （补）生成后能否手改 | 已记录，本期不做 | 见下方「记录点」 |

本期不做：设计器里预生成「下一个真实号」、导入时由 Excel 列指定流水号、按流水号单元格内联编辑、多个自动计数段、子表单流水号、跨表共享计数器、按规则预览接口、秒级时间戳。生成后手改见「记录点」，不要在本期顺手做。

### 记录点：生成后手动修改

**本期：不能改。** 创建时由后端写入，填报只读；更新请求里带了该字段也丢掉。

已知有极个别业务需要生成后再改号（补录、作废重开、对接外部编号等）。那是明确的后续需求，不是本期缺口。下次要做时单独开，至少要定：谁能改、改完是否还占原序号、是否查重、属性里要不要「允许修改」开关。未单独立项前，不要把「是否可修改」加回流水号属性面板。

## 2. 和现有能力怎么区分

| 能力 | 干什么 | 库里存什么 |
|---|---|---|
| 登录人姓名 / 登录人部门 | 只读展示当前登录者 | 不入库 |
| 数据联动 | 条件变化后从**他表**写入当前字段 | 当前字段自己的值 |
| 流水号「表单字段联动」 | 生成时把**本条记录**某文本/数字字段的值拼进号码 | 拼进流水号字符串 |
| 不允许重复值（文本/数字） | 用户填的值查重 | 用户填的值 |
| 流水号 | 创建时系统生成业务编号 | 一条字符串。本期创建后不可改；手改见「记录点」 |

## 3. 字段配置

公共项只留：标题、占位、宽度、tips。

不提供：必填、禁用、可修改、不允许重复值。流水号不是人填的：填报始终只读。本期创建后不可改（手改需求已记录，见第 1 节记录点）。有自动计数时靠计数器避免撞号；没有计数时**不保证唯一**，也不为此自动加「不允许重复值」。占位默认「保存后自动生成」。

拖入时的默认规则：分隔符 `-`；一段当天日期 `YYYYMMDD` + 一段自动计数（起始 1、位数 5、不重置）。预览形如 `20260831-00001`。用户可以删掉计数段，只留日期或毫秒时间戳。

```json
{
  "type": "serialNumber",
  "placeholder": "保存后自动生成",
  "serialSeparator": "-",
  "serialRule": [
    { "id": "s1", "kind": "datetime", "format": "YYYYMMDD" },
    {
      "id": "s2",
      "kind": "counter",
      "start": 1,
      "digits": 5,
      "reset": false
    }
  ]
}
```

`serialRule` 是有序数组。`id` 只给前端拖排序用，生成时不读。保存表单时至少要有一段规则（四种任一即可），否则 400，提示「请配置流水号规则」。没有 `counter` 是合法的。

`serialSeparator`：字符串，默认 `"-"`。保存和生成前都 `trim`；trim 后为空则各段之间不加分隔符。最长 8 个字符，允许空格以外的常见符号（trim 后中间若有空格则保留，例如 ` - ` 先 trim 成 `-`）。

### 3.1 规则段

| `kind` | 配置 | 拼进号码的内容 |
|---|---|---|
| `fixed` | `text` 字符串，最长 32，允许空格和符号，不允许换行 | 原样。空字符串等于这段不输出 |
| `datetime` | `format` 见下表 | 按格式格式化生成时刻 |
| `counter` | `start` 整数，默认 1，最小 0；`digits` 整数，默认 5，范围 1～12；`reset` 布尔，默认 false；`resetPeriod` 仅 `reset === true` 时有效：`day` / `week` / `month` / `quarter` / `year` | 当前序号，左侧补 0 到 `digits` 位；超过位数不截断 |
| `field` | `fieldKey` 指向本表一个 `input` 或 `number` 字段 | **本次提交里该字段已经 coerce 过的值**，转成字符串。不去别的表、不另查库。空则这段不输出。数字 `0` 输出 `"0"`；小数按提交的数字转字符串（`1.5` → `"1.5"`） |

日期时间 `format`：

| 选项文案示例 | `format` | 输出例（上海时间 2026-08-31 16:22:05.123） |
|---|---|---|
| 2025 | `YYYY` | `2026` |
| 202508 | `YYYYMM` | `202608` |
| 20250823 | `YYYYMMDD` | `20260831` |
| 20250823102035 | `YYYYMMDDHHmmss` | `20260831162205` |
| 毫秒时间戳 | `epochMs` | `1756623725123`（13 位，Unix 毫秒，与时区无关） |

前四项按上海时区格式化日历/时钟。`YYYYMMDDHHmmss` 不含毫秒。毫秒时间戳单独一项，不要做成秒级。

自动计数整条规则里最多一段：没有时可以加；已有时「添加」下拉里的「自动计数」不可选；删掉后可以再加。**没有计数段也能保存表单、也能创建记录。** 没有计数时，同一规则在同一时刻可能生成相同字符串（尤其只用日期、不用毫秒时间戳时），产品接受，后端不因此拒绝保存。

字段引用：`fieldKey` 在生成时找不到、或类型已不是 `input`/`number`，这段当空。设计器下拉只列出当前仍合法的字段；已失效的 key 仍留在规则里，面板上该段标红「字段已删除」。

### 3.2 属性面板

紧挨标题 / 占位 / 说明，不要用 `el-space`：

1. 分隔符：一行输入框，默认 `-`，提示「各段之间的连接符，留空则直接相连」。
2. 规则列表：每段一行，左侧排序图标、中间该段摘要（固定字符显示文本，日期显示格式名，计数显示「起始 n / n 位 / 不重置|按天重置」等，字段显示被引用字段标题）、右侧删除。只拖左侧排序图标改顺序，不要整行拖。
3. 列表下方一个「添加」按钮。点击后下拉列出四类：固定字符、日期时间、自动计数、表单字段。选中一项后在末尾追加一段并打开弹框配置。已有计数段时，「自动计数」禁用。
4. 点规则行也会打开该段弹框。固定字符用输入框；日期时间用预置格式下拉（含毫秒时间戳）；自动计数为起始值、位数、是否重置、重置周期；表单字段用下拉（本表单行文本、数字）。这些详细项不铺在属性面板上。

画布和填报：只读输入框。未生成时显示占位；已有值显示完整字符串。

## 4. 值形状

入库是一条字符串，例如 `"PO-20260831-00001"`。

- 创建：后端生成后写入 `data[fieldKey]`。客户端创建请求不要带这个 key；带了也忽略。
- 更新：`mergeRecordData` 不接受客户端改这个 key；已有值保持。
- `coerce`：创建路径不把客户端值当最终值；更新路径若出现该 key 则丢掉。读出来必须是字符串。
- 若所有段都空（例如只引用了空文本字段），写入空字符串；列表按空展示。有日期或计数时正常会有内容。

## 5. 何时生成

| 动作 | 行为 |
|---|---|
| 新增保存 | 校验完其它字段、唯一值之后，按当前规则生成，写入后再插入 Mongo |
| 编辑保存 | 不重算，也不接受客户端改号（手改见记录点，本期不做） |
| 删除记录 | 不回收序号；有计数器时只增不减 |
| Excel 导入每一行 | 与新增相同：按该行已解析的文本/数字字段生成流水号。模板不含流水号列（`IMPORT_SKIP_TYPES` 加入 `serialNumber`） |
| 复制记录 | 设计器无字段复制入口；以后若恢复复制，视为新增，生成新号 |

填报新增：控件只读，显示占位。保存成功后接口返回的 `data` 里带上号，列表/详情能直接显示。不要为了拿号再打一次详情。

## 6. 自动计数与并发

没有 `counter` 段时：不碰计数表，只按其它段拼接。

有 `counter` 段时：计数器按「一张表的这一个流水号字段 + 重置周期桶」隔离，存在 MySQL，用行级自增，避免两个人同一瞬间拿到同一个序号。

周期桶 `periodKey`（上海时区）：

| 重置 | `periodKey` 例 |
|---|---|
| 不重置 | `all` |
| 天 | `2026-08-31` |
| 周 | `2026-W36`（ISO 周，周一起算） |
| 月 | `2026-08` |
| 季度 | `2026-Q3` |
| 年 | `2026` |

新桶第一次取值等于 `start`；之后每次创建 `+1`。改规则时：

- 只改位数：下一个号按新位数补 0，序号接着走。
- 只改起始值：当前桶已有计数则 `下一个 = max(已有下一个, 新 start)`，避免改小起始值撞号。
- 打开/关掉重置或改周期：新桶从 `start` 开始；旧桶不再使用。
- 已生成的历史号码不回写。

删除记录、导入失败导致 Mongo 没写上：序号照样消耗，允许跳号，不允许因计数器重号。

表结构意向（实现时再落 entity）：

```text
form_serial_seq
  formId
  fieldKey
  periodKey
  nextValue
  唯一 (formId, fieldKey, periodKey)
```

## 7. 拼接顺序（生成算法）

对 `serialRule` 从左到右算出每段字符串：

1. `fixed` → `text`（空则跳过）
2. `datetime` → 按 `format` 格式化「此刻」；`epochMs` 为 `Date.now()` 的十进制字符串
3. `counter` → 先占用下一个序号再格式化（先占号再插入记录）；没有计数段则跳过
4. `field` → 取本次创建已经 coerce 过的 `data[fieldKey]`，不另查表；文本缺省跳过；数字用 `String(n)`（不要科学计数法）

得到非空片段数组 `parts`，`sep = (serialSeparator || '').trim()`，结果为 `parts.join(sep)`。空片段不参与 join，避免出现 `PO--00001`。

引用字段若在标签页未打开的 pane 里，只要提交数据里有值就拼进去（对齐标签页：未打开 pane 仍提交）。

## 8. 一张表一个

对齐标签页：

- 设计器：已有 `serialNumber`（含标签页内部）时再点/拖，提示「每个表单只能有一个流水号」并拒绝。
- 保存 schema：摊平后 `serialNumber` 多于一个则 400。
- 规则至少一段；`counter` 至多一段。没有计数合法。
- 不进子表单。子表单尚未完成；即便以后能把字段拖进子表，流水号也不允许放进子表列。

## 9. 列表、筛选、导入、联动

- 列表显示完整字符串，不可单元格内联编辑。
- 加入 `FILTERABLE_TYPES`，按字符串筛（与单行文本相同的操作符），建 `data.*` 索引。不自动建唯一索引。
- 导入跳过该列，导入每一行仍由后端生成。
- 不做数据联动取值来源。`LINKAGE_VALUE_TYPES` 不加 `serialNumber`。联动配置里流水号只出现在「源表已有字段」（选他表字段）里，不出现在当前表触发字段、也不作为当前表被写入的目标——流水号在保存后才有值，填报过程中是空的。

## 10. 验收

1. 调色板能拖「流水号生成」；一表拖第二个会提示并失败。
2. 属性里能加/删/拖四类规则段；自动计数第二段加不进去；能删掉计数段并保存表单。
3. 默认规则新增保存后号码形如 `20260831-00001`（分隔符 `-`）；同一张表连建两条且带计数时，序号 +1。
4. 分隔符改成空后保存，新记录各段直接相连（如 `2026083100001`）；改成 `/` 则如 `20260831/00001`。
5. 编辑其它字段再保存，流水号不变。
6. 打开重置=天，跨自然日（上海时间）新建，序号从起始值再来；同一天接着加。
7. 规则引用本表单行文本时，号码里能看到该字段**当前提交值**；文本为空时该段不出现、也不多出一个分隔符。
8. 日期格式可选 `YYYYMMDDHHmmss` 和毫秒时间戳；前者是日历时钟，后者是 13 位数字。
9. 没有自动计数段时，保存表单成功，新增也能成功。
10. 有自动计数时，两个请求几乎同时创建，序号不重复。
11. 填报新增时控件只读，显示占位；不能改已有记录上的号。
12. 导入不含流水号列，导入后每行有号。

## 11. 实现时建议拆分

1. 字段类型、属性面板规则编辑（含分隔符、毫秒时间戳）、一表一个。
2. 创建记录时按规则拼接写入；有计数才碰 MySQL 计数表；更新忽略该字段。
3. 重置周期、字段引用、导入生成。
4. 列表筛选索引；有计数时的并发测试。
