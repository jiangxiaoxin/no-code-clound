# 关联数据设计

日期：2026-08-27  
状态：待确认  
参考：简道云 [关联数据](https://hc.jiandaoyun.com/doc/18113)、[字段使用方式](https://hc.jiandaoyun.com/doc/18607)、[关联数据与选择数据的区别](https://hc.jiandaoyun.com/doc/18699)  
范围：主表字段 `type: 'relate'` 的设计配置与填报。存主表记录 id，按配置字段实时显示。不包含关联子表单、关联标签页、跨应用、聚合表。

## 1. 背景与目标

简道云的关联数据：在当前表（关联表）里选另一张表（主表）的一条已有记录，**把主表记录的数据 id 存下来**，两边建立起实质关系。主表记录改名后，关联表刷新就能看到新名字；详情里可以跳到源数据。

两种用法：

| 用法 | 主表选什么 | 典型场景 |
|---|---|---|
| 关联他表 | 本应用另一张已保存表单 | 联系人指向客户；一个客户对应多个联系人 |
| 关联本表 | 当前表单自己 | 绩效目标、组织层级；只连相邻两层，拼成树 |

本项目调色板已有 `{ type: 'relate', label: '关联数据' }`，存储设计也已把 `relate` 定为字符串（对方记录 id）并允许按该列筛选。画布和填报目前是禁用空下拉，没有选表、选记录、显示标题。

README 对本期的要求：

1. 记录真实数据 id；显示哪个字段；源表改了值，刷新后跟着变。
2. 弹框 + table 选记录；要能配置表格展示哪些列。
3. 能把当前表单选成主表，用来测树。

本期目标：把 `relate` 做成真正的关系字段，选记录交互尽量复用已有「选择数据」，但语义和选择数据分开，不要把选择数据升级成关联。

## 2. 和现有能力怎么区分

| 能力 | 人选什么 | 库里存什么 | 源表改了历史数据 |
|---|---|---|---|
| 下拉「其他表数据」 | 他表某字段的值 | 字段文本 / 数字，不是记录 id | 已提交的值不跟着改 |
| 数据联动 `optionSource: 'linkage'` | 人不选行，条件一变系统自己查 | 当前字段自己的值 | 已提交的值不跟着改 |
| 选择数据 `data` | 弹窗选一条，再按规则拷贝到其他字段 | 当前字段存源记录 id，**只为回显选中行**；被填充字段存拷贝值 | 控件回显会按 id 再查，所以标题能跟上；**填充出去的值不会跟上** |
| 关联数据 `relate` | 弹窗选一条，建立关系 | 当前字段存主表记录 id，**表示关系** | 控件和列表都按 id 再查标题，源表改名刷新即跟进；填充出去的值同样不跟上 |

选择数据已经会把源记录 id 存进 Mongo，打开时再 `getFormRecord` 回显。看起来和关联数据很像，但产品约定不同：

- 选择数据：**挑一行来拷贝**。id 只服务于本控件回显，不表示两表关系，主表详情不会因此出现「被谁关联」。
- 关联数据：**指向那一行**。id 就是关系。本期先把正向关系做对（选、存、显、跳转）；主表详情里反向查看（关联标签页）另立项。

两套配置可以长得很像，实现上复用弹窗表格、过程设置、填充规则弹框。字段 `type` 必须分开，不要合并。

## 3. 本期边界

### 本期做

- 字段类型 `relate`：属性里选主表（本应用已保存表单，**或当前表单**）。
- 填报弹窗选 **一条** 主表记录；可配弹窗表格列、过滤条件、快捷搜索、分页。
- 必选一个主表字段作为 **显示字段**（控件收起态、数据管理列标题）。
- 可选「显示在表单中的字段」：选中后在控件下方卡片展示，**不入库**。
- 可选填充规则：把主表字段值拷到当前表已有字段（不自动新建字段）。
- 库里 `data[relateKey]` = 主表记录 id 字符串。
- 打开填报 / 刷新 / 数据管理列表时，按 id 再查主表，显示配置的显示字段；源表改了标题，这边跟着变。
- 详情只读时，点击显示文本可打开主表那条记录的详情。
- 关联本表：选记录时排除当前正在编辑的记录，禁止自关联。
- 画布：未选主表提示「请选择主表」；已选则用选择数据同款占位（`preview`，不发查询）。

### 本期不做

| 项 | 原因 |
|---|---|
| 主表详情「关联标签页」 | 简道云会在主表自动生成反向列表；要扫「谁指向我」，另立项 |
| 关联子表单 `relate-subform` | 调色板已占位，是「一条主表记录带多行从表」，不是本字段 |
| 主表关联数据多选 | 简道云主表关联数据选一条；多条走关联子表。README 未把多选列为关联数据本期项 |
| 拖进子表单 | 简道云不允许；本项目子表单也未做 |
| 跨应用、聚合表 | 与选择数据、数据联动同一限制 |
| 填报弹窗里「允许新增主表数据」 | 选择数据也还没有对等能力 |
| 填充到新字段（自动在当前表建字段） | 只填充到已有字段 |
| 主表改值后同步已填充字段 | 填充是拷贝，与选择数据相同 |
| 删除主表记录时级联清空 / 级联删除关联表 | 本期源记录 404 则显示「已删除」，id 仍留着直到人清掉 |
| 简道云数量上限（每表 50 个关联字段等） | 不设配额 |
| 导入时按标题匹配关联、智能助手 | 导入若带该列，只接受记录 id 字符串；匹配标题另说 |
| 把选择数据改成真关联 | 两者并存 |

## 4. 核心决策

### 4.1 只选一条

主表上的关联数据字段本期只关联 **一条** 主表记录。Mongo 里是字符串，不是数组。这与存储设计、简道云主表关联数据一致。

多条关系用后续「关联子表单」，不要在 `relate` 上做 `multiple`。

### 4.2 主表可以是当前表单

`FormSourcePicker` 已有 `includeCurrent`。关联数据选主表时打开它（`includeCurrent: true`）。选择数据继续排除当前表。

「当前表单」出现在列表里时，主表字段列表用 **当前画布 `fields`**（设计中途改字段也能配显示字段 / 填充），不必等保存。运行时查记录仍走当前 `formId` 的 Mongo 集合。

一张表 **最多一个** `sourceFormId === 当前 formId` 的关联数据字段。再拖一个关联本表时提示「已有关联本表字段」，不写入。关联他表数量不限制。

关联本表只表达相邻两层（子指向父）。更深的树靠多条记录各自指向自己的父节点，不在控件里选「爷节点」。

### 4.3 显示字段跟 id 走，填充不跟

- **显示字段 / 卡片字段**：每次打开按 id 查主表当前值。这是 README「字段的值随便改，刷新后立马跟进」的范围。
- **填充规则**：选中时把当时的值拷到目标字段。之后主表改了，已写入的目标字段不变。被填充字段标题前的「会受 xxx 字段影响」要把 `relate` 算进去（现有 `fillInfluencerTips` 只扫了 `data`）。

### 4.4 设计期允许改主表

简道云选完主表并保存表单后不能再改主表。本项目没有独立的关系注册表，设计器与选择数据一样：允许改主表；一切换就清空 `titleKey`、`displayFieldKeys`、`fillMappings`、`pickerColumnKeys`、`optionFilters`。已有填报数据时，旧 id 可能对不上新主表，列表会显示失败或「已删除」。不在后端做外键校验，也不锁定属性面板。

### 4.5 不新增专用关联接口

选记录、回显、列表补标题都走现有：

- `POST .../records/query` 弹窗列表、数据管理补标题
- `GET .../records/:id` 回显单条、跳转详情

关联本表排除自己：查询增加可选 `excludeIds`（字符串数组）。只用于「当前这条不要出现在可选列表」。没有该参数时行为与现在完全一样。

### 4.6 列表展示标题、筛选仍按 id

`relate` 已在可筛类型里，筛选 `eq` 的是存进去的记录 id。本期数据管理该列 **展示** 显示字段的文本（本页记录的 id 去主表批量查），**筛选 / 排序** 仍按 id。按标题模糊搜关联列登记后续。

批量查标题：收集本页非空 id，对主表 `query`（或逐条 `get`，页大小最大 100，优先一次 query）。查不到的显示「已删除」。

## 5. 字段 JSON

在现有字段对象上增加 / 复用这些键（仅 `type === 'relate'` 有意义）：

```json
{
  "type": "relate",
  "key": "…",
  "title": "客户",
  "sourceFormId": 12,
  "titleKey": "客户名称字段key",
  "displayFieldKeys": ["客户名称字段key", "手机"],
  "displayFieldLabels": { "客户名称字段key": "客户名称" },
  "fillMappings": [{ "sourceKey": "地址", "targetKey": "联系地址" }],
  "pickerColumnKeys": ["客户名称字段key", "手机"],
  "optionFilters": null
}
```

| 键 | 含义 |
|---|---|
| `sourceFormId` | 主表 `app_form.id`。等于当前 `formId` 即关联本表 |
| `titleKey` | 主表字段 key，控件收起态和数据管理列用它。必选（选了主表之后） |
| `displayFieldKeys` / `displayFieldLabels` | 卡片展示，不入库。可与 `titleKey` 重复 |
| `fillMappings` | 与选择数据相同：`sourceKey` → 当前表 `targetKey` |
| `pickerColumnKeys` | 弹窗表格列。空则按选择数据现有默认（能展示的源表字段） |
| `optionFilters` | 弹窗默认过滤，复用选择数据的条件结构 |

未选 `sourceFormId` 视为未配置，填报只显示「请选择主表」，不弹窗、不查询。  
选了主表但未选 `titleKey`：弹窗仍可选记录；收起态和列表没有标题时显示 id 或「—」。属性面板要提示去选显示字段。

`titleKey`、卡片、填充、过程列用的源字段范围与选择数据一致（可展示的填报字段 + 创建人 / 创建时间 / 更新人 / 更新时间）。分割线、图片、文件、子表单、选择数据、关联数据不出现在这些选择器里。

运行时入库仍按存储设计：`data` / `relate` → 字符串；空值不写该 key。

## 6. 设计器交互

选中关联数据字段后，属性区在公共项（标题、占位、必填、宽度、tips、禁用、可修改）之下：

1. **数据源**（主表）：`FormSourcePicker`，`includeCurrent`。占位「请选择表单」。
2. 已选主表后出现：
   - **显示字段**：一个主表字段（单选）。这是 README 的「显示哪个字段」。
   - **显示在表单中的字段**：复用 `DataSelectDisplayFieldsDialog`（多选，卡片）。
   - **填充到表单中的字段**：复用 `DataSelectFillMappingDialog`。
   - **选择过程设置**：复用 `DataSelectProcessDrawer`（表格列 + 过滤）。

切换主表时清空上面四项附属配置，与选择数据切表相同。

画布：

- 无 `sourceFormId`：标题下提示「请选择主表」。
- 有 `sourceFormId`：用与 `FormDataSelect` 相同的收起态占位（`preview`），下方若已配卡片字段可出示例行，不请求接口。

关联数据 **没有**「数据源 = 数据联动 / 字典」这一层。它自己就是选表 + 选记录。

## 7. 运行时

### 7.1 填报控件

不要用原生 `el-select`。交互对齐 `FormDataSelect`：

- 收起：显示主表记录 `titleKey` 的当前值；未选显示占位符。
- 点击：`el-dialog` 表格选一条，确定后写入 id，并按 `fillMappings` `emit('fill')`。
- 下方卡片：按 `displayFieldKeys` 展示，不写入 `data`。
- 快捷搜索、分页、过滤条件：与选择数据相同；过滤条件里引用的当前表单字段变了要重查弹窗列表。
- 禁用：不能打开弹窗。不可修改：新增可选手；编辑已有记录时锁住（与现有「是否可修改」一致）。
- 清空：允许清空（非必填时）；清空后去掉 id，不自动清已被填充的其他字段。

实现上优先扩展 `FormDataSelect`（例如增加 `mode: 'data' | 'relate'`、`includeCurrent`、`excludeRecordId`、`titleKey`），或抽公共弹窗表格再包一层 `FormRelateData`。不要复制一份几乎相同的弹窗。

### 7.2 回显与跟进

`modelValue` 是 id 字符串。有 id 就 `getFormRecord(appId, sourceFormId, id)`。

| 结果 | 收起态 | 卡片 |
|---|---|---|
| 查到 | `titleKey` 格式化文本 | 各展示字段当前值 |
| 404 / 无权限 | 「已删除」 | 不展示或全部为 — |
| 主表字段被删（`titleKey` 不存在） | 退回显示 id | 缺的列显示 — |

这就是「源表改名，刷新跟进」：跟进的是 **再查到的标题**，不是改 Mongo 里存的 id。

### 7.3 关联本表

弹窗查询当前表记录时传入 `excludeIds: [当前记录 id]`。新建（还没有 id）不传。任意记录不能把自己选成父节点。

不在提交时做环检测（A→B→A）。本期只禁自关联；成环树的展示等关联标签页 / 树视图再做。

### 7.4 跳转源数据

详情抽屉只读、或数据管理点开只读时：点击关联数据的显示文本，打开主表该条的数据详情（复用 `FormRecordDetailDrawer`，换成主表 `formId` + 该 id）。编辑态点击仍打开选记录弹窗，不跳转。

打不开（已删除、无权限）时 `el-message` 说明，不跳。

### 7.5 数据管理

该列展示标题文本，单元格不可内联编辑（与选择数据一致，避免表格里再开选记录）。详情 / 新增 / 编辑表单里才选。

导入：该列按记录 id 字符串写入；不按显示文本匹配。格式不对的行按现有导入规则丢弃。

### 7.6 `fillValues`

`relate` 与 `data` 一样属于「控件自己要持久化、但不是普通填报输入」：

- `emptyRecordValues` / `cloneRecordValues` 要拷贝 `relate` 的 id 字符串。
- 被填充的目标字段仍走现有 fill 补丁，不改目标字段类型。

## 8. 验收场景

1. **关联他表改名跟进**  
   联系人表关联客户表，显示字段 = 客户名称。客户「甲」改名为「甲公司」。打开原联系人（刷新或再进详情），关联数据上看到「甲公司」。库里仍是原来的客户记录 id。该联系人上被填充的「客户地址」如果当时拷过，不随客户改地址而变。

2. **弹窗列可配**  
   过程设置勾选客户名称、手机。填报打开选记录弹窗，表格只有这些列 + 序号 / 选择列。快捷搜索、分页可用。

3. **卡片不入库**  
   配置卡片展示「手机」。选中客户后控件下显示手机号。提交后 Mongo 的 `data` 只有关联字段的 id，没有手机副本（除非另做了填充规则）。

4. **关联本表树、禁自关联**  
   同一张「目标」表，关联数据主表选自己。先录「年度目标」（关联留空）。再录「上半年」，弹窗能选到「年度目标」，不能选到正在编辑的自己。保存后上半年的关联字段存年度目标的 id，显示年度目标的标题。

5. **未配主表**  
   画布和填报提示「请选择主表」，点控件不弹窗。

6. **源记录删除**  
   删掉被关联的客户。联系人仍在，关联列显示「已删除」，id 还在。人可以清空或改选别的客户。

7. **与选择数据并存**  
   同一张表可以同时有选择数据和关联数据，指向同一张或不同主表。选择数据改不了关联数据的关系，也不会在主表产生标签页（本期本来就没有标签页）。

8. **列表标题**  
   数据管理联系人表该列看到客户名称，不是 Mongo ObjectId。筛选若使用该列，按 id 精确匹配（有筛选 UI 的前提下）。

## 9. 实现时建议拆分

1. 属性面板：选主表（含当前表）、显示字段、复用三套弹框；画布占位；限制一个关联本表。
2. 填报控件：复用 / 扩展选记录弹窗；存 id；回显标题与卡片；填充；`fillValues` 与影响提示覆盖 `relate`。
3. 关联本表：`includeCurrent` + query `excludeIds`。
4. 数据管理列展示批量补标题；只读跳转详情。

第 1、2 步没有 3、4 也能先测「他表选一条、刷新跟进」。树和列表标题放后面。
