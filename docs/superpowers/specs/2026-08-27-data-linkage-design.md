# 数据联动设计

日期：2026-08-27  
状态：已确认  
参考：简道云 [数据联动](https://hc.jiandaoyun.com/doc/9027)、[数据联动规则](https://hc.jiandaoyun.com/doc/9028)  
范围：字段属性里把「数据联动」收进统一的来源设置（文本等用「取值来源」，下拉用「选项来源」）；设计期配置与运行时按条件从他表取值。不包含公式、AI 填充、跨应用、聚合表。

## 1. 背景与目标

简道云的数据联动：在当前表单里，按条件去另一张表查已有数据，把匹配记录上的某个字段填到当前字段，或作为当前字段的可选项。

本项目里已经有几块容易和它搞混：

| 现有能力 | 干什么 | 库里存什么 |
|---|---|---|
| 数据源「系统字典表」 | 固定选项 | 字典项的 value |
| 数据源「其他表数据」+ 选项过滤 | 他表某字段的去重值当选项，人来选 | 选中的字段值（不是他表记录 id） |
| 选择数据 + 填充规则 | 人先选他表一条记录，再按规则拷贝多个字段 | 当前字段存源记录 id；被填充的字段存拷贝值 |

数据联动要补的是：**人不选行**。填了条件字段之后，系统自己去他表匹配，把结果写到当前字段（或变成当前字段的选项）。典型场景：奖金表输入员工编号，自动带出姓名、手机、部门。

本期目标：

1. 所有支持联动的字段，都在「取值来源」或「选项来源」里选择「数据联动」，不再另开「默认值 / 选项」两套入口。选择数据组件仍用自己的「数据源」。
2. 配置弹框复用现有「选表」和「过滤条件」交互。
3. 未实现的组件只在文档里登记，等组件本身做完再开联动。

## 2. 本期边界

### 本期可设计、可实现的字段

这些字段已经能填报、能入库，来源下拉可以加「数据联动」：

- 单行文本 `input`
- 多行文本 `textarea`
- 数字 `number`
- 日期 `date`、时间 `time`、日期时间 `datetime`
- 下拉单选 `select`、下拉多选 `select-multiple`
- 图片 `image`、文件 `file`

单选 `radio`、复选 `checkbox` **不做数据联动**，继续只用系统字典，也不为此补取值/选项来源这一层。

### 只登记、本次不开发

组件本身还没做完，数据联动入口先不出现：

| 组件 | 原因 |
|---|---|
| 成员 `member`、部门 `dept` | 控件未完成 |
| 子表单 `subform` | 控件未完成；简道云还有「子表单整体联动」（一次填多行），等子表单后再单独立项 |
| 关联数据 `relate` | 控件未完成 |
| 地址、定位、流水号、手机、OCR | 项目里没有对应组件 |
| 选择数据 `data` | 用自己的「数据源」+ 填充规则，不走数据联动 |
| 单选 `radio`、复选 `checkbox` | 继续只用系统字典，不提供数据联动 |
| 当前登录人 `currentUser`、分割线 `divider` | 不是填报字段 |

多级下拉（省 → 市 → 型号）简道云既可以用数据联动，也可以用「关联其他表数据 + 选项过滤」。本项目后一种已经有了，**级联选项优先继续用「其他表数据 + 选项过滤」**。数据联动主攻「条件成立后给当前字段取值」。

## 3. 核心决策

### 3.1 统一放在取值来源 / 选项来源

不再按简道云拆成「默认值里设联动」和「选项里设联动」。本项目所有相关字段都只有一个 `optionSource` 下拉，面板标题按类型区分：

| 字段 | 面板标题 | 选项 |
|---|---|---|
| 单行 / 多行 / 数字 / 日期 / 时间 / 日期时间 / 图片 / 文件 / 地址 | 取值来源 | `custom` 自定义（默认）、`linkage` 数据联动 |
| 下拉单选 / 下拉多选 | 选项来源 | `dictionary` 系统字典表、`table_data` 其他表数据、`linkage` 数据联动 |
| 选择数据 | 数据源 | 选他表，不走数据联动 |
| 单选 / 复选 | — | 无此项，仍为「选项字典」 |

自定义：和现在一样，用户手填，没有额外配置。

选「数据联动」后，下方出现设置按钮：

- 未配置：`设置数据联动`
- 已配置：`已设置数据联动`，右侧有清除图标；点清除要二次确认，确认后删掉联动配置，来源仍停在「数据联动」（按钮回到未配置文案）。

切换来源时，清掉另一套配置（与现在字典 / 其他表互清相同）：切走 `linkage` 时删除 `linkage`；切到 `linkage` 时清 `dictCode`、`sourceFormId`、`sourceFieldKey`、`optionFilters`。

### 3.2 联动配置长什么样

存在当前字段 JSON 上，不单开表：

```json
{
  "optionSource": "linkage",
  "linkage": {
    "sourceFormId": 12,
    "match": "all",
    "conditions": [
      {
        "key": "empNo",
        "op": "eq",
        "valueType": "field",
        "value": "empNo"
      }
    ],
    "sourceKey": "name"
  }
}
```

含义：

1. **联动表单** `sourceFormId`：本应用里另一张已保存表单（或当前表单，允许，便于本表引用）。选表控件复用 `FormSourcePicker`。
2. **联动条件** `match` + `conditions`：形状与现有 `optionFilters` 相同，弹框复用 `FormOptionFilterDialog`。多条之间「所有 / 任一」。条件右侧可以是当前表单字段或自定义值。**至少一条条件**，保存时校验；选了数据联动就不能空着条件。
3. **触发联动** `sourceKey`：联动表里要取哪个字段，填到**当前这个字段**。每条数据联动只服务当前字段；姓名、手机、部门要各配一次，联动表和条件可以相同，只改 `sourceKey`。

条件、触发字段的可选类型与「其他表数据」选字段时一致（可填报的基础字段 + 系统字段创建人 / 创建时间 / 更新人 / 更新时间）。

### 3.3 类型对应（触发字段 vs 当前字段）

除下列放宽外，触发字段类型必须与当前字段相同：

- 单行文本可以对应：单行文本、多行文本、单选、下拉单选
- 多行文本同上
- 下拉单选同上（选项值来自这些字段；城市目录这种「城市」是单行文本的表，才能被下拉字段选到）
- 下拉多选可以对应源表的下拉多选（源表若已有复选框字段，也可以对应）
- 图片只对应图片。表单字段列表接口会返回图片字段，供数据联动触发字段选择；下拉「其他表数据」仍不把图片当选项来源
- 文件只对应文件。列表接口同样返回文件字段；「其他表数据」树里不出现文件
- 日期、时间、日期时间必须各自对应，不混用
- 数字只对应数字

对不上的字段不出现在「触发联动」下拉里。

### 3.4 运行时怎么取值

条件里用到的当前表单字段一变，就重新查联动表（复用记录查询接口，条件组与选项过滤相同）。

查到的结果按字段形态处理：

| 当前字段 | 0 条 | 1 条 | 多条 |
|---|---|---|---|
| 文本 / 数字 / 日期时间 | 清空，不提示 | 写入该条的 `sourceKey` | **不写入**（清空当前字段），并用 `el-message` 提示 `[ 字段标题 ] 字段联动查询出多条数据`；有字段说明时为 `[ 标题，说明 ] 字段联动查询出多条数据` |
| 下拉单选 | 清空选项并清空值 | 选项仅此值并自动选中 | 选项为去重后的 `sourceKey` 值，**不自动选**，等人选；不弹多条提示 |
| 下拉多选 | 同上 | 自动勾上这一个 | 选项为去重后的值，保留仍在结果集里的已选，去掉不在结果集里的；不弹多条提示 |
| 图片 / 文件 | 清空，不提示 | 按 `url` 去重收集后写入 | 按收集到的个数相对 `maxCount` 判断：不超过则写入全部；超过则清空并提示超量，不弹「查询出多条」 |

文本 / 数字 / 日期需要人从多个结果里挑时，应把该字段做成下拉，而不是单行文本。多条提示在每次查询得到多于 1 条时发出（与选项过滤一样，由条件依赖字段变化触发查询）。

入库规则不变：联动写进去的就是字段自己的值（文本、数字、选项 value），**不存联动表记录 id**。源表改了历史数据，已经提交的记录不会跟着改。这和「其他表数据」下拉一样。

禁用字段：联动仍可写入（填报时自动带出、人不点）。  
不可修改：新增时允许联动写入；编辑已有记录时按现有规则锁住，不再被联动改掉。

条件字段还没填全（必填条件的当前字段为空）时，不发查询，当前字段按 0 条处理。

### 3.5 和「其他表数据 + 选项过滤」怎么选

- 只要下拉选项、人来选：选项来源用「其他表数据」，需要级联就加选项过滤。
- 要自动带出（编号带出姓名）：取值来源 / 选项来源用「数据联动」。
- 要先选一行再拷贝多个字段、还要回显那一行：用「选择数据」，不要用数据联动。

## 4. 设计器交互

选中字段 → 取值来源或选项来源选「数据联动」→ 点设置按钮 → `el-dialog`「数据联动设置」（可拖拽），同一页完成：

1. 联动表单（必选）
2. 过滤条件：文案为「联动表单字段满足以下 [所有/任一] 条件时」，条件行直接铺在弹框里（字段、操作符、当前表单字段或自定义值），不必再开一层弹框；至少一条完整条件
3. 触发以下联动：当前表单字段只读 + 「联动显示」+ 联动表字段 + 「的值」

确定时校验：已选联动表、至少一条条件、已选触发字段。不通过不关闭弹框。通过后写入 `field.linkage`。取消不保存。

「已设置数据联动」仅在这三项都齐全时成立。只把来源切到「数据联动」、弹框未保存成功的，仍显示「设置数据联动」。

画布：配了联动的输入框仍显示占位符，不真去查；下拉保持空选项。真实查询只在添加数据 / 编辑记录时发生。

## 5. 运行时落点

- `FormFillGrid` 已能根据过滤条件里引用的当前字段重查下拉选项。数据联动用同一套「依赖字段变化 → 重新查询」的思路，但查询结果是**写当前字段的值**（文本类）或**替换选项**（选择类）。
- 查询仍走 `POST .../records/query`，条件转换复用 `buildSourceQuery` / `mergeFilterQueries`。
- 不新增后端专用联动接口。权限与现有查记录相同。

不在数据管理单元格内联编辑里跑联动（linkage 字段不可单元格编辑），避免表格里连环写入。详情抽屉、新增表单里要跑。

详情只读时不查询、不写值。点「编辑」后若条件字段相对打开时没变，只刷新下拉选项，不改文本 / 数字 / 时间，也不自动改下拉选中值；条件变了才按 0/1/多条写入。这样已提交记录不会因为源表后来改了就被打开详情时覆盖。

## 6. 字段 JSON 约定

`optionSource` 允许值：

- `custom`：仅文本 / 数字 / 时间类
- `dictionary`：选择类
- `table_data`：下拉
- `linkage`：本节

`linkage` 仅在 `optionSource === 'linkage'` 时有意义。未配完（缺 `sourceFormId`、`sourceKey`，或 `conditions` 为空）视为未设置，运行时当自定义空值 / 空选项，也不发查询。

旧字段没有 `optionSource`：

- 选择类继续默认 `dictionary`
- 文本 / 数字 / 时间类视为 `custom`，不必回写

## 7. 明确不做

- 跨应用联动表
- 聚合表、数据工厂输出表
- 公式、AI 填充与联动的优先级引擎（若以后同时存在，以「后触发的覆盖」为默认，不在本期做冲突配置）
- 文本类多条时取第一条，以及为此做的排序配置（多条一律不填并提示）
- 子表单整表多行填充
- 为数据联动单独做权限开关

## 8. 实现时建议拆分

实现建议按这个顺序：

1. 来源 UI：文本 / 数字 / 时间类用「取值来源」，下拉用「选项来源」，都加上 `linkage` 选项、设置 / 清除按钮、弹框（选表 + 至少一条条件 + 触发字段）。选择数据仍叫「数据源」。
2. 填报：文本 / 数字 / 时间类按条件查询并写入；多条则清空并 `el-message`。
3. 填报：下拉按查询结果生成选项，并处理 0/1/多条。
