# 表单与数据权限（第 3 期）

日期：2026-09-11  
状态：已拍板，按本文实现  
来源：已有应用级权限（所有者 / 配置名单 / 使用范围）落地后，使用范围页仍提示「能进应用 = 所有表、全部行」；2026-09-11 会话补定默认和破例。  
总规格：`docs/superpowers/specs/2026-09-05-permission-design.md` §10、§13 第 3 期以本文为准。

范围：进了某个应用之后，**哪张表能看见、数据管理里能看见哪些行**。不改组织后台角色、不改应用所有者/配置/使用范围、不改流程待办「只看这一条」、不改流程节点字段权限。

用词和总规格同一套：应用【人事】，表【请假单】【加班单】【薪资档案】；工作台【添加数据】【数据管理】；表单设计顶栏【表单发布】。

---

## 1. 一句话说清

能进【人事】的人，默认左侧树里**每张表都看得见**，但【数据管理】默认只看见**和自己有关的行**。

所有者和配置名单上的人始终能看见所有表、所有行，方便改表和排错。

没有应用使用权的审批人仍然只能从首页【我的待办】打开派给自己的那一条，不能因为「参与过」去翻【数据管理】。

---

## 2. 和现有几层怎么叠

| 层 | 管什么 | 还管不管第 3 期 |
|---|---|---|
| 组织后台角色 | 能不能进管理后台、改人改部门 | 不管应用里的表和行 |
| 应用所有者 / 配置名单 / 使用范围 | 首页有没有这个应用、能不能进设计/后台 | 第 3 期之前先过这一层 |
| **表谁能看见（本期）** | 进了应用后，树里有没有这张表 | 默认全看得见，可按表收紧 |
| **行谁能看见（本期）** | 【数据管理】、点开一行、选择数据、关联、联动带出能看到哪些行 | 默认与自己相关 |
| 表单发布「新增/编辑/删除」 | 这张表允不允许这种操作 | 继续有效；看见一行之后才能谈改 |
| 流程节点字段权限 | 待办抽屉里字段可编辑 / 只读 / 隐藏 | 只管抽屉，不管数据管理列表 |
| 待办按这一条放行 | 没使用权也能批那一条 | 不走应用的表/行权限 |

设计表单、流程、应用后台**只看配置权**，不按表再授权。

---

## 3. 表：谁能看见

### 3.1 默认

能进这个应用的人，左侧表单树里每张表都在，能打开【添加数据】【数据管理】（再叠发布页按钮开关和流程是否已启用）。

### 3.2 收紧

【表单发布】→【谁可以看】可以按**部门 / 角色 / 人员**限制「谁能看见这张表」，配法和应用后台【使用范围】一样：

- 选部门：不含下级部门；部门停用或删除后这条保留但不命中。
- 选角色：该启用角色下的人能看见；角色停用后不命中。
- 选人员：就是这个人。不能新加停用账号。
- 没分配部门的人：部门条盖不住，要靠角色或点名。

**空名单 = 不限制**（默认）。只要加了任意一条，普通使用人必须命中才看见表。

### 3.3 破例

所有者和配置名单上的人**始终能看见所有表**，不用写进这张表的名单。

### 3.4 看不见时

- 左侧树里没有这张表。
- 改网址打开这张表的工作台、或直接调这张表的接口，提示「表单不存在」（和现在对错应用一样，不要提示「没权限」）。

【添加数据】：能看见这张表，并且发布页「新增」开着，就可以填。

---

## 4. 行：谁能看见

只约束**普通使用人**（能进应用，但不是所有者、也不在配置名单）。

看【数据管理】列表、点开一行、导出、选择数据 `data`、关联数据 `relate`、数据联动带出，都走同一套范围。列表不能只在前端藏行，接口也要拦。

### 4.1 四档

在【表单发布】→【谁可以看】里选「数据范围」：

1. **与自己相关（默认）**
   - 普通表：创建人是我。
   - 流程表：创建人 / 发起人是我，**或** 这张单的流程任务曾经派给我（待处理、已处理、已取消、抄送都算「派过」）。
2. **仅本人创建**：只看创建人是我。流程里批过、被抄送的人，数据管理里看不到这行，继续走【我的待办】/【抄送我的】看那一条。
3. **本部门**：创建人**当前**所属部门是我的部门（人调部门后跟现在的部门走，和应用使用范围一致）。
   - 我没部门：退化为「与自己相关」。
   - 创建人没部门的单：本部门同事看不见；他自己（以及所有者/配置者）能看见。
4. **全部**：这张表对使用人不再按行收。

没写过这项的旧表，按「与自己相关」。这是对现在「能进就能看全部行」的收紧，测的时候要心里有数。

### 4.2 破例

所有者和配置名单：**这张表全部行**，不受上面四档限制。不想让某人当「超级看数」，把他移出配置名单。

没有应用使用权的审批人：**不能**进【数据管理】，也不能靠「参与过」调 `records/query`。首页待办抽屉仍走 `/api/workflow/...`，按这一条实例授权（总规格 §8.2）。流程抽屉里的选择数据 / 联动**不要**改成应用行权限。

### 4.3 看见之后能不能改

行范围只过滤「看见哪些」，不再拆一套「能看不能改」：

- 普通表：能看见这一行 + 发布页编辑/删除开着 → 能改/能删。默认「与自己相关」时，普通人自然只能动自己的。改成「全部」后，使用人也能改别人的行（和现在能进就能改一样）。
- 流程表：继续走已有规则（审批中不能在数据管理改；草稿/驳回/异常只有发起人能删；已通过只有原发起人能改且要重新审批）。

创建人、更新人必须是**当时操作的登录用户**。导入 Excel 也写成当前登录人，不要写成应用所有者。

## 5. 人在哪配

表单设计顶栏【表单发布】，在「工作区设置」「数据管理」旁边加一页 **【谁可以看】**（只有能进表单设计的人进得来，也就是所有者和配置名单）。

页面上两块：

1. **这张表谁能看见**  
   默认一句：「能进本应用的人都能看见这张表。」  
   下面是已加的部门 / 角色 / 人员列表，可移除。  
   【添加部门】【添加角色】【添加人员】，交互对齐应用后台【使用范围】（选部门时写明不含下级）。
2. **数据范围**  
   四个选项：与自己相关 / 仅本人创建 / 本部门 / 全部。默认「与自己相关」。

说明文案（必须有）：

- 所有者和配置名单始终能看全部表、全部行。
- 没有应用使用权的审批人不能靠「参与过」来翻表，只能走待办看那一条。

点【保存设置】才写入。应用后台【使用范围】顶部原来那句「等于开放全部表全部行」改成：每张表还可以在【表单发布】→【谁可以看】里再收；默认表都看得见，行只看与自己相关。

## 6. 怎么存

不新建权限表。写进现有表单配置 `app_form_config.config`（和「数据管理按钮」同一份 JSON）：

- `formViewers`：数组。每项 `{ type, targetId }`，`type` 是 `user` / `department` / `role`。空数组 = 不限制。同一 `type + targetId` 不要重复。
- `rowScope`：`related` | `created` | `dept` | `all`。缺省或无法识别时按 `related`。

读取配置给发布页时，把部门名 / 角色名 / 人名带上；停用或已删除的条目标成不生效（文案对齐使用范围页）。

---

## 7. 接口怎么拦

判定要集中，避免列表过了、详情或选择数据没过。

1. 先确认能使用这个应用（已有）。
2. 再确认能看见这张表：所有者/配置名单直接过；否则 `formViewers` 为空则过，否则按使用范围同一套规则命中部门/角色/人员。
3. 再按行范围过滤或校验这一条。

要拦的入口：

- 应用表单树（进应用左侧）
- 打开某张表、读表单结构
- 记录的查询、点开、改、删、导入、下载导入模版
- 选择数据、关联、联动用到的源表查询（走 `/apps/.../records/query` 的）

不要拦：

- `GET /api/workflow/inbox/...` 以及 `render/:instanceId/...`（按这一条实例）
- 表单设计、流程设计、保存字段、改发布配置（这些只看配置权；配置者始终能看见所有表）

「与自己相关」查流程参与：任务表里 `assigneeId` 是我，对应实例的 `formId` / `recordId` 落在这张表，和「创建人是我」做并集。

## 8. 验收（对照界面）

预备：【人事】所有者 A，配置名单有 B，使用范围有「部门 = 研发部」。研发部员工 H、同事 I（同一部门）、其他部门的 J（靠角色也能进【人事】）。请假单是流程表，加班单是普通表。另建一张【薪资档案】普通表。

1. **默认**  
   H 进【人事】：树里有请假单、加班单、薪资档案。加班单【数据管理】只有 H 自己填的行，看不到 I 的。A、B 打开加班单能看到 H 和 I 的。
2. **收表**  
   A 打开【薪资档案】【表单发布】→【谁可以看】，添加「角色 = 人事专员」，保存。H 不是人事专员：刷新后树里没有【薪资档案】，硬开网址提示表单不存在。B 树里还有【薪资档案】，数据全能看。
3. **流程参与**  
   H 交一张请假单，派给不在使用范围的审批人 F。F 首页没有【人事】，【我的待办】能打开这一条。H 的【数据管理】看得到这张（自己发起的）。I 默认看不到。F 批完后，若后来把 F 加进使用范围、数据范围仍是「与自己相关」：F 在【数据管理】能看到自己批过的这张；改成「仅本人创建」后看不到。
4. **本部门**  
   加班单改成「本部门」。H 能看到 I 填的加班，看不到 J 填的。H 被调出研发部后，只能再看到与自己相关的。
5. **全部**  
   加班单改成「全部」。H 能看到 I、J 的行；发布页编辑开着时也能改别人的加班（普通表）。
6. **导入创建人**  
   H 在加班单导入两行。这两行创建人是 H，不是 A。A 用「与自己相关」以外的身份看得到；H 自己也看得到。
7. **待办不走应用行权限**  
   F 没有使用权，待办里节点允许选「设备台账」时，弹窗仍按流程窄接口出源表已通过记录，不要先查他能不能看见设备台账这张表。
8. **发布页说明**  
   A 打开任意表【谁可以看】，能看到所有者和配置名单始终能看全部表、全部行的说明。【使用范围】页不再写「等于开放全部表全部行」。

---

## 9. 明确不做

- 自定义行条件、成员字段选中也算参与
- 字段级「对某些人隐藏」（流程节点字段权限继续只管审批抽屉）
- 子表权限组
- 使用范围含子部门
- 多权限组、按人拆不同的增删改
- 所有者和配置名单也受行范围限制
